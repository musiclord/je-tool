# JET 收斂與專案記憶

本檔定義跨工具共用的專案記憶與收斂邊界。`jet-converge` 負責互動方法；本檔負責資料從哪裡來、哪些能當
權威，以及裁決後寫回哪裡。

## 要解決的問題

長期專案會在多個 session 累積觀點、需求、功能提案與待完成事項。若每一段對話都直接變成 backlog，JET
會逐漸失去 CaseWare IDEA 替代、GA 本機工作與已確認 KCT 範圍的核心順序；若只靠某個 Agent 的記憶，換機、
換 host 或記憶整理後又無法可靠續接。

因此 JET 採「repository 是專案記憶，host memory 是查找線索」：先收斂，再把長期有效的結果寫回原本的
唯一權威，不建立新的平行知識庫。

## 四層資料

| 層級 | 內容 | 能證明什麼 |
|:---|:---|:---|
| 現行權威 | `src/`、測試、`docs/` 現行規格、使用者本輪明示裁定 | 現在應如何運作、目前有效的決定 |
| 執行狀態 | branch、HEAD、dirty tree、現行 `docs/specs/` 計畫、`development-status.md` | 現在做到哪裡、下一步與未完成邊界 |
| 歷史與來源 | `docs/history/`、`legacy/`、來源 commit／正式研究 | 為什麼形成目前決定；不能覆蓋現行權威 |
| 回想與證據 | task／thread、Codex 或 Claude memory、ignored receipt、聊天摘要 | 協助找回來源與當次結果；不能單獨建立規則 |

資料不可取得時寫「未能查核」。Compaction、task summary、memory 或成功 exit code 都不是完整證據。

## 收斂何時啟動

- 使用者明確呼叫 `$jet-converge`。
- 使用者要求整理多個 session 的觀點、尚未解決事項或彼此衝突的方向。
- 一項可能回頭開發的待完成事項缺少背景、邊界、重啟條件或完成標準。

一般狀態查詢、已有明確範圍的小修正，不自動展開完整訪談。Agent 可提醒存在衝突，但不能把普通工作偷偷
改成大型收斂程序。

## 開始前核對

1. 讀 `AGENTS.md`、`docs/project-context.md`、`docs/idea-replacement-scope.md` 與
   `docs/development-status.md`。
2. 查 branch、HEAD、dirty／staged／untracked 狀態；保留其他 session 的變更。
3. 若已有現行大型計畫，確認本輪是替它做收斂，還是另一個尚不能立案的主題。一次仍只能有一份現行計畫。
4. 列出本輪可讀來源、未能取得的 session，以及明確不會讀取的私人資料。
5. 在查核完成前，不把 thread 標題、記憶摘要或歷史提案當成目前需求。

## 分類而不是累積

每一項觀點只能落入一個目前狀態：

- **已確認**：有現行權威或使用者本輪裁定。
- **候選**：值得比較，但尚未獲准。
- **衝突**：兩個仍可能有效的說法互斥，需要裁定。
- **已知但延後的事項**：目前不做，且具有背景、目前邊界、重啟條件與第一個驗證動作。
- **已取代／否決**：不再指導現在；只在仍有解釋價值時保存歷史。
- **重複／無依據**：不進 backlog，不因多次被提起就提高權重。

`jet-converge` 必須同時檢查「和核心業務的關係」與「是否已具備重啟條件」。高興趣不等於高優先；久未處理
也不等於應立即開發。

## 裁決後如何保存

| 結果 | 回寫位置 |
|:---|:---|
| 專案目的、服務順序、正式環境限制 | `docs/project-context.md` |
| 領域、架構、資料流、action 或畫面行為 | 相應現行規格與測試 |
| 大型工作目標、核准範圍、階段、first-red、下一步 | 唯一現行 `docs/specs/` 計畫 |
| 延後事項與重啟條件 | `docs/development-status.md` |
| 已取代但仍需解釋的決策 | `docs/history/` |
| 一次性過程、完整 logs、逐輪問題 | 留在 session 或 ignored evidence，不搬進現行文件 |

寫回前先列出精確目標檔與要保存的事實。沒有文件修改授權時，只交付對話中的決策包。寫回後執行
`Documentation`，並把改動段落完整讀一次。

## Session 交接

跨 session 工作只需在現行計畫保留一份目前摘要：本輪成果與完成條件、已做與未做、重要裁定及否決理由、
驗證範圍與下一動作。工作樹和近期收據由 `Context` 現查；原話及第一次失敗以連結追溯，不另建交接文件。
「下一步」表示順序，本輪結束條件另依 [`development-workflow.md`](development-workflow.md) 判斷。

新 session 先讀 repository，再用 task history／memory 找補充來源。若兩者衝突，以實際 working tree 與現行
權威為起點，回報衝突，不自動覆寫。

## 停止條件

本節只適用於明確呼叫 `jet-converge` 的收斂訪談。使用者確認共同理解後，依原任務授權繼續；只授權整理時
不擅自實作，已授權開發時也不把訪談結束當成整個開發任務的停止點。Git 交付與私人資料仍依各自授權邊界。
