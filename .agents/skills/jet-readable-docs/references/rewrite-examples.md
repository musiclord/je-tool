# 改寫範例

每一筆記錄原文、改寫、原因與來源。原文只收本專案實際出現過的句子，包括 agent 在對話中寫出的收尾摘要；
不編造。事實不確定的例子不收。目前 9 筆；之後每次有代表性的人工改寫，就加一筆。

本檔故意保留不良句子當對照，所以不列入 `Documentation` 命令的樣式檢查，否則每次都會出現同一批
warning。它是否存在由 `SKILL.md` 的必要指向與 `docs/first-root-commit-candidate.txt` 保證。

## 來源說明

- 「Codex 對話」指使用者 2026-09-02 提供、標題為「如何避免 agent talk shit」的分享對話。
- 「2026-09-02 session」指 Claude Code 在該日修正 `dev.log.exportFile` 缺陷並提交時，寫進計畫檔、狀態文件
  或回覆的句子。

## 已列為 warning 的自創名詞

下列詞曾出現在本專案文件，現在由 `tools/harness/documentation-check.json` 的 `styleWarnings` 標為疑點。
它們的共同問題是把一個動作或一段流程壓成看似專業的四字詞，讀者無法還原。遇到時用普通中文說出實際
動作，不要再造同類的詞：

具名規範閉環、驗證證據回流、候選輸出執行、安全前置、目前停止點、公開守門、入口完成；正式驗證受阻、
測試文字證據、provider 一致性、架構守門、契約守衛、淘汰守衛、首紅、接線錯誤、公開邊界、能力群組、
公開基線、回歸守衛、加密交涉。
