# JET 前端設計

延續審計員已接受的設計，解決這次的畫面與操作問題。通用的 frontend-design skill 為網頁與行銷頁而寫，
JET 前端一律依本 skill，兩者衝突時以本 skill 為準。先讀本次相關的
[前端說明](../../../docs/jet-frontend-description.md) 與 `src/JET/JET/wwwroot/css/app.css` 的 `:root`；
操作流程見 [frontend-design-mode.md](../../harness/frontend-design-mode.md)。涉及資料或 action 時再讀契約與對應程式。
本技能提供方向，不要求每次重讀全部來源或重新選風格。

## 設計方向

JET 是離線的 Windows 審計工具。審計員長時間閱讀分錄、科目、日期與金額，畫面以內容清楚、操作一致與快速回應為優先。

- 暖紙畫布、近白工作面與石板藍重點色。淺色標題列橫跨視窗，使用 JE Tool 字標；使用者看過深色樣張後選了淺色，
  不改回深色標題列，也不恢復深藍漸層框帶。
- 用位置、間距、字重與表面明度分層。托盤收納操作，白紙承載內容，文件卡代表產出的檔案；報告不和測試程序排成同一層。
- 層級用實物的材質與擺放表達（使用者 2026-10-11 要求參考擬物化復興，2026-10-12 再加 1px 邊光）：按鈕是可按的實體按鍵，
  輸入框、條件組與托盤底槽往下凹，紙仍然是紙；不做亮面。
- Liquid Glass 用在浮於內容上的功能層：標題列、固定表頭、選單、對話框和滑動中的選取。內容層維持不透明，不在玻璃上再疊玻璃。
  玻璃須有實際背景、可讀的文字和不透明退路。光澤沿細邊呈現，不用漸層填色、裝飾光暈或跟隨指標的高光。
- 一個工作面只有一個主要動作，用石板藍實心按鈕。其他按鈕都是白底深字加細框的按鍵，停用時灰底灰字；新增動作在名稱前加灰色加號，
  列內的「移除」「檢視」「操作」也是同一種按鍵，展開中的按鈕往下凹。白底細框本身看得出可以按，不必再用藍字或灰字
  （使用者 2026-10-11 指出灰字的「加入」像一般文字；2026-10-29 指出中間操作區不需要到處用強調色，並選擇主要按鈕保留藍色）。
- 中文用打包的 Noto Sans TC，英數用 Instrument Sans，圖示沿用本機 Fluent SVG。新資源附授權，不載入網路字型或 CDN。

顏色、字級、間距、圓角與動態參數以現行程式變數為準，不在這份文件維護第二套數值表。
一般文字至少 12px；金額與筆數使用等寬數字，金額格式沿用 `Ui.money`。中文不用字距、全大寫或斜體。

## 元件與資料表

- 沿用同功能的共用元件。分段切換使用凹槽與滑動選取；頁籤使用底線；展開、抽屜與下拉箭頭沿用現有圖形。
  同功能只留一套（使用者 2026-10-19 要求）：切換畫面的頁籤與分段切換用 `Ui.tabAttributes` 與 `Ui.bindTabs`；
  按鈕打開的選單用 `.jet-menu` 與 `Ui.bindMenus`；按鈕形式的展開用 `Ui.disclosureAttributes` 與 `.jet-disclosure`，字固定不換；
  「尚未儲存」對話框用 `Ui.confirmUnsaved`。行為與用字見 `docs/jet-frontend-description.md` 的「畫面結構」。
- 並排的區塊靠上對齊，不用垂直置中，也不把內容推到底部；一側展開明細時，明細接在並排區塊下方並佔滿整寬，不撐高另一側。
  展開與收合由標題控制：整列標題再點一次就收起，按鈕式的展開由按鈕本身開關，不在內容底部另放「收合」。
  清單列展開的內容，例如已儲存情境與第四步的明細，放在下凹的淺灰底槽裡，標題留在槽外；表格下方展開的傳票分錄用細線分開，不再包一層。
  這幾條是 Claude 從使用者 2026-10-29 指出的三個問題歸納的做法，使用者同日確認做法照舊、寫明來源。三個問題是：置中造成並排區塊對不齊、收合按鈕和展開位置割裂、情境之間分不清。
- 表頭標題固定靠左，維持單行與穩定高度。長名稱用有界寬度和刪節呈現，保留查看完整名稱的方式；不能把表頭撐高或撐破外層。
  金額與筆數的資料格仍靠右；數字欄只取內容需要的寬度，讓靠左的標題和靠右的數字留在同一個窄欄裡，多出的寬度給文字欄。
  這取代原本「數字欄連同表頭靠右」的做法（使用者 2026-10-16 要求標題固定置左）。
- 傳票交叉表的條件欄表頭只寫 C1、C2 等代號，停留可看完整情境名稱，名稱對照放在「符合條件摘要」；勾選對齊代號。
  這讓十個條件的交叉表不必橫向捲動（使用者 2026-10-16 選定）。
- 明細表每頁最多 200 筆，包含欄位配對的來源資料。超過一頁時左下角只放左箭頭、`目前頁數/總共頁數` 和右箭頭；
  只有一頁時不顯示分頁列。使用共用分頁外觀，端點停用相應箭頭並提供無障礙名稱；不再以「載入更多」累加明細。
  其他清單的換頁（例如工作底稿版本紀錄）也用同一個分頁外觀。
- 排序必須針對目前查詢範圍的完整資料，由資料庫先排序再分頁。不能只排序已載入的頁面；沒有完整排序能力就不顯示排序操作。
- 寬表在自己的容器內水平捲動；固定表頭不遮住焦點。資料載入、失敗、空結果與換頁後的狀態都要正確呈現。
- 表格滾動與儲存格選取不加裝飾動畫。選取、焦點和狀態不能只靠顏色傳達。

上面的表頭、交叉表與 200 筆分頁是使用者 2026-10-16 的要求與選擇；實作與驗證進度查現行計畫，不以技能文字當成已完成證據。
更多檢查點見 [data-and-cjk-rules.md](references/data-and-cjk-rules.md)。

## 動態與焦點

沿用 `app.js` 的 `JetMotion`、選取滑動與焦點還原，不為單一畫面另造一套動態。

- 玻璃操作保留輕微彈性，內容版面變化收斂、不回彈。流程欄的選取維持原尺寸平移。
- 加入條件的標籤沿直線到目標，不走拋物線；加入、移除、清除與切換都保持空間連續性。
- 使用者自己按下移除、清除或刪除時，要拿掉的東西先在原位輕微快速地左右晃一下（最多 4px、約 0.2 秒）再收起；
  只清空、不會拿掉的東西直接晃一下。這是使用者 2026-10-13 要求的例外，不算誇張彈跳；切換或篩選造成的消失不晃。
- 動作立刻開始，不等動畫完成才操作；連續輸入和重繪保留目前位置、速度與焦點。
- 需要跨重繪辨識的元件使用穩定身分，不能用會變的索引。退場複本不再接收操作；視覺樣式掛 class，避免依賴會被複本移除的 action 屬性。
- 尊重減少動態與高對比設定；視窗不在前景時玻璃改為不透明。新增或調整元件時一併檢查這些狀態。

實作細節讀 `app.js` 的 `JetMotion`、`SPRINGS`、`bindGlide`、`bindArrival` 與 `bindWindowFocus`，以及 `app.css` 的對應規則。
參數與曲線要同步，不把歷史測量或舊參數當成現行規格。

## 避免偏離方向

不要把畫面改成行銷網站、全頁同款卡片、深色螢光介面或報紙風。避免裝飾性大標、假統計、襯線斜體、彩色粗邊、
漸層填色和無操作原因的進場動畫。暖紙、狀態膠囊與 Liquid Glass 是使用者已選定的方向，不因通用禁止清單而移除。
[ai-default-patterns.md](references/ai-default-patterns.md) 保留來源與容易混淆的例外；清單協助判斷，不要求每輪累加新規則。

常駐的文字只寫狀態與下一步。規則或條件的定義放在用到的地方，例如條件列、展開的明細或標題的提示；同一句話在同一個畫面只出現一次，
也不寫「不會改寫」「不受影響」這類保證句（這條是 Claude 從使用者 2026-10-29 指出常駐說明太多、對操作者沒有實質幫助歸納的做法，使用者同日確認照舊；保證句在 2026-10-14 縮短黃色提示時已拿掉一批）。提示不夾帶程式沿革、內部代號，也不要求審計員回報開發人員；
用詞與提示分級依前端說明。

## 完成方式

依任務大小決定實作方法，必要的 HTML、CSS、JS、class 與資料屬性都可調整，同步核對受影響的契約與測試。
用合成資料查看實際畫面，挑與本次修改有關的長文字、空結果、窄版、焦點或連續操作情境；
截圖方法見 [screenshot-review.md](references/screenshot-review.md)。驗證與獨立檢查時機依前端設計模式，不在這裡重複規定。

使用者要求大幅改版或重新選方向時，才用同一個真實畫面製作少量差異明確的樣張。一般修正直接延續現行方向。
新的長期設計決定更新前端說明；需求原話留在現行計畫，技能只更新有效指示，不追加逐輪故事。
