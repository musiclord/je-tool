# JET 前端設計

模型沒有設計方向時，會退回幾種固定的預設樣式；只說「不要有 AI 感」，通常只會換成另一種預設。
JET 用三件事避免這個問題：寫死的設計簡報與已裁定的方向、具體點名的禁止清單、做完後用截圖逐項檢查。

通用的 frontend-design skill 是為網頁與行銷頁寫的，這台電腦的 Claude 載入的還是要求「大膽極端美學」的舊版。
JET 的前端設計一律依本 skill；通用 skill 的建議和本 skill 衝突時，以本 skill 為準。

## 什麼時候用

- 修改 `src/JET/JET/wwwroot/` 的 CSS、呈現用 JS 或 HTML 結構的外觀。
- 新增畫面、元件、空狀態或錯誤提示的樣子。
- 使用者說畫面難看、不一致、太擠、像 AI 做的，或要重新選設計方向。
- 檢查別人做好的畫面。

不用在審計規則、action 與 payload、後端程式。畫面上的用語依 `docs/jet-frontend-description.md`，
文件與回覆的寫法依 `.agents/skills/jet-readable-docs/SKILL.md`。

## 先讀

1. `.agents/harness/frontend-design-mode.md`：預覽工具、每輪檢查與正式整合的順序。
2. `docs/jet-frontend-description.md`：已接受的畫面設計、互動與用語。本 skill 不覆蓋它；兩者衝突時以前端說明為準，並回報衝突。
3. `src/JET/JET/wwwroot/css/app.css` 開頭的 `:root`：顏色、字級、間距與圓角的唯一來源。
4. 改到 JS 或送出的資料時，再讀 `docs/action-contract-manifest.md`。

## 設計簡報

這份簡報已經定案，不必每次重新推想。

- 產品：JET 是審計員做分錄測試的 Windows 桌面程式。WinForms 視窗裡的 WebView2 顯示網頁畫面，完全離線執行。
- 使用者：會計師事務所的審計員。長時間看分錄、科目、日期與金額；熟悉 Excel 與 IDEA。
  常見螢幕是 1920×1080、縮放 125%，也就是約 1536×864 的畫面寬高。
- 工作：六個步驟完成同一案件的分錄測試。依序是設定查核範圍、匯入來源、確認欄位、檢查 GL 及分類、
  選取待查核分錄，最後產生底稿。右側資料預覽隨時可以查明細。
- 感覺：可靠、精確、有個性。畫面像整理好的一桌紙，工作內容最亮、安靜、數字容易對齊；托盤放東西、白紙寫內容，按鈕是摸得到的按鍵；
  標題列、表頭、選單與對話框是浮在上面的一層玻璃，底下的內容透得過來；分段切換的選取會浮起來變成玻璃滑過去，流程欄的選取照原樣平移；加入的東西長出來、拿掉的收起來，按下主要按鈕時會亮；畫面上只有一種重點色。
- 一個畫面只有一個焦點。審計員要能在兩秒內說出這個區塊是做什麼的。

## 已裁定的設計方向

使用者 2026-10-10 認為介面「過於無聊，使用的形狀和元素都大同小異」，又有排版沒對齊的問題，要求以大版本研究整體設計，
並指定 MindBridge 的 KPMG 合作頁為參考之一。2026-10-11 看過四個方向的樣張後，選了「方向一 深藍框架」，
也採用四個方向共用的全部結構改變。這取代 2026-10-08 的「混合二」（暖紙底、單一藍色、4px 控制項），研究與選擇經過記在 KCT 需求計畫（`docs/history/specs/2026-10-06-kct-gl-requirements-plan.md`）。

選項說明的原文是：

```text
參考 MindBridge：頂部深藍漸層色帶框住案件資訊，冷白底上放白色工作面，藍色 #1A73E8，英數用 Instrument Sans，狀態標籤膠囊、節點圓形，搭 Fluent 圖示。辨識度最高，也最接近你給的參考。
```

同一天使用者看過實作後再調整外觀。原話節錄：「對於整體 `je-tool` 的色調與樣式，我認為可以回到先前的色系，因為飽和過高的藍色我認為過於突兀」、
「但我希望可以保留現在新的樣式中，有些強調色、高亮對比等等元素」，並希望「參考蘋果的 liquid glass 要素和對應相關的設計理念，
讓整體介面的元素可以呈現自然、光影和使用者交互的感覺」。完整原話與評估在 KCT 需求計畫的「介面色系、材質與標誌調整」。

第一版做成石板墨色的漸層框帶，加上玻璃高光、跟著指標的光與按下下沉。使用者同日否定這個版本，原話節錄：
「我覺得這次的調整甚至比前次的改動還差，尤其是上方的漸變顏色非常的難看，而且這也不符合 liquid glass 的樣式，
並不是單純地給介面增加立體感就是 liquid glass，他更多的是應該是設計理念和自然的表達，而不是單純的套版」，
並要求「借用蘋果在設計的思路，長年下來到現在最新的改動之後的理念和表達」。完整原話、研究與評估在 KCT 需求計畫的「依 Apple 設計理念重新調整外觀」。
所以那一版的方向是：顏色維持混合二的暖紙色系與石板藍；不再有色帶、漸層、內高光與靠陰影做出的立體感；
依 Apple 從早年到 2026 年 Mac 介面一貫的理念，內容在前、層級靠版面與分組，材質要誠實，光與動態只用來回應操作或說明狀態改變。
判斷任何一個光影、材質或動態要不要加，先問它是否回答「這是哪一層、能不能按、目前選中什麼、剛才的動作有沒有生效」其中一個問題；
答不出來就是裝飾，不加。交付前的獨立檢查發現第一個版本把底下沒有內容經過的流程欄與頂部操作組也叫玻璃，
看起來和紙一樣，只剩名稱；所以玻璃只留給真的浮在內容上的選單與對話框，其餘都是不透明的紙。

同日第三次調整，使用者看過上面的版本後提出九項意見，原話節錄：「左上角的 JE Tool 旁的 logo 看起來不明所以」、
「右上角的菜單獨立出來很好，但是放在右上角不知道為什麼感覺很孤立」、「我感覺介面區塊相互之間有種割裂感，沒有之前那樣整體一致性」、
「我特別喜歡你設計選單切換的介面元素會有滑動的動態效果」，並要求驗證報告這類產出不要和測試程序看起來同一層、
「加入」要看得出是按鈕，第五步多參考「liquid glass 和擬物化復興的風格」。完整原話在 KCT 需求計畫的「標題列、層級與條件篩選的材質」。
使用者在淺色與深色兩種整條標題列的樣張中選了淺色。所以標題列回到橫跨整個視窗的一條，標誌改成字標；
層級改用實物之間的關係表達：低一階的托盤放東西，白紙寫內容，文件卡代表檔案；加入的東西看得到從哪裡來、到了哪裡。

使用者 2026-10-12 操作過上面的版本後，認為動態感有增加，但只調整了第五步，整個 JE Tool 應該一起維持一致，並指出「我並未看到任何玻璃效果」。
原話節錄：「我希望可以帶有蘋果 liquid glass 的質感，而且不是用無意義的漸變色來填充，應該帶有通透且自然的光澤感，甚至可以說是帶有擬真復興的感覺」。
完整原話在 KCT 需求計畫的「整體的 Liquid Glass 質感」。Claude 在 4246 做樣張，使用者在三種透明度中選了「照樣張套用 (Recommended)」。
所以玻璃不再只留給選單與對話框，而是照 Apple 的分層：功能層是玻璃，浮在內容上方，底下真的有內容經過；
內容層是不透明的實物，按鈕是按鍵，輸入框與底槽往下凹，紙仍然是紙。光澤只在 1px 的邊上，從左上方來，不用漸層填色，也不跟著指標。
這取代上面「不再有內高光與靠陰影做出的立體感」與「玻璃只留給選單與對話框」兩句。

同一天使用者把沒重新整理的舊頁面和新版並排比對，提出五點要接續修改。原話節錄：流程欄的選取「希望它可以維持原本的樣子不會放大縮小，
因為這顯得過於醒目」；加入條件的飛行「看起來像是廉價的套版」「整個過程非常突兀」；「只有新增條件會有動態效果，但當我移除、清除條件時
卻沒有任何動效」「這個問題在其他流程也有」；切換常用查核條件時「應該是流暢的切換，而不是一閃而過」；左下角的訊息區
「展開之後要再收合時，發現那裏整個是錯位的」。完整原話在 KCT 需求計畫的「動態的完整度、流程欄與訊息區」。所以：
流程欄的選取同樣大小平移，不浮起成玻璃；加入條件改成帶過去的玻璃標籤；加入、移除、清除與換掉的東西在整個 JE Tool 用同一套動態（`JetMotion`）；
原地展開的區塊兩個方向都轉場；訊息區改成開關固定在欄底的抽屜。做法見下面的「動態」與「加入與移除」。

同一天使用者在內建瀏覽器操作後又提出兩點。原話節錄：第三步按「重新配對」後「我切換 `借方欄+貸方欄` 到其他選項時他並不會以我預期的移動，
而是單純閃過切換到我選的項目，並且上方直接提示 "配對已修改，請按..."」；「調整後的動態效果還是覺得很突兀，他應該有更加質感且自然的滑動效果」，
並要求先研究 Apple 近年的設計理念、人機介面指引與開發者文件，再套用到所有流程畫面，必要時可以重新設計整個前端樣式。
完整原話在 KCT 需求計畫的「第三步切換閃動與整體動態重新設計」。研究後的判斷是：已裁定的分層、材質與色系和 Apple 的做法沒有衝突，
突兀來自動態本身。原本的曲線比 Apple 的彈簧快，被打斷時從零速重新起跑；重繪時只比對標了識別的東西，所以沒標識別的區塊一下變高變矮、換字一閃而過。
所以這次不重做外觀，整個 JE Tool 的動態改用 Apple 的彈簧，並補上原地改變。做法見下面的「動態」與「加入與移除」。

2026-10-13 使用者在內建瀏覽器操作後提出三點。原話節錄：「fade-in 和 fade-out 的效果，我認為那些太緩慢了，請加快相關的動畫速度」；
「有一些摺疊菜單或展開的元素，並沒有一致的套用動態效果」「請你自行找出問題點並修復」；進階條件篩選選擇條件時元素
「以跳躍的形式」移至右側「看起來有點 goofy」，而清除條件時那一下「類似蘋果那樣輕微快速地晃動來作為移除元素的設計」不錯，
要讓右側條件組合、刪除案件（原話是「移除專案」，畫面上一輪已改稱案件），以及「其他流程中要移除或清除什麼東西時」都這樣晃一下。完整原話在 KCT 需求計畫的「加快淡入淡出、補齊展開收合與移除前的晃動」。
所以：彈簧與淡入淡出整體加快；全部步驟逐一找出沒有動態的展開區、錯誤與提醒訊息、選單與小按鈕並補上；
帶過去的標籤改走直線；使用者自己按下移除、清除或刪除時，要拿掉的東西先晃一下再收起。做法見下面的「時間與曲線」「加入與移除」與「移除前的晃動」。
使用者同日在 4245 看過後確認，接著表示「目前關於前端相關的部份我認為都處理得很好」，
2026-10-09 接手以來的方向都已經過使用者確認；之後的調整照本節已裁定的方向延續。

套用時依下列角色分工。實際數值以 `app.css` 的 `:root` 為準：

- 頂部是一條橫跨整個視窗的標題列，一整片淺色玻璃 `--toolbar-bg`，也就是 `--glass-bar`，不是色帶也沒有漸層。
  玻璃畫在 `.app-shell::before`，兩列時也不會在案件摘要那裡斷開，下緣是玻璃的邊 `--glass-edge`。
  流程目錄、中欄、資料預覽與案件清單都從視窗頂端開始，上緣藏在它下面；標題列的高度由 `app.js` 的 `bindChromeHeight` 量好寫在 `--chrome-h`，
  各欄用它讓出上內距與 `scroll-padding-top`，鍵盤移動焦點時不會停在玻璃後面。內容捲到它下面時 `.app-shell` 加 `data-under-chrome`，
  玻璃改用 `--glass-bar-under` 霧一點、影子加深，藍色按鈕剛好經過時 12px 的小字仍有 5.2:1；玻璃上的小字用比一般灰字深的 `--toolbar-muted`。
  玻璃的層級 30、上面的字 31，在中欄的選單之上、對話框之下，捲上來的選單不會畫到標題列上面。
  不再把標誌疊進流程目錄頂端（使用者 2026-10-11 第三次調整認為那樣各區塊割裂）。
  開啟案件且視窗寬度至少 1536px 時只有一列：左邊是字標與「目前帳號」，案件摘要是這一頁的標題，從中欄的左緣排到操作組前面，
  案件名稱用深墨色當錨點；右邊的「總覽」「開啟案件資料夾」「回首頁」「退出」收在同一個淡框裡，這個框是貼在玻璃上的一層淡白，不是第二片玻璃。
  案件清單畫面或比較窄的視窗是兩列：第一列是字標、帳號與操作組，案件摘要在第二列，和字標同一條左緣。
  標題列的顏色都是 `:root` 的 `--toolbar-*`；使用者看過深色版樣張後選了淺色，不要改回深色。
- 字標：名稱裡的 JE 放進石板藍的 6px 圓角方形，Tool 接在後面，JE 就是 Journal Entry；「目前帳號」在下一行，兩行對齊同一條左緣，
  也和流程目錄的步驟圖示同一條左緣，帳號前不加色點。使用者兩次認為圖形標誌看不出意思，試過的 T 字帳戶在實際大小下又像中文字「示」，
  所以不再用圖形標誌。字標只出現在頂部一次。
- 明暗照「內容在前」排：左側流程目錄是比畫布低一階的紙 `--color-surface-sunken`，貼齊視窗左緣，右緣一條細線；
  中欄是暖紙畫布；工作面是最亮的近白紙面 #FFFEFB，1px 淡框、12px 圓角，只有貼著的接觸影 `--shadow-surface`；
  右側資料預覽的表格底色 `--color-surface-lit` 比工作面低一階，讓目前步驟的工作面最醒目。
- 玻璃是浮在內容上的功能層，底下真的有內容經過：標題列、表格固定的表頭（明細表 `.preview-table`，科目分類表也是這一種，以及資料預覽）、
  選單、對話框、忙碌提示、總覽圖表的提示框、加入條件時帶過去的標籤，以及分段切換滑動中的選取。
  數值都在 `:root` 的 `--glass-*`：標題列 `--glass-bar` 五成、表頭 `--glass-head`、選單與對話框 `--glass-fill` 八成，模糊背後的內容並提高一點飽和度；
  邊光 `--glass-rim` 左上最亮、右下淡一點，外面一圈 `--glass-line` 細暗邊，浮起來的再加 `--shadow-overlay`。
  表頭是整列 `thead` 一起固定的一片玻璃，帶一點托盤的灰，和表格列分得出來；最後一欄固定在右邊的表頭那一格維持不透明。
  第三步對應表的框不會上下捲動，表頭不會固定，所以不是玻璃。
  玻璃上不疊玻璃，內容層不用玻璃，不用漸層填色或上半部亮面。對話框打斷目前的工作，背後的畫面變暗但仍看得到。
  流程總覽是圖表與數字，屬於內容，維持不透明的紙面；它的圖表提示框浮在圖表上，是玻璃，寫在 `overview-bi.js` 的 `TOOLTIP_GLASS`。
  使用者切到 Excel 等其他程式時，`app.js` 的 `bindWindowFocus` 在 `<html>` 加上 `window-inactive`，標題列、表頭、選單與對話框的玻璃
  改成不透明、不模糊背景，回到 JE Tool 時恢復。人機介面指引 Windows 說不在作用中的視窗不使用 vibrancy，看起來比較收斂、離得比較遠。
  變成不透明時背景色也直接換，不沿轉場，免得背景還半透明、模糊已經拿掉時露出一下清楚的內容。

  整段重繪時容器帶 `data-motion-rendering`，重建出來的區塊不重播；`swap` 用 `JetMotion.setShown` 顯示新的窗格，裡面原本打開的區塊不再長一次。
  原生 details 由 `::details-content` 處理。
  同一行裡出現或消失的小東西（例如「已選取」、訊息數量）標 `data-collapsible-inline`，寬度與左右內外距跟著收放。
  收起的訊息要留著字，等收完才清掉，否則一按就先變成空的一條；畫面程式切換 `hidden` 時不要同時把字清空。
  右側資料預覽是靠右的抽屜：收合與展開時寬度沿彈簧改變，裡面的內容先淡掉再收起，展開時等寬度快到才淡入；拖曳調整寬度時不轉場。
  可以拿去用的 KCT 卡片滑鼠移上去時影子變長（iPadOS 的 lift），不移動位置。這些都不改 state、不送 action，標籤不接收滑鼠。
  不做固定在畫面底部的玻璃操作列：它會蓋住條件列，Gui 測試用真實滑鼠點擊時會被擋住。
- 系統設定的退路：關閉透明效果與要求高對比時，所有玻璃改成不透明的紙面、不做模糊，滑動中的選取改成放在字下面的實心一片；
  要求高對比時邊線也加深，按下不亮。Windows 高對比佈景只換顏色、不會拿掉透明與模糊，所以玻璃一律改成不透明的系統底色；
  它也不畫按下的光，不加滑動的選取底，改用系統的反白色外框標出目前步驟、

結構規則（使用者 2026-10-11 一併採用）：

- 頁內表單的主要動作放在最右，取消或放棄緊鄰左邊，預覽、查看與重新讀取放在最左。純分頁操作維持靠左。
  `.panel__actions` 靠右，臨時操作用 `.panel__action--start` 留在左邊；純分頁列用 `.panel__actions--start`。
  條件組合編輯時依序放「另存為新情境」「取消編輯」「儲存變更」。對話框沿用靠右且主要按鈕在最後的排列。
- 第六步匯出後的「案件流程已完成」是淡綠底、不加框的一塊，勾號用和流程軸線完成節點相同的綠色實心圓，
  下面的檔名前各一個灰色文件圖示，不用綠框小標籤（使用者 2026-10-13 選擇改成和其他產出區一致）。
- 產出：工作面裡的報告區是工作面底部的 `.rule-card > .report-output:last-child`，獨立的報告區是 `.report-output` 托盤，用 `--color-tray`；
  標題前一個灰色文件圖示，每份檔案是 `.report-artifact` 白色文件卡，左邊灰色文件圖示（文件卡不能按，所以不用石板藍）。
  產生或重新產生報告的按鈕是白底細框的次要按鈕，放在報告區標題右邊；一個步驟的實心主要按鈕留給工作面的主要動作或「下一步」。

- 表格外框是直角，只有正在排序的欄顯示方向箭頭。金額與筆數欄連同表頭靠右，欄位加 `preview-table__amount`。

- 第三步的過帳狀態、人工/自動分錄代碼與攸關資料元素欄位用粗體小標與細線分隔，不包框；這是使用者 2026-10-09 的選擇。
  依使用者 2026-10-14 的回饋，拿掉「資料處理」總標題與外層上框線，第一個小區塊上方只留一條線。
- 步驟式的操作區，例如第四步「用 Excel 配對」，每個步驟一列，標題、說明、按鈕左右排開；說明只寫下一步和會覆蓋資料的提醒。

元件不寫裸色碼、裸字級或裸圓角，一律引用 `:root` 的變數。需要新的角色時，先在 `:root` 定義，再補進本節。

## 禁止清單

下列都是已被點名的 AI 預設樣式。使用者沒有明確指定時，就算看起來合理也不要用。
完整說明、出處與 JET 目前狀態在 `references/ai-default-patterns.md`；每輪看完截圖，把新發現的預設樣式加進那份清單。

1. 大面積奶油或米白底，接近 `#F4F1EA`，配襯線大標、斜體強調字，以及陶土、赤陶或琥珀色強調色。
   JET 的暖紙畫布 #F5F3ED 是使用者指定的例外：2026-10-08 選了混合二，2026-10-11 又要求回到這組色系。
   不得再加襯線字、斜體或陶土色。
2. 近黑底配單一螢光強調色、發光邊框；用 `#0B0B0B`、`#111` 這類近黑代替黑色。
3. 報紙風：處處細線、零圓角、密排欄位、斜體襯線，加上加寬字距的等寬小標。
4. SaaS 卡片組：一整排一模一樣的圓角卡片、所有東西同一種圓角、每張都有同一個灰陰影、漸層底；卡片裡再包卡片。
5. 樣板裝飾：每個標題上方都有全大寫加寬字距的小標；用 `A · B · C` 中間點串資訊；`WORD — fragment` 句型；
   按鈕或連結文字後面加 `→`；用等寬字當小標。
6. Anthropic 對 Opus 5.5 點名的五項：奶油或米白底、標題裡只強調一個字、內容不是真正順序卻用 01、02、03 編號、
   等寬小標、膠囊形按鈕。JET 的六個步驟是真正的順序，左側流程與案件摘要可以保留步驟數字。
7. 卡片或區塊單側 2px 以上的彩色粗邊。
8. 紫藍漸層、漸層文字、玻璃擬態、裝飾用光暈或光點、條紋或格線背景。
   使用者 2026-10-11 指定參考 Liquid Glass，2026-10-12 又要求整個 JE Tool 帶有它的質感，所以 JET 有玻璃，但照 Apple 的分層：
   只用在浮在內容上的功能層，底下真的有內容經過，而且有不透明的退路；不做彩色背景上疊毛玻璃卡片的玻璃擬態，內容層不用玻璃，玻璃上不疊玻璃。
   玻璃與按鍵的光只在 1px 的邊上，不用漸層填色、上半部亮面或跟著指標的高光；使用者 2026-10-11 看過漸層框帶與立體高光後否定了那種做法。
   按下時從按下位置亮起的光只在按下的瞬間出現，是回饋，不算裝飾。
9. 每個區塊進場都淡入上滑、每張卡片都有滑鼠移上去的陰影、彈跳緩動、數字跳動計數、裝飾用的脈動圓點。
   選取浮起來變成玻璃滑過去（流程欄只平移）、選單從按鈕長出來、對話框浮現與淡出、加入條件時標籤帶過去、加入與移除的東西長出來與收起來、
   展開的內容從標題長出來與收回、可拿起的卡片影子變長，以及按下時立刻變深並稍微鼓起，
   是使用者 2026-10-11 與 2026-10-12 要求互動回應、動態完整一致並多參考 Apple 設計思路後的做法：只用在回應操作或說明狀態改變，
   內容層用 Apple 不回彈的彈簧，玻璃層被操作的東西只帶一點點回彈（bounce 0.15，最多超過目標 0.6%，看不出在彈）。
   這裡禁止的彈跳緩動是看得出在彈的曲線，例如反覆彈跳的 easeOutBounce，不是 Apple 的 bounce 0.15；移除前的晃動是使用者 2026-10-13 要求的，
   刻意用 bounce 0.75 晃一下，但只晃約 0.2 秒、最多 4px，也只在使用者自己要拿掉東西時出現，
   不加在進場與捲動上，換步驟也不加整段淡入；KCT 卡片的影子只因為它可以拿去用，一般卡片與工作面滑鼠移上去仍不加影子。
10. 大數字配小標籤再加漸層的「數據卡」當版面主角。真實的統計摘要可以用大數字，但不加裝飾。
11. 第二層預設：禁掉上面幾項後，模型常改用冷灰藍霧面底（`#E9EDF0`、`#F6F8FB` 一帶）、鈷藍強調色、
    Grotesque 字體、3 到 6px 圓角加琥珀點綴。JET 的 6px 控制項沿用使用者依 MindBridge 參考選定的深藍框架；2026-10-11 起畫布改回暖紙，
    辨識度來自暖紙與石板藍、整條標題列與 JE 字標、托盤與白紙的擺放、流程軸線、圓形節點與膠囊狀態，以及選取會滑動、按下會亮、加入會飛的回應；
    不再往這組預設多加琥珀點綴或冷灰層次。
12. 依產品類型套色，例如金融就用海軍藍加金色；或直接套 Tailwind slate 整組（`#0F172A`、`#F8FAFC`、`#E2E8F0`）。
    2026-10-11 的墨色框帶已在同一天依使用者意見拿掉；之後使用者在淺色與深色兩種整條標題列中選了淺色，不要再加回深色框帶。
13. 行銷式文案與假資料：Elevate、無縫、賦能；Acme、John Doe；99.9%、10,000+ 這類整數假統計；成功訊息加驚嘆號。
14. 中文介面專屬的毛病：對中文加字距、對中文套全大寫、小於 12px 的字、斜體中文。

## 資料密集畫面的規則

下面是摘要，每條都可以直接檢查。完整條文與出處在 `references/data-and-cjk-rules.md`。

- 金額與筆數靠右對齊，加 `font-variant-numeric: tabular-nums`。畫面上的金額由 `ui-core.js` 的 `money` 格式化，兩位小數加千分位。
  第四步明細表的設定用 `numeric` 標出要靠右的欄，「載入更多」的欄位寫成 `{ cell, className: 'preview-table__amount' }`，表頭跟著靠右；
  這幾張表原本靠左，使用者 2026-10-13 選擇改成靠右。
- 表格列高預設約 32px；表頭固定在上方；寬表在自己的框內水平捲動；只有正在排序的欄顯示排序符號。
- 狀態至少用顏色、文字或符號其中兩種表達。一個畫面的狀態種類不超過六種。
- 空狀態分成「還沒開始」「條件下沒有結果」「出錯」三種，各自說明原因並給一個下一步。
- 錯誤訊息說出什麼失敗、知道原因時說原因、怎麼補救；不拿內部代碼當主要訊息，不清掉使用者已輸入的內容，不道歉也不開玩笑。
  要新增會擋住使用者的錯誤時，先寫出使用者接下來能做什麼。
- 所有可操作的元素都有 `:focus-visible` 的 2px 焦點框，對比至少 3:1；固定的表頭或工具列不能遮住焦點。
- 重繪不丟焦點。`app.js` 依 `data-focus-key` 或控制項的身分把焦點放回同一個控制項，身分是所在區塊的 `data-motion-key`、元素種類、
  名稱、無障礙標籤與不會變動的 data 屬性，重繪前後都只對到一個才還原；按下的控制項消失或停用時，畫面程式用 `JetFocus.deferFirst`
  交給接替它的控制項，執行中的作業結束後焦點回到按下的控制項。新的畫面不必再替每個控制項加 `data-focus-key`，
  但同一區塊裡長得一樣的控制項要有能區分的名稱或 data 屬性。這是使用者 2026-10-13 指示的修正。
- 動態只用來說明狀態改變或回應操作，用上面「時間與曲線」的彈簧，看起來完成約 0.22 到 0.3 秒，可以被下一個操作打斷並保留速度，
  並尊重 `prefers-reduced-motion`。主要動 `transform` 與 `opacity`；選取底是組裡的一個絕對定位圖層，寬高可以跟著選項變，滑動中的玻璃是組的 `::after`。
  加入條件時帶過去的標籤分三段：浮起 70ms、沿 `SPRINGS.carry` 移動、約 0.24 秒到標題上就放下，放下 110ms，前後重疊。
  長出來用 `SPRINGS.open`、收起來用 `SPRINGS.close`，字晚一點淡入、先一點淡出。
  按下時立刻變深，鼓起只用 90ms；表格捲動與儲存格點選這類每天上百次的操作不加動畫。
  按下之後畫面要盡快開始動，所以同一個操作只寫一次 state、只重繪一次。
- 層級靠位置、間距、字重與表面明度建立；同一組的東西靠近，不同組拉開。瞇眼看畫面仍分得出主要與次要。
- 文字對比至少 4.5:1；停用的文字至少 3:1。

## 繁體中文排版

- 中文不加字距。全大寫與加寬字距只對拉丁字母有作用，中文標籤一律不用。
- 最小字級 12px。字級只用 `:root` 定義的六階；字重只用 400、500、600。強調用字重，不用斜體。
- 行高：內文約 1.6，表格約 1.45，標題約 1.3。
- 中英文之間的間距與全形標點的寬度，目前沿用瀏覽器預設。要全面開啟 `text-autospace` 或調整 `text-spacing-trim`，
  先在 WebView2 實測，再請使用者決定。

## 工作流程

1. 確認範圍。使用者還在提出註解或討論時，先說明選項，不動手；明確要求實作後才改。需求原話寫進現行計畫。
2. 寫設計計畫，小改可以只寫三行：要改哪個畫面、審計員在那裡要完成什麼、用到哪些 `:root` 角色、要避開哪三種預設。
3. 對照禁止清單檢查計畫。如果同一份計畫放到任何一個後台都會得到一樣的結果，那就是預設，改掉並寫下改了什麼。
4. 實作。只改 CSS 與變數，必要時才改呈現用 JS。不改 class 名稱與 `data-` 屬性，因為 Gui 驅動程式與測試靠它們找元件。
   不改 action、payload、審計規則與後端。
5. 截圖檢查。用 `scripts/preview-shot.cjs` 在合成預覽無頭截圖，步驟見 `references/screenshot-review.md`。
   它不在使用者桌面開視窗，也不連使用者的瀏覽器主機。逐項對照禁止清單與規則，修正後再截一次。
6. 使用者確認設計方向並要求正式整合時，請一位沒參與開發的助手做一次獨立檢查。使用者還在比較或調整方向時不做，修完也不再複審。
   只給它設計方向、禁止清單與截圖，請它找預設樣式與違反規則的地方，只處理和需求有關的發現。這項檢查是對照清單看截圖，不需要用最高推理等級。
   使用者 2026-10-08 裁定這項檢查不每輪做，原話是「不需要到每一輪，這太浪費額度了」。之後每換一次方向仍各做一次，10-08 到 10-12 共八次，
   所以 2026-10-15 使用者選定把時機收斂到要求整合時。
7. 新的設計決定寫回 `docs/jet-frontend-description.md` 與本節的「已裁定的設計方向」。新發現的預設樣式寫進禁止清單的參考檔。
8. 測試、驗證與正式整合依 `.agents/harness/frontend-design-mode.md`。

## 重新選方向或大改版時

- 在同一個真實畫面上，例如第五步的篩選工作區，用合成資料做三到四個差異夠大的方向，其中一個是現況整理版，當作對照。
- 每個方向寫出底色、工作面、文字與重點色的色碼，以及字體、字級、圓角和一句理由。
  誠實寫出它接近哪一種預設，讓使用者知道選了什麼。
- 用 `AskUserQuestion` 這類視窗內選項，附上截圖請使用者選。使用者回覆混合或其他說法時，再做混合樣張確認，不自己猜。
- 方向樣張只在合成預覽外加一份樣式表，不改正式前端。

## JET 的限制

- 完全離線：不載入網路字型、CDN 或外部圖示；新增資源放在 `wwwroot/assets` 並附授權。測試禁止 `index.html` 與 `app.css` 出現網路網址。
- 字體只有打包的 Noto Sans TC 可變字型與 Instrument Sans 英文子集；圖示只用打包在 `wwwroot/assets/icons/fluent/` 的 Fluent SVG。
  新增圖示時從同一套件同一版本取用，連同授權放進同一資料夾；樣式表引用的圖示由架構測試檢查是否存在。
  JET 的字標用打包的字體畫出，不另放標誌圖檔；架構測試檢查頂部標題的字標標記與樣式。
- 沒有前端框架與建置工具；樣式集中在 `app.css`，不另建第二份前端。
- WebView2 跟著 Edge 更新，可以用 `:has`、container query、`color-mix` 與 `oklch`。
- 架構測試會直接比對 `app.css` 與 JS 原始碼字串。改到被鎖住的值時，先寫原因並保存第一次失敗，再依裁定改寫，不放寬其他斷言。
- 既有樣式的間距還沒全部收斂到 4 的倍數。新寫或改動的地方照規則做，不必為此一次重排整份樣式表。
- 流程總覽的圖表色票寫在 `overview-bi.js`，要和 `app.css` 的 `--chart-*` 變數一起改。
- 使用者在 Codex 的瀏覽器主機（`127.0.0.1:4244`）看畫面並註解。Agent 不啟動、不關閉、不連線那個主機。
  Claude 要在接上正式後端的畫面檢查設計時，用 4245 的 `JET browser host (Claude)`，自動交錯操作檢查用 4246，
  做法見 `.agents/harness/frontend-design-mode.md` 的「台灣中小企業合成案件與交錯操作檢查」。
