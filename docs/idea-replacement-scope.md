# CaseWare IDEA JET 替代範圍

目前狀況：早先新增的九項篩選操作已通過使用者人工驗收與 Agent 合成案件補充驗收，公司環境的三項操作
也已通過。2026-09-17 那一批回饋的主要功能和同一輪的三組篩選都已實作，A 到 U 的操作入口已依指定工作簿
補齊，兩個本機資料庫已有 33 組固定答案；完整性差異流程與新增操作仍在試用。具體來源、操作與報表驗證結果只記在
[使用者回饋與操作流程一致性修正計畫](history/specs/2026-09-17-user-feedback-and-workflow-review-plan.md)，這份計畫已在 2026-10-05 移到歷史文件，待使用者驗收。

這份文件用來判斷「目前 JET 是否已能負責原本 CaseWare IDEA 的 JET 工作」。它不重新定義欄位、規則或
報告內容，只把現行能力、證據入口與尚未確認的責任放在同一張表中。

早期筆記與已清洗的 legacy 歸檔可確認最初主線至少包含：匯入 CSV、TXT 或 XLSX，因應不同來源欄名進行
欄位配對，GL 與 TB 的完整性與有效母體判定，Account Mapping，組合簡單條件，以及輸出高風險結果與底稿。
這些內容用來補足責任輪廓；精確欄位、條件與報表仍以現行契約、程式、測試及使用者驗收為準。

這些責任屬於遷移前已存在的上下文，不應再次列為尚未定案（使用者 2026-09-07 指出）。
`business-logic-provenance.md` 的遷移核對顯示：共有 936 個同路徑產品檔，889 個雜湊相同，47 個差異已有分類，
未發現其他業務邏輯偏移。完整指南、action 契約及前端說明仍保存在 `docs/history/superseded/`。
`history/development-log.md` 的 2026-08-15 及 2026-08-26 紀錄也保存既有功能人工驗收完成的範圍。
因此應修正現行摘要的來源銜接，不能從摘要未逐項列全推定大量資訊遺失，或要求使用者重新定義全部需求。
歷史驗收證明當時候選，後續改動仍需自己的回歸驗證。

工作順序是先完整涵蓋舊版 JET 的審計功能和需求，再以新架構重構、優化與改良。脫離 CaseWare IDEA 後，
篩選由共用 AST 表達，操作應更直覺，並支援審計員自由組合不同情境。相容性要核對業務定義、實際命中及
完整流程，不要求複製 IDEA 的技術限制、舊表單缺陷或已被新裁定取代的行為。新版連續零尾數方針保留；
MAC 等外部多層會計科目表與對照不在目前職責範圍。2024 表單 A 到 U 和使用者回饋的逐項對照統一保存在
現行計畫，不另建第二份相容清單。

## 完成條件

IDEA 替代範圍只有在下列條件都成立時才能標為完成：

1. 維護者把既有 IDEA 工作、條件及底稿逐項對應現行實作、保留來源或明確的不做決定；不把來源查核責任
   改成使用者重新提供整份清單。只有具體且無法由原文解決的衝突才請使用者裁定。
2. 每項現行實作都有對應的公開測試、需要時另行執行的 provider 比較、GUI、Excel 或明示授權的私人案件
   驗證；不能用單一 `ReleaseCandidate` 名稱代替未執行的 SQL Server 或私人案件驗收。
3. 本機作業在公司允許的最低權限與網路條件下通過部署及操作驗收，不需要 AI 網路服務。
4. 尚未完成的 KCT 新條件與 SQL Server 中心化工作明確留在後續範圍，不混入 IDEA 完成宣告。
5. 文件、程式、測試與本次有效收據沒有互相矛盾；私人內容沒有進入 Git 或可同步證據。

2026-09-05 到 09-07 已完成的篩選補充與操作驗收，連同當時的舊功能來源對照，移到
[篩選補充與操作驗收紀錄](history/2026-09-07-filter-acceptance-records.md)。

## 目前不能自行補完的內容

- KCT 的正式全稱，以及條件 F 到 J 的來源。2026-10-06 的 KCT 簡報已提供條件 A 到 E 的定義與條件 B 的分類，
  整理在 [`kct-gl-workflow.md`](kct-gl-workflow.md)。F 到 J 與完整清單仍待 KCT 提供。

KCT 新條件的資料不足只影響後續 KCT 擴充，不把它加成既有 IDEA 本機替代範圍的完成條件。公司一般權限
完整操作、Office 原檔編輯與占用重試、案件冷複製與重開三項，已由使用者在 2026-09-17 回報驗收通過；
這是使用者回報，不代替尚未開發功能的驗證。
