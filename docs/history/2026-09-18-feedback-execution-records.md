## 指定借貸科目與每月日期條件修正（2026-09-18）

使用者本次原話如下，其中的本機絕對路徑以〔本機路徑〕代替，不寫進文件：

> 請在 〔本機路徑〕 接續開發。先用 harness 的 Context 命令了解目前進度，依現行計畫與最新裁定，完成下一批篩選功能修正。請自行判斷實作方式，驗證完整操作流程，並用清楚易讀的文字更新計畫。

本批處理兩項已有來源的缺口，依據為計畫的 A–U 對照與 9/18 使用者裁定：

1. 欄位條件可直接限制同一筆分錄的借貸方向。例如第一條指定「借方且科目 A」，第二條指定
   「貸方且科目 B」，再選同一傳票。沿用 `fieldValue`，不另建借貸執行引擎；原本沒有方向限制的
   條件維持原意。方向沿用現行 `drCrOnly`，比對匯入後的 `dr_cr` 借貸別，不由畫面重新判斷金額。
2. 日期增加每月月初及月底 N 天，N 為 1 到 31，包含月初或月底當天；天數超過當月長度時涵蓋全月。
   總帳日、核准日及已配對的額外日期各自判斷，空白預設不列入。例外仍以同一分錄內的否定日期
   條件組合，可分別排除補班、指定加班日期及月底區間；不改寫共用日曆，也不取代查核期末最後 N 天。

月底 2 天的固定答案包含 2024-02-28、2024-02-29、2025-02-27、2025-02-28、2025-04-29，
不包含 2024-02-27、2025-05-29、2025-05-01；月初 2 天則只包含最後一個日期。相同答案須在 SQLite
和 DuckDB 成立。這些核准日期可以在查核期間外，母體仍以總帳日限定，不能把兩種日期混用。

本批不改寫既有分類的審計角色比對，也不新增分類父子繼承。「全部明細符合」、多個欄位綁定同一筆
佐證分錄、舊表 A 的文字衝突及 C 只有貸方的邊界仍另列未完成。

### 結果

`fieldValue` 新增選用的 `drCr`，只接受 `debit` 或 `credit` 原字串；預覽、保存後的命中、佐證位置及報表條件文字共用同一規則。
分類查核確認 `CategorySelectionRoles` 仍依 `semantic_role` 比對，選兩個同為 Cash 角色的分類會得到相同結果。
篩選規則版本推進到 `filter-2026-09-18-v15`，舊命中結果不能直接用於新版報表。

修正過程找到並修好：SQLite 對 9999-12-31 計算下個月時越界造成月底分錄漏選（十二月改用固定 31 天）、借貸方向有前後空白時
執行與報表不一致、方向選單擠壓窄版文字條件（改為只在科目編號與科目名稱提供）。原有對齊斷言保留。

### 下一批與待裁定案例

1. 同傳票若要求「貸 B 且摘要含 X」由同一筆佐證分錄滿足，目前不能把兩條獨立佐證當成已支援。
2. 本地分類節點選取與審計角色不同。以 `AccountPairCategorySelectionPredicateTests` 的 `exactWithSameRoleCustomCategory` 為例，
   目前固定答案是 `M2|1`、`M2|2`、`M3|1`、`M3|2`；若新增「只選這個分類」方式，候選答案才會縮成 `M3|1`、`M3|2`。
   這是待實作方案。父子分類另需保存上下層關係，目前 `AccountTaxonomyCategory`（`AccountTaxonomyContracts.cs`）沒有父分類欄位。此方案不涉及 MAC。
3. 「至少一筆貸 B」與「所有貸方都為 B」結果不同；整張沒有貸方時「全部符合」是否要求至少存在一筆，本批沒有替使用者選定。
4. 舊表 C 只有收入貸方而沒有借方的異常傳票，在現行規則與 IDEA 來源可能得到不同答案；舊表 A 的標題和說明也仍衝突。

公司環境三項操作已依 2026-09-17 使用者回覆驗收通過，不再列為未完成。原始私人 PBC 的失敗原因仍未知。

## Harness 改善：以工具與回饋支持判斷（2026-09-18）

使用者原話：

> 約束限制太多了，你應該是建置使用更新的 harness 框架，而不是在專案建立一大堆的約束和限制來規避判斷行為

使用者接著補充文件用詞：

> 同樣的，務必要注意用詞，避免不必要的術語和資訊壓縮，盡量讓整體專案的文件內容保持可讀、易讀、清晰的摘要重點

這項要求修正上一輪的交接方式：不再把完整專案規定複製進 prompt，也不把固定閱讀順序或「唯一下一步」
當成額外開工關卡。計畫提供目標與證據，Agent 依問題自行選擇可回復的實驗、設計與驗證，遇到失敗後調整。
真正的業務歧義與外部授權另依其責任處理；一般工程選擇不逐一等待使用者決定。

本次新增 `tools/verify.ps1 -Command Context`，命令契約版本為 8.2。它讀取現行計畫摘要、尚未提交的修改及近期測試結果，
缺少一部分資料時其餘資訊仍會顯示；不把 Git 版本相同當作目前修改已經測試通過。新的工作方式也寫入 AGENTS、開發流程與框架使用文件。
Context 的 17 項檢查、完整框架 463 項檢查與文件檢查（37 份文件）都通過。本輪沒有改動產品規則。
