本文件記錄 2026-09-22 與 2026-09-23 註解涉及的報表、科目配對檔和舊程式來源，
不是另一份開發計畫。進度與驗證結果記在現行使用者回饋計畫。

四份工作簿只讀取文字、儲存格位置與結構，未修改範本，未執行巨集、外部連結或 Excel。

來源確實使用「JE 測試母體」，因此不能說它不是審計用語。畫面依目前資料範圍改用具體說明；
原始底稿、既有報告工作表及歷史引用中的名稱不偷偷改寫。
底稿含 59 筆抽樣說明，但本次不是更改抽樣規則的授權，也不以文字整理改動抽樣量。

## 同一資料跨畫面的名稱

| 概念 | 對外用語 | 不改動的部分 |
|:---|:---|:---|
| 期間判斷日期 | 總帳入帳日 | 2026-09-23 使用者採用新名；`postDate`、`post_date`、`總帳日期_JE` 及舊報表原欄標保留。傳票日期與傳票核准日另列，定義見指南第 2 節。 |
| 本案會計科目的識別欄 | 會計科目編號；短表頭可用科目編號 | 來源別名仍接受科目代號、`account code`、`GL_Number`。不改匯入相容性。 |
| 一筆分錄的單欄金額 | 分錄金額（單欄） | `amount`、金額方向、四位小數及舊報告欄名不變。 |
| 已套用欄位配對的試算表 | 已配對的試算表 | `tbBalances` 與金額換算不變。 |
| 篩選成立的分錄 | 符合條件的分錄 | `isHit`、主要條件、佐證分錄與參考分錄的計數不變。 |
| 對整張傳票或借貸方設定至少一筆、全部或不存在 | 傳票分錄條件 | `voucher` 與量詞運算不變；不把數學名詞當作操作名稱。 |
| 分類的收入、現金等用途 | 分類用途；相同分類用途 | `semanticRole` 不變，不和人員職務混稱。仍是進階設定，不沿用上層。 |
| 報告的產生時間 | 建立時間 | 取 `generatedUtc`，不是目前檔案修改時間。外部修改另外提醒。 |
| 報告大小 | MB，兩位小數 | 一 MB 為 1,000,000 位元組；原始 bytes 保留，未知大小不顯示成零。 |

`ReportArtifactContracts.cs` 說明 `Bytes` 與 `LastWriteUtc` 是寫完當下的紀錄，用於偵測外部變動。
因此不能把 `LastWriteUtc` 包裝成檔案總管目前的修改時間。畫面保留實際檔名，不再顯示完整路徑；
四至六步共用相同清單及「開啟資料夾」文字，仍以報告識別值開啟位置。

## 全畫面核對範圍

| 區塊 | 檢查與處理 |
|:---|:---|
| 案件清單、建立案件、頂部摘要 | 保留既有案件名稱與客戶資料意義。頂部只留英文標題；不改 Windows 操作人員來源。 |
| 流程側欄、收合步驟 | 標題改「流程」，用一次短動態線條呈現；減少動態偏好關閉動畫。摘要仍與主標題分行。 |
| 匯入資料 | 檔案筆數與來源列位置分開；來源原文與匯入錯誤位置不改成審計結論。 |
| 欄位配對、金額模式、額外欄位 | 單欄金額名稱同步領域目錄與前端；保留模式相依必填、來源共用和日期獨立定義。完成提示不再使用「已標準化」。 |
| 資料驗證、分錄測試範圍 | 兩組統計與總覽共用數字字級、字重、行高及等寬數字。抽樣說明明示人工核對，不暗示系統已確認可靠性。 |
| 科目配對 | 改成搜尋、勾選、整批套用、儲存。可全選目前一頁；不暗中修改其他頁。取消還原，儲存失敗保留草稿。Excel 整份取代的提示保留。 |
| 分類設定 | 分類名稱仍是日常操作；分類用途與上層分類屬選用設定。配對清單顯示目前分類及待儲存狀態。 |
| 預篩選 | 人員、科目彙總與篩選結果分開。多項明細仍可展開，這是選用結果清單，不是隱藏必要定義。 |
| 進階條件、結果與已保存情境 | 完整條件、判定說明、結果說明及每筆符合原因直接顯示。條件結合設定、空白值設定、範例與已保存情境操作仍可展開，因為其中有選用操作。 |
| 匯出底稿、報告歷史 | 共用檔名、建立時間、MB 與資料夾入口；保留外部修改、檔案不存在及先前版本提醒。 |
| 流程總覽 | 標題使用客戶名稱，案件識別僅在摘要行保留。統計名稱與第四步對齊，移除回放等工程用語。三組長圖表維持按需展開；技術資訊仍收合，不冒充審計步驟。 |
| 右側資料預覽 | 試算表名稱和領域資料集標籤同步。原始欄位名稱與使用者自訂欄名保留，避免資料來源失真。 |
| 全部表格、選單、對話框與圖表 | 既有字體別名均指向 Noto Sans TC；圖表亦使用該字體。統計採共用字級，表格和圖表刻度保留較小字級，不把不同閱讀層級強制同大。焦點框改畫在元件內緣，避免捲動容器裁掉左邊。 |

這次沒有刪除所有展開介面：必要說明直接呈現，長清單、圖表、選用表單與診斷資訊仍可展開。
介面文字不重新計算審計規則；篩選讀回文字的前後端名稱一起修改，識別值與已保存情境不搬移。

## 2026-09-22 後續九則註解

科目配對的 JET 與 Excel 方式改為互斥顯示，分類設定另開子畫面；切換不清除草稿。
移除報告時間旁的「JET 產生」及重複用途提示，時間來源仍為 `generatedUtc`。
預篩選的報告區只保留檔案及操作，不重複程序標題。第五步取消固定操作列及左側獨立捲動，
A–U 與常用範例用完整寬度排列；替換目前條件、匯入覆蓋及重建清空等影響仍就近說明。

## 2026-09-23 再次核對

上一輪把科目配對欄名刪成「C 欄」，雖然縮短文字，卻失去在 Excel 辨認操作對象的資訊。

兩者都是 `Standardized Account Name*`。畫面必須沿用這個名稱，保留「選擇科目分類」及 Cash、Revenue 範例。
沒有改寫工作簿或執行 Excel。

`legacy/idea-script.bas` Routine R5 依傳票建立人員彙總，R6 依科目彙總後按 `NO_OF_RECS` 升冪排序，
兩者不是 11 筆以下的固定篩選。現行 `PrescreenRules.cs` 的兩個上限保持 11；
顯示名稱改為「編製分錄較少的人員（11 筆以下）」及「使用較少的科目（11 筆以下）」。
第四步、第五步選單與條件說明、總覽圖表及後端名稱同步；既有案件識別值、歷史情境自訂名稱與已匯出的檔案不改寫。

展開明細的標題改「篩選結果」，總覽對應「預篩選結果分布」。完整操作與保存後留在原頁的檢查記在現行計畫。
之後的文字複審須對照真實欄名與操作，不再把縮短句子當作可用性的證據。
