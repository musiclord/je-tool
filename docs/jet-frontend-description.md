# JET 前端說明

更新日期：2026-09-23

一般操作提示說明查找條件、結果或下一步，不夾帶程式沿革與內部資料格式。
例如借現金範本說明「借方為現金，而整張傳票沒有貸方現金的分錄」，不附程式相容來源。
範本提示與新套用的動機使用同一份文字；已儲存的動機保留使用者原有內容。

六步驟共同完成同一案件的分錄測試：設定查核範圍、匯入來源、確認欄位、檢查分錄測試範圍及分類、選取待查核分錄，
最後產生底稿。同一資料與動作跨頁沿用名稱；提示只回答操作當下的問題，不要求使用者理解程式狀態或遷移背景。
按鈕須能從鄰近標題辨認對象，存在多種檔案時直接寫出檔案用途。必要的欄位說明直接可見；細節展開只用於選用內容。
狀態以文字說明，不使用看似單選鈕的空心圈。相依欄位、操作及結果就近排列，間距與按鈕尺寸使用共用樣式。

第五步的自訂條件可加入「同一分錄的條件括號」或「整張傳票或借貸方的分錄條件」。
括號內可再加括號，各條子條件各自選「且」「或」。傳票條件先選整張、借方或貸方，再選至少一筆、全部符合或不存在符合。
畫面與報表都列出完整括號及選取範圍，並說明全部符合需要至少一筆。
第四步科目配對以科目清單為主要操作。審計員搜尋科目並整批勾選，一次套用同一分類後儲存。
科目清單和 Excel 配對工作檔使用已確認欄位配對的科目，不要求先有資料驗證結果。
每頁 100 個科目，可全選本頁，支援編號與名稱搜尋。勾選欄可用滑鼠拖曳連選，Shift 點選則選取區間。
從已勾選的科目開始拖曳會取消該區間；拖回時縮小區間，原本區間外的選擇保留。
拖到清單邊緣會捲動本頁，不跨頁載入。Esc 或指標操作中斷會取消這次拖曳；換頁、搜尋及套用後重新建立選取起點。
單點與鍵盤勾選仍可使用。選取即時更新勾選、列底色與筆數，不重繪表格，也不套用或儲存分類。
科目名稱仍可反白複製；拖曳只從勾選欄開始。「本頁」文字與勾選框在同一列置中對齊。
只儲存本頁改動，其他頁與 Excel 已匯入的分類保留；失敗時保留選擇供重試。
「在 JET 配對」與「用 Excel 配對」只顯示所選方式，支援方向鍵移動分頁焦點、Enter 或空白鍵選取。
分類設定是獨立子畫面，返回時保留原方式及未儲存草稿。Excel 依取得、填寫與匯入排列，匯入覆蓋和重建清空的提醒保留。
「分類設定」可新增或調整名稱，日常操作不必處理分類用途與階層。「進階設定」才展開分類用途與上層分類。
第五步分類清單仍區分分類本身、包含下層與相同分類用途；分類用途獨立設定，不由父分類繼承。
含巢狀條件的編輯器讓底部操作列隨頁面排列，避免固定操作列遮住子條件。

右側面板標題為「資料預覽」，標題、頁籤、選單、提示與表格統一使用 Noto Sans TC。
一般文字及表格為 12px，狀態標題為 13px；數字保留等寬數字與右對齊，寬表在面板內捲動。
資料名稱為「GL 原始資料」「納入測試的分錄」「未納入測試的分錄」「TB 原始資料」「已確認配對的試算表」
與「科目配對」，頁籤、其他資料選單及載入提示使用相同名稱。
「納入測試的分錄」最後一欄是人工或自動，顯示「人工」「自動」或空白；原始資料、未納入測試的分錄及第五步篩選預覽不加這一欄。
流程總覽的數字、日期與圖表刻度也使用 Noto Sans TC。第四步兩組統計和總覽統計共用字級、字重與行高；表格與圖表刻度維持各自閱讀層級。

頂部案件摘要的標籤、中文、英文與數字統一使用 Noto Sans TC，數字使用等寬數字設定。
右上角顯示「目前帳號：帳號」，由既有 `system.whoAmI` 提供目前 Windows 身分。建立案件也使用同一個
Windows 短帳號，表單不提供另一個可修改的操作人員欄位。
案件已建立後，第一步摘要與總覽將原先保存的身分標為「建案者」，不與右上方的目前帳號混用。
預覽工具以範例帳號呈現，合成資料提醒只放在工具列。退出按鈕顯示「退出」，不承諾儲存未儲存的草稿。
當前步驟的「進行中」和未完成提醒集中在標題下方；建立案件收合時只顯示「案件基本資料已建立」，
詳細資料仍可展開查看。第五步以「儲存情境」為主要按鈕，「查看符合的傳票」為次要操作，儲存流程和規則不變。

收合步驟以名稱為第一行，資料摘要另列在下方；例如「匯入資料」下方顯示總帳明細與試算表筆數。
第六步還沒匯出目前版本的工作底稿時寫「匯出工作底稿」，已匯出時寫「已匯出工作底稿」與匯出時間，
和左側進度、第六步的完成用同一個判斷。
第四、五、六步及總覽使用「分錄測試範圍」，以查核期間與過帳狀態說明哪些分錄納入測試。
驗證與預篩選報告使用相同的操作列；已有當次報告時提供「開啟資料夾」，尚未產生時提供產生按鈕。
資料夾入口依已登錄報告的識別值呼叫既有主程式功能，不由前端猜測檔案位置。

欄位配對的簡易清單與對照表格都只顯示目前金額模式適用的欄位。多個用途共用來源欄時，表格列出全部用途，
並可切到簡易清單各自調整；切換介面不改已選配對。欄位鍵、標籤、必填模式與字面值欄位均以領域目錄為依據。
「傳票核准日」在簡易清單有獨立一列，直接選擇沒有核准日、由來源欄提供或與總帳入帳日相同。
只有「由來源欄提供」顯示來源選單；對照表格使用相同的三態控制，指派來源欄給核准日也會同步選擇該模式。
另兩種模式不保留核准日來源欄，不出現與選擇矛盾的輸入框。
匯入步驟的四個展開入口與已儲存情境的選單均稱「操作」，並提供含對象名稱的無障礙標籤。
展開後的「開始匯入」「編輯」「移除」仍使用明確動詞，不把所有按鈕改成同一名稱。

頂部、瀏覽器與桌面視窗標題使用 `JE Tool`。側欄標題為「流程」，短動態線條尊重減少動態設定。
頂列按鈕文字為「總覽」「開啟案件資料夾」「回首頁」「退出」，高度、字級與內距一致。
「回首頁」沿用原本離開案件並返回案件清單的行為。
整個介面的標題、數字、日期、選單、輸入框與訊息統一使用 Noto Sans TC；不另用等寬或襯線字體。
工作區不重複顯示 WORKPAPER、案件名稱與期間，中央流程列與流程總覽的六個階段卡都不顯示 01、02 等編號；頂部案件摘要及左側流程目錄保留。
篩選結果先顯示「符合條件：N 筆分錄（M 張傳票）」，查核期間及參考分錄的解釋直接顯示，不再收合。
第五步未完成原因只在標題下方顯示，頁尾不重複列出，下一步是否可用仍依原有判定。

條件組的結合方式與比對範圍集中在組標頭下，範圍入口明示同一分錄或同一傳票，
不放在條件清單尾端。選取的條件組以藍色外框和組號旁的「已選取」標示，不填滿整組底色。
點選組的標頭或外側空白即可選組，鍵盤可移至組框並按 Enter 或空白鍵。組內選取的單一條件另以藍色底和「選取中」標示。
選取條件時同步選取其所屬組；單獨選組則清除條件高亮。新增目標仍同步左側選單，不改條件、預覽或捲動位置。
錯誤條件保留紅色，外層畫面配色不變。檢視設計時須同時查看多組與跨組選取的畫面，避免局部調整產生多個競爭焦點。

左側固定為條件總覽，右側固定為組設定與條件編輯，不搬移或在組內嵌入整套選單。
寬度超過 900px 時保留左右排列；左側總覽隨整頁捲動，不再有另一個獨立捲軸。
較窄畫面保留上下排列。KCT 先呈現可用條件，停用項目放在「尚不可用」內，展開仍可查看完整名稱與原因。
右側資料預覽展開後，若第五步工作區剩餘寬度不足 660px，也使用上下排列，避免條件卡被擠窄。
多組時，左側以獨占一列的「新增條件到」下拉選擇唯一的加入目標；單組時不顯示。右側組標頭顯示組號及選取狀態，
不另設單選鈕。編輯某組中的條件會同步左側下拉與 KCT 勾選。切換目標不重繪輸入欄，
不移動焦點或捲軸，也不令預覽過期。組內不設僅作跳轉的「加入條件」按鈕。
「新增條件組」位於右側「條件組合」標頭，建立新組並選取該組。左右排列時定位新組；
上下排列時定位條件總覽的加入選單，讓使用者直接選條件。新增組與單獨選組會清除舊條件高亮，加入後定位新條件。
2026-10-02 使用者裁定移除「情境層級」，取代原本「非營業日 I 不加入目前組」的做法。KCT I 現在和其他 KCT 條件一樣，
加入目前選取的條件組，成為該組的一條條件括號。2026-10-04 使用者再裁定 KCT I 排除補班日，因此新括號內使用一條日期的非營業日條件。
I 和同組其他條件的連接方式依該組設定，條件說明與符合原因寫成「非營業日（排除補班日）」。
KCT 卡片不再有黃色標記與「適用整個情境」的說明，已選狀態與其他 KCT 卡片相同。
舊情境不轉換：原本獨立的非營業日組重開後，顯示成一般條件組裡的兩條預篩選，命中不變；
舊括號若是週末或假日，讀回仍寫「（週末過帳 或 假日過帳）」。要改成新定義，在目前組重新加入 I 再儲存即可。

「條件組合」和組數位於右側編輯區的同底色工具列，以細分隔線連接下方條件組；新增按鈕一直可見。組框再包住各條件，
與左側條件總覽、單一條件的藍色選取狀態分開。流程標題的程式焦點保留，但只有鍵盤操作顯示焦點框。

情境名稱與動機各自記錄是否由系統產生。自動名稱在儲存、重開和反覆勾選後仍隨目前條件更新，
使用者手改的文字不被覆蓋；舊情境沒有命名來源時保留原文，儲存或移除其他情境時也不補上命名來源。副本名稱視為固定文字，避免下一次勾選丟掉副本識別。
按「移除」打開確認後改去編輯或複製其他情境，確認區會收起。
儲存成功不切換頁籤，也不清除相同條件的預覽。請求期間新輸入的文字或新條件保留，並標示尚未儲存。
移除目前編輯的已儲存情境會清空連動草稿及預覽；移除其他情境只調整其清單位置，獨立新草稿不變。
後端失敗時保留原清單和草稿。同案重開、換案件或相依資料變更後，不接收之前請求的回應。

每條條件先顯示名稱，再顯示具體設定。預篩選條件的名稱為「預篩選條件」，下拉顯示「假日核准」等值；
其他分錄特徵沿用現有條件型別名稱。條件名稱只協助辨識，不參與 payload 或審計判定。
單邊分類和舊式條件也有標題。篩選方式與訊號下拉沿用共用焦點鍵，變更後仍可接續鍵盤操作。

主要動作列放在完整條件之後，所有視窗尺寸均隨頁面捲動，不覆蓋輸入欄或結果。
開啟儲存表單時，先收起預覽與儲存入口，表單明示儲存的是所有條件組。
取消編輯放在編輯情境標頭，儲存表單開啟時也能使用。零結果不顯示沒有用途的傳票搜尋，
有結果或已輸入搜尋字詞時仍保留搜尋與清除功能。條件變更後以短句提醒更新預覽，不繼續顯示舊命中數；換成新草稿，例如新增情境、取消編輯、開啟已存情境或套用範例時，回到初始提示。
查看完成後定位預覽結果。傳票分錄的狀態先顯示「符合條件的分錄」或「參考分錄」，直接顯示完整原因，
原因欄限制寬度並換行，內容直接沿用後端回傳，不由前端重新解釋條件。

儲存後不自動切換到已儲存情境，也不清空條件。原編輯區直接顯示儲存結果，保留同一條件的預覽；
再次儲存更新同一個情境，不新增重複項目。「新增情境」才清空目前草稿，已儲存項目仍保留。
儲存失敗仍停在原表單；能對到條件列的錯誤標在該列，名稱重複、超過十個情境或已儲存清單已變更這類錯誤寫在儲存按鈕上方，
沒有送出時不記「儲存篩選情境完成」。查看全部情境或矩陣由使用者主動切換。條件及預覽放在同一外框內，以分隔線區分設定與結果。

Excel 科目配對提示必須寫實際欄名「Standardized Account Name*」，並說明選擇科目分類，例如 Cash 或 Revenue。
不能只用欄位位置替代名稱。預篩選中的明細入口稱「篩選結果」，總覽稱「預篩選結果分布」。
兩項既有固定條件分別稱「編製分錄較少的人員（11 筆以下）」及「使用較少的科目（11 筆以下）」；
與不設這項門檻的「依分錄編製者彙總」及「較少使用之科目」分開，所有計數與 wire key 不變。

JET 的前端是放在 WinForms WebView2 裡的 HTML、CSS 與 JavaScript。它負責讓使用者操作案件、查看摘要
與有界明細；審計規則、資料有效性與報告內容由後端決定。

## 畫面結構

進入案件後，主要畫面有四個區域：

1. 頂部案件摘要：顯示案件識別、客戶、查核期間與目前階段；操作人員顯示在右上方。
2. 左側流程目錄：列出六個步驟與已完成狀態。下方的「進度」計算六個步驟中已完成的數量。
3. 中央內容：只展開目前步驟，其他步驟顯示一行摘要。
4. 右側資料預覽：查看來源資料、納入測試的分錄與有界明細；狀態訊息在左下角展開。

左下訊息的操作按鈕可整個換行，不把按鈕文字拆成直排；長日誌內容可換行並在區內捲動。

流程總覽使用 modal 呈現既有 state 的摘要。它不是第二套導航，也不重新計算每個步驟是否完成。
頂端小標是「分錄測試流程總覽」，標題是客戶名稱，沒填客戶名稱時改用案件名稱；下方一行寫案件名稱與查核期間，
標題已是案件名稱時不重複。
左側目錄的勾選與進度、流程總覽的完成數，以及第六步的「案件流程已完成」，都用 `ui-core.js` 的同一個完成判斷。
前四步在下一步可以進入時算完成；第五步在已儲存情境可以套用目前規則時算完成；第六步在已有目前版本的
工作底稿時算完成。因此匯出完成後，左側會寫「進度 6/6」，和總覽一致。

畫面上的金額一律顯示兩位小數加千分位，例如 35,920.33，由 `ui-core.js` 的 `money` 統一格式化。
這是使用者 2026-10-02 的裁定：畫面統一兩位小數加千分位，報表與底稿不變。輸入框、篩選條件的數值與
送給後端的值不經過這個格式化。

## 同一資料在不同畫面的名稱

同一個概念在各步驟、報告與總覽使用相同的對外用語；程式識別值、匯入相容性與舊報表欄名不跟著改。
「總帳入帳日」是 2026-09-23 使用者採用的新名。

| 概念 | 對外用語 | 不改動的部分 |
|:---|:---|:---|
| 期間判斷日期 | 總帳入帳日 | `postDate`、`post_date`、`總帳日期_JE` 及舊報表原欄標保留。傳票日期與傳票核准日另列，定義見 [`jet-guide.md`](jet-guide.md) 第 2 節。 |
| 本案會計科目的識別欄 | 會計科目編號；短表頭可用科目編號 | 來源別名仍接受科目代號、`account code`、`GL_Number`。不改匯入相容性。 |
| 一筆分錄的單欄金額 | 分錄金額（單欄） | `amount`、金額方向、四位小數的儲存精度及舊報告欄名不變；畫面顯示兩位小數。 |
| 已套用欄位配對的試算表 | 已確認配對的試算表 | `tbBalances` 與金額換算不變。 |
| 篩選成立的分錄 | 符合條件的分錄 | `isHit`、主要條件、佐證分錄與參考分錄的計數不變。 |
| 對整張傳票或借貸方設定至少一筆、全部或不存在 | 傳票分錄條件 | `voucher` 與量詞運算不變；不把數學名詞當作操作名稱。 |
| 分類的收入、現金等用途 | 分類用途；相同分類用途 | `semanticRole` 不變，不和人員職務混稱。仍是進階設定，不沿用上層。 |
| 報告的產生時間 | 建立時間 | 取 `generatedUtc`，不是目前檔案修改時間。外部修改另外提醒。 |
| 報告與工作底稿的檔案大小 | MB，兩位小數 | 報告清單與流程總覽共用同一個格式，以 1,000,000 bytes 為 1 MB；原始 bytes 保留，未知大小顯示「大小未知」，不顯示成零。 |
| 本次納入測試的分錄 | 分錄測試範圍；句中可寫「在本情境的分錄測試範圍內」 | `populationScope`、`auditPeriod` 不變。畫面不再使用「母體」；底稿既有的「JE測試母體」「篩選測試母體 :」與只在程式錯誤時出現的「GL 有效母體」訊息保留。 |

| 依傳票計數 | 傳票張數（同號只算一張） | `countUnit` 的 `vouchers` 與空白號碼不計張的規則不變。 |
| 尾數比對使用的金額 | 金額整數部分（不含小數） | 先捨去小數再比對末幾位的規則不變。 |
| 摘要欄位沒有內容 | 空白摘要 | `blankDescription` 識別值不變。 |
| 寫入案件的動作與狀態 | 儲存、已儲存、尚未儲存 | `data-action`、`savedScenarios` 等識別值不變；意思是保留或留存時仍可寫「保存」。 |

### 分類樹與科目選取

分類設定、套用分類的下拉及第五步的分類樹都顯示上下層。分類設定可一次建立上層與下層；新增下層先帶上層用途，手動改過的用途保留。
移除上層前列出受影響的直接下層，確認後接到原分類的上一層，儲存前仍可取消。新增分類後焦點移到名稱欄，進階設定切換保留焦點。
第五步的分類樹可以搜尋及收合。新卡與舊表 P 新加入的分類條件預設包含下層，舊情境沒有選取方式時仍按原本分類用途判斷。
條件說明寫出方式與實際納入分類；草稿引用已刪除的分類時提醒重新選擇，不顯示內部 ID。科目分類條件可選不限借貸。
科目編號的完整值清單可從分類樹查詢本案科目，搜尋及換頁只取有界資料；勾選仍寫進原有科目編號清單，保留前置零。
勾整個分類時不把第一頁當成全部。若超過既有 100 個值上限，原清單不變，提示縮小範圍或改用科目分類條件；查詢失敗可重試，晚到回應不改其他案件或已移除的條件。
## 案件選擇

啟動後先顯示本機案件。SQLite 與 DuckDB 可以在沒有 SQL Server 的情況下使用。只有使用者要求同步
線上案件時，才查詢 SQL Server registry；線上失聯不能清空已顯示的本機清單。開啟案件時，前端把清單列上的
資料庫種類一起交給 `project.load`。本機找不到案件資料夾時，只有 SQL Server 案件會再查線上登錄，
SQLite 與 DuckDB 案件直接顯示找不到案件。開案後只有 SQL Server 案件定時送出心跳。

建立案件時選定 provider。案件名稱錯誤由後端用結構化 `error.field = "caseName"` 指回欄位，前端不
解析錯誤句子猜測焦點。

載入或刪除失敗時，picker 在原操作位置保留錯誤，並提供「複製錯誤」與「輸出支援日誌」。後者使用
同一次錯誤回應的 correlation id，把去識別紀錄直接寫到該案件目錄；不需要先成功載入案件，也不依賴
Release 中不會顯示的 DEV 面板。Debug 組建在同一處另有「輸出診斷日誌（DEV）」，把含 SQL 與參數的原始
紀錄連同該次 correlation 寫到同一個案件目錄；DEV 面板裡的「輸出日誌」要先載入案件才能用，載入本身
失敗時就靠這個按鈕。報告檔在 JET 之外被改寫或刪除不會讓載入失敗；那只會在第六步清單標示狀態。

刪案確認先讀取 JET 紀錄中仍存在的報告與工作底稿份數，並明說整個案件資料夾及其他檔案一併刪除、無法復原。
讀取失敗時數量顯示未知，可重試，也仍可依原確認流程刪除；不把未知寫成零。SQL Server 案件另提醒這會影響所有共用者。

## 六個步驟

已有篩選情境時，更改前面步驟已設定的資料會清除後面步驟的設定（使用者 2026-10-07 裁定）。會清除的修改，是讓篩選結果過期的那些：
重新匯入或重新確認總帳與試算表配對、假日與補班日、每週非工作日、科目配對、授權名單、期末財報準備日與分類設定。
總帳與試算表的匯入或配對確認使用同一條規則，資料驗證、預篩選與篩選命中一起失效，全部已存情境清除。
清除後第五步回到預設狀態，訊息只寫一句請重新設定篩選情境；沒有情境或草稿可清時不新增訊息。
修改失敗時保留原情境。成功修改後，條件篩選報告與底稿照既有規則標成過期，已匯出的檔案不會改寫。
修改前不另加確認。已有篩選情境時，第二到四步顯示一句「更改已設定好的資料，會清除後面步驟的設定。」；
第一步只在打開「修改案件資料」後顯示同一句，案件摘要不顯示。不列出清除的細節。

### 1. 建立案件

案件名稱、查核起始日與查核截止日必填；案件編號、客戶名稱及期末財報準備日可以留空。
操作人員由系統取得目前 Windows 短帳號，使用者不能在表單改成別人。表單上方的操作人員提示讀取
`system.whoAmI` 的結果；身分晚於表單出現時，只更新操作人員那一行，不重建表單，已輸入的內容、選取範圍與焦點都保留。客戶名稱留空時，案件清單及工作區
以案件名稱作為主標題，不會顯示成空白案件。
查核期間決定要測試的分錄；期末財報準備日用於相關核准日風險條件，畫面在欄位旁說明兩者用途。
案件名稱只含空白或全形空白時要求填寫，查核起始日比截止日晚時就地指出日期問題，不送出建立請求。
期末財報準備日早於查核起始日，或晚於查核截止日超過一年時，欄位旁提醒確認年份，但仍可建立或儲存。
建案後可在同一頁按「修改案件資料」，只編輯客戶名稱、案件編號與期末財報準備日；案件名稱、查核期間、建案者與資料庫種類仍只讀。
取消不改原資料，失敗保留輸入。成功後更新抬頭和摘要，未儲存的篩選草稿保留；需要重算的結果依後端回應更新。
畫面也說明既有匯出檔不會被改寫，之後匯出才採新資料。第五步缺財報準備日時指向這個入口，不顯示內部欄位名稱。
第一步另顯示驗證保存的同號多入帳日提醒，分開列出號碼數與涉及分錄筆數。同月不同日也包含在內，傳票比對鍵不變。
尚未驗證、舊摘要缺欄或結果過期時寫尚未確認；只有實際量測到零才顯示零。這是供審計員確認來源資料的提醒，不阻擋操作。
「資料儲存方式」的「SQL Server（共用實例）」只在啟動時的 `system.databaseInfo` 明確回報這台電腦沒有設定
線上資料庫時停用，選單下方寫「這台電腦沒有設定線上資料庫，請改選 SQLite 或 DuckDB。」。結果還沒回來時
維持可選，不因查詢慢而擋人；已設定但連不上時也維持可選，建立案件時照舊回報錯誤。

### 2. 匯入資料

四類資料的入口按鈕統一為「操作」，展開後仍使用各自原有操作。未匯入授權清單只顯示「未匯入」，
不以「解鎖」描述用途。頁首提示簡述支援格式及合併條件；收合摘要以「總帳明細 N 筆 / 試算表 M 筆」呈現。
清單未完成符號為橫線，實際狀態仍以「未匯入」等文字呈現。授權清單的說明只寫比對名單外編製人員的用途，
選檔後才要求人員識別欄與 GL 一致，不夾帶 R5 人員彙總的背景。
日曆資料的匯入列稱為「假日與補班日」，展開後可匯入清單或設定每週非工作日，不顯示資料庫用語「日期維度」。
「取得假日與補班日範本」把兩份隨附的 2025 年範本複製到案件資料夾，同名檔保留，畫面逐檔寫出已複製或已存在。
不自動匯入或開啟資料夾；使用者可按「開啟案件資料夾」。畫面說明日期欄須用 yyyy-MM-dd，年份與日期需自行更新後再上傳。

GL 與 TB 支援 `.xlsx`、`.xlsm`、`.xls`、`.csv`、`.txt`、`.mdb` 與 `.accdb`。GL 可合併欄位相同的來源；TB 提示先整理好本次要比對的資料，不暗示能把期初、期末兩份檔案自動配成餘額。`.xlsm` 由 JET 直接唯讀
活頁簿內容，不啟動 Excel 或執行巨集。前端先讓使用者選檔，再要求後端檢視、預覽及匯入。
右側只顯示有界的少量預覽；完整資料直接寫進案件資料庫，不會整批放進 WebView2。
Access 使用現有 Office ACE 16 讀取一般資料表，沿用來源預覽及匯入清單；不執行儲存查詢或巨集，.xlsb 不支援。
授權編製人員、科目配對、假日與補班日是支援資料，不是每個案件都必填。
授權清單匯入須明確選來源欄位，可查看原始預覽及有效識別值。匯入與重開案件後都顯示原始資料列數、略過空白與重複數，
並說明標頭與完全空白列不計入；舊名單沒有保存統計時照實提示。原檔上方有標題列時，提示先在 Excel 刪除標題列再匯入。
有效名單另顯示出現在 GL 傳票建立人員的人數，一位都對不上時只提醒可能選錯識別欄，不擋後續操作；尚未確認 GL 建立人員
配對時提示先確認，確認後會更新比對。所選識別欄完全沒有有效值時，要求改選欄位或換檔重試，保留原名單。
取消或失敗保留原清單；移除會清除該清單和相依結果，保留 GL、TB 與驗證結果，預篩選需重新執行；已儲存的篩選情境依下方規則清除。
加入來源仍先進入匯入清單，由使用者確認；重新匯入同一資料集的按鈕明示取代資料。成功後說明哪些
配對及計算結果需要更新；已匯出的底稿檔案不會改寫。
追加後若後端發現檔名、工作表與實際列數都和既有來源相同，顯示可能重複的提醒，本次匯入仍成功；
這和下方「尚未送出的清單不重複加入」是兩件事，不會刪除已匯入資料。
一次選多個檔案時逐檔檢視，某一檔讀不出來不會中斷其餘檔案：那一列留在清單上，寫出原因，勾選框停用，
不能被送出；文字檔可以在同一列改選編碼或分隔符立刻重試，其他格式按「重新檢視」。再選一次已在清單上的
檔案或工作表不會重複加入，訊息區會說明哪些已在清單中。後端回的提醒（例如文字檔只讀到一欄，可能是報表格式）
顯示在該列下方，不擋匯入。每個來源的「預覽」只顯示表頭與前 10 列。
匯入卡片在剛完成匯入時顯示「剛剛重新匯入（時間）」或「已加入來源（時間）」，時間放在括號內，不用「·」串接。

多檔匯入只會合併欄位相同的列，不會辨認 TB 檔案的期初或期末角色，也不按科目把兩份檔案連接成餘額。期初、期末分檔功能已裁定不做，不能用普通追加代替。

### 3. 欄位配對

頁首只提示選擇來源及星號必填。已配對摘要的按鈕為「重新配對」和「預覽」，GL 設定分項呈現。
一般畫面文字以短句、逗號或分項表達，不使用「・」或「·」串接狀態。GL 與 TB 的確認狀態各自呈現；只確認 GL 時，不再把 GL 一起寫成待配對。
狀態用「已確認配對」，按鈕維持「確認配對」。來源欄已指定但尚未按確認時，不冒稱已確認。
兩種配對介面都不顯示常駐草稿警語；實際修改後提示重新確認，來源變更時提醒重新配對。
操作列與最後一個欄位區保留間距。從既有報告載入配對草稿的入口依 2026-09-22 要求撤下，待複盤後再定。
簡易清單只顯示「分錄測試欄位」與「來源欄位」兩欄；程式欄位識別碼仍留在資料契約，不要求使用者閱讀。
簡易清單的操作列按鈕是「預覽」與「確認配對」，和摘要卡的「預覽」同名。對照表格的借方代碼旁提示
「輸入代表借方的代碼，例如 D 或 1」。

前端顯示來源欄位、JET 目標欄位與值摘要，讓使用者確認 GL／TB mapping。欄位由審計員逐項手動選取；只有
`mapping.commit.gl` 或 `mapping.commit.tb` 成功後，後端才建立標準資料。
已移除自動建議功能；成功後顯示「已確認配對」。人工或自動、過帳狀態的來源值清單
在逐項設定時保留清單捲動、頁面位置與操作焦點；返回其他步驟仍依原本導航回到該步起點。

尚未按加入的代碼輸入也保留在本地草稿，不因另一組值摘要完成讀取而消失。草稿只屬於當時的案件、匯入
來源與欄位，取消或更換來源即清除。必要的畫面更新保留同值文字輸入的選取範圍與游標；日期和下拉選單
不套用文字選取 API。中文組字期間延後重建，組字完成後才顯示最新狀態，不把中間文字誤送成最後結果。

借方代碼、貸方代碼與攸關資料元素的顯示名稱是文字輸入框。每次輸入都會更新草稿、必填清單、修改提示，以及
「確認配對」能不能按；離開輸入框時不重建整個步驟。所以改完值不必先按 Tab，直接用滑鼠按「確認配對」或
「重新確認配對」，第一次就會送出。舊做法在離開輸入框時重建整步，按鈕在滑鼠按下與放開之間被換掉，
要按第二次才送出。修改已確認的配對時，畫面維持編輯狀態，直到確認或取消變更。

報讀器聽得出每個控制項的用途。簡易清單的來源欄下拉以欄位名稱命名，例如「總帳入帳日的來源欄」，
名稱取自欄位目錄。對照表格的每個下拉名稱寫出它所在的來源欄。兩個代碼輸入框分別名為「借方代碼」與「貸方代碼」。
金額加借貸別的兩種模式都要填兩碼，舊配對缺貸方碼時留空，不猜另一側代碼。兩碼的等價關係由後端提供，失敗時可重試，不掃描 GL 母體。
讀取來源值後，每個來源值的人工、自動與不歸類選項自成一組，以來源值命名，例如「來源值「0」」。
人工代碼與自動代碼的按鈕畫面上都寫「加入」，報讀器分別讀成「加入人工代碼」與「加入自動代碼」；
過帳狀態補充值的按鈕讀成「加入已過帳的值」。

可見欄位名稱統一為「總帳入帳日」，用來界定查核期間；正準欄名仍為 `總帳日期_JE`，action 仍為 `postDate`。
傳票日期選填，供回溯過帳及一般日期條件使用；未提供時回溯過帳顯示無法執行，其他程序不受影響。
核准日方式與來源欄位在同一區。指定來源欄時自動切換成「由來源欄提供」；選「沒有核准日」或「與總帳入帳日相同」時
清除來源欄配對。兩種編輯畫面共用相同的連動。「取消變更」一起還原欄位、金額模式
和所有 GL 設定，避免留下未還原的日期或分類設定。點選必填清單的欄位名稱，會在簡易清單定位對應控制項。

人工或自動分錄的值摘要只列最多 50 個常見非空白值，畫面另列空白筆數與是否還有未顯示的值。可逐值指定，也可只列人工或自動，
把其餘非空白值歸到另一側。空白可選人工、自動、不判定或先補齊來源；舊案件省略設定時保留原逐值規則。
這一區的標題是「人工/自動分錄代碼」，和欄位名稱「人工/自動分錄」用同一種斜線。
取消或更換這個來源欄時，前端清除上一欄的代碼設定，已提交摘要也不再顯示脫離欄位的舊值。
代碼經完整來源核對後確實不存在時，就地寫「來源裡沒有這個值」，不自動刪除。確認按鈕前同時提醒代碼重疊、已知的空白列與未歸類值，
提醒本身不阻擋確認。清單被截斷時，建議改用只列一側；尚未核對或核對失敗時明說狀態，不從畫面沒有列出某值推定它不存在。
只列一側、而且還沒讀取來源值時，確認按鈕前多一句提醒，例如「人工分錄代碼「1」還沒和來源核對。來源裡沒有這個代碼時，
其他非空白的值都會算成自動分錄。可以先按「讀取來源值」確認。」確認後，如果清單代碼在來源裡一筆都沒有，狀態訊息再提醒一次，
寫出代碼、來源欄與下一步。

確認配對失敗時，原因顯示在該配對區的確認按鈕上方。先寫一句總結，例如「68 列無法轉換，系統沒有儲存這次配對結果。」，
系統掃描全部來源後依來源欄與問題分組，每組一行：寫出完整列數、有界的值和列號樣本，
以及一次處理方式，例如「欄位「人工註記」有 47 列未歸類為人工或自動：「轉入」在第 33、34……列等。」；
空白值寫成「是空白：第 327、385 列」。每個值最多列 10 個列號，超過時，一組裡有多個值就寫出那個值的總列數，
只有一個值就寫「等」，因為句首已寫了總數。每組最多列 10 個值，其餘寫出未列出的列數，不把前 50 列當成全部錯誤。
能對到畫面設定位置的組，右側有「前往設定」：人工/自動分錄的空白問題移到「來源空白時」，其他人工判定問題移到「判定方式」，
攸關資料元素移到它的型別，其他欄位移到來源欄選單。設定改過後，舊錯誤仍保留並標示「設定已修改，請重新確認」，其餘組的定位按鈕仍可用。
訊息面板仍是一整段文字。重新確認後更新結果；換案件或匯入來源後清除舊錯誤。

過帳狀態換來源欄時也會清除舊的接受值與接受空白設定，請重新選擇哪些值表示已過帳。兩種值摘要可分別
讀取，失敗後按「再試一次」會重送請求。重新匯入或切換案件後，舊值摘要與舊配對錯誤不再顯示。

重新匯入 GL 或 TB（取代或附加）會讓已確認的配對失效。同一次開啟中保留目前草稿，畫面明說「已保留目前草稿」；
重開案件才帶回上次確認的配對，兩者都請使用者檢查後按「確認配對」。新資料沒有的來源欄會從草稿拿掉，提示逐一寫出是哪個欄位、
原本選的是哪一欄，例如「總帳入帳日（原為「日期」）」；人工/自動或過帳狀態的來源欄被拿掉時，它們的代碼設定也一起清掉。
重新整理頁面或重開案件後，`project.load` 帶回上次確認的配對作為草稿，不保存關閉前尚未確認的編輯。
攸關資料元素欄位沿用上次確認時的欄位識別碼。

攸關資料元素欄位另有「傳票建立日」快捷，選未使用的來源後自動勾選、命名並設為日期型別；已有同名欄時更換它的來源，保留既有識別碼。
來源已用於另一欄時，先顯示目前用途，提供「把它改成傳票建立日」與取消。確認後沿用被選欄的識別碼，不刪除其他欄位。
若原來另有傳票建立日欄也會保留，提示會說明；核心配對已使用的來源不能在這裡重複使用。
第五步選欄位時，攸關資料元素欄位的名稱後面會加註來源欄，例如「傳票建立日（攸關資料元素欄位，來源欄：CreateDate）」，
一般條件、舊式 typed 條件、新增篩選條件、加入子條件，以及舊表 O、R 與範例 2 的選單共用這份文字。
兩個同名欄位也分得出來；條件仍以欄位識別碼儲存，讀回文字只寫欄位名稱。
攸關資料元素欄位可全選或全部取消。全選只勾選尚未被核心配對使用的來源欄，預設沿用來源欄名並先視為文字；
使用者仍可逐欄調整名稱與型別。後端最後檢查欄位是否存在、名稱與型別是否合法、欄位識別碼是否沿用正確，
以及來源欄有沒有重複。
勾選或改型別後保留清單捲動位置；全選和全部取消後，焦點留在仍可操作的控制項。編輯已確認的配對時先保留提示區高度，
第一次修改不會把下方清單推走。TB 與 GL 一樣，必填文字欄整欄空白時在成功確認後提醒使用者檢查配對。

### 4. 資料驗證與測試

「用 Excel 配對」可以匯入前一案件的配對檔。匯入成功後，在分類留白提醒旁列出「本案沒有的科目」與「配對檔未列的科目」筆數，
各有「列出科目」。兩份清單依有效 GL 與 TB 的科目聯集比對，不把配對檔本身當成本案科目來源。
額外科目保留，畫面說明它們不會出現在篩選結果；未列科目不屬於任何分類，與留白視為 Others 不同。
清單按需載入，可分頁與失敗重試；畫面重繪保留已載入頁，案件或資料變更後不沿用舊回應。
重開案件時先顯示「尚未核對」，不自動重掃 GL；按「列出科目」才取得本次筆數。
Excel 檔有篩選或隱藏列仍會全部匯入。調換新舊範本的欄序時，先以確切欄名辨識，不因分類欄含 Name 而讀成科目名稱。

畫面先顯示分錄測試範圍、總帳入帳日空白資料與驗證摘要，再讓使用者以分頁查看差異或問題明細。預篩選可在此執行，
但它只是風險訊號，不是進階篩選的必要前置。
不在第四、五步頂端重複顯示結果過期的全頁黃框。驗證和預篩選各自執行、各自更新狀態，不能互相視為完成。
成功後清除對應旗標；資料變更只清相依結果，沒有執行過的程序不標成過期。案件載入最後採用後端旗標。
完整性差異保留為警示，已完成驗證即可繼續篩選與匯出；流程可繼續不等於完整性通過。
空白傳票號碼和空白科目編號各有明細、排序、搜尋與分頁。同筆同時缺兩欄時分別列示，不把兩類相加當作總分錄數。

完整性測試先確認 JET 存下的分錄沒有少、也沒有重複，明細兩欄是「確認配對時算出」與「存下後重新計算」的筆數、借方合計及貸方合計，
再逐科目比對 GL 與 TB。卡片與明細都寫明這一項不和來源檔自己的合計比對。原始判讀句保留「金額不符代表總帳母體可能缺漏」。
只有第一項不符時，卡片狀態寫「存下的分錄數字不一致」；舊案件沒有這組數字時寫「存下的分錄無法核對」，不寫泛稱的「未通過」。
借貸不平測試逐張傳票檢查借方與貸方金額是否相等；判讀句照使用者原件寫「借貸不平代表傳票編號、金額欄位可能有誤」。
資料可靠性測試抽出分錄樣本，供審計員核對傳票附件及篩選欄位。說明寫明先確認 RDE 可靠性，再執行高風險篩選條件；這是審計作業順序，不是新增操作關卡。程式維持固定且可重現的抽樣，
不替審計員判定可靠性，也不增加額外門檻。ValidationReport 與 INF 報表內的「INF 抽樣測試」名稱保留，
畫面在報告清單標示用途並保留實際檔名，不在測試說明交代沿革；DPP 範本指引不改寫。

畫面金額維持兩位小數。完整性與借貸不平的非零差額若會顯示成 0.00，改寫「不足 0.01」並提示完整數字在驗證報告；負數差額仍標明是負值。
這只改畫面格式，不改差異判斷、報告或底稿精度。不存在或尚未執行的摘要顯示未知或原因，不把 null 當成 0。

畫面的「總帳入帳日空白」目前只列匯入 GL 中總帳入帳日空白的來源列；這些列無法判斷是否在查核期間，因此不納入
分錄測試範圍。日期在查核期間外不列在這裡。既有 action 回應仍使用 `sourceQuality` 與 `nullPostDate`，畫面不顯示
內部分段名稱 Part A 或 Part B。

驗證完成後產生兩份驗證報告，並建立尚不存在的科目配對範本。範本已有檔案時保留，已填分類不會被
重新驗證覆蓋。畫面分別說明報告和範本的處理結果；其中一項失敗仍保留驗證與其他已完成輸出，可在
對應區塊重試。手動按「重建科目配對檔」才覆寫原檔，按鈕旁明示會清空已填分類。取消後不啟動後續輸出。

科目配對檔的完整狀態顯示在「用 Excel 配對」分頁。正在準備或準備失敗時，預設的「在 JET 配對」分頁也在
科目清單上方顯示一行狀態。失敗時寫出原因並提供重試按鈕，按下後切到「用 Excel 配對」分頁，焦點移到
「準備科目配對檔」。已建立或已保留時只在 Excel 分頁顯示，不打擾直接在 JET 配對的審計員。

上方統計列的「納入測試的分錄」與下方「分錄測試範圍」區塊的「納入本次測試」，都指符合查核期間與過帳狀態設定的分錄；
「已完成欄位配對的分錄」則包含因期間與過帳狀態排除的列。「分錄測試範圍」區塊另列「日期未符合」與「過帳狀態未符合」，
逐項列出後端計數，不在畫面自行相減。
各步報告清單先顯示「資料驗證報告」「資料可靠性抽樣清單」「預篩選報告」「條件篩選報告」或「工作底稿」，
再列實際檔名、建立時間與大小，不重複展開完整路徑。使用者可按「開啟資料夾」定位檔案；遺失檔案停用定位，保留原有提醒。
報告列的按鈕垂直置中，窄版整顆換行，文字不被擠成直排。
重新開啟案件時，預篩選的定位說明使用目前版本的文字；原本保存的結果、不適用原因、計數、執行識別與日期都照原樣顯示，不回寫原紀錄。

科目分類名稱輸入只更新本地草稿與就地提示，保留原輸入框及中文組字狀態；儲存、取消、新增與移除
才重建清單。儲存仍由 `accountTaxonomy.save` 檢查名稱與穩定識別碼，並使預篩選及篩選命中失效。
分類設定預設只呈現名稱；開啟進階設定後，角色與上層分類各有可見標籤及就近說明，窄視窗分列。
「科目配對」依序包含本案科目清單、分類設定入口及 Excel 批次操作入口；日常分類不需先開啟 Excel。
批次操作的填檔說明使用範本實際欄名 `Standardized Account Name*`，不只寫 C 欄。
「準備科目配對檔」保留既有檔案，旁邊提供「開啟案件資料夾」；填妥存檔後按「匯入科目配對檔」。
依目前資料重建科目清單的操作另列，明示會清空檔內分類。原有分類儲存、範本保存與覆寫行為不變。
預篩選區以「預篩選」為單一標題，兩項彙總後可展開「篩選結果」；不顯示「主要呈現」等額外標籤。
驗證與預篩選明細各自在區塊內顯示讀取狀態，過帳側與核准側都會送出唯讀查詢。失敗可直接按「再試一次」；
同次讀取不重複發送，已完成表格的排序與分頁在收合再展開後保留。換案件、資料或執行結果後，舊快取與
晚到回應作廢。這些查詢不占用全畫面的作業遮罩，符合 `ActionExecutionPolicy` 的併行查詢分類。

分頁、搜尋、排序及未分類科目明細共用就地讀取流程。請求期間只標記該表忙碌，其他區塊可繼續操作；
失敗保留原有資料與頁面位置。重試使用失敗那次的排序及搜尋值，不偷偷改查另一頁。案件、資料版本、
執行結果或 DOM 已更換時丟棄舊回應。讀取狀態以 `role="status"` 與 `aria-busy` 提供，不移動焦點，
也不顯示沒有依據的進度百分比。此設計參考
[W3C 狀態訊息指引](https://www.w3.org/WAI/WCAG21/Understanding/status-messages)及
[Fluent 等待體驗](https://fluent2.microsoft.design/wait-ux)，實際結果仍由 JET 後端決定。

報告成功產生後，若清單刷新失敗或逾時，保留既有清單並加入新檔，在新檔旁提示可直接開啟案件資料夾，
不用重新產生。這是暫時的顯示提醒，不新增全頁黃框，也不把成功輸出改報為失敗。

### 5. 進階條件篩選

使用者建立條件情境，先預覽，再儲存。條件編輯器只產生後端接受的結構；不在 JavaScript 組 SQL 或
自行計算命中結果。預設用 `query.filterVoucherPage` 顯示傳票清單，展開時透過
`query.filterVoucherRowsPage` 取得該傳票查核期間內的完整分錄，每頁 50 筆。符合條件的分錄、同傳票佐證與
參考分錄分開顯示，各列指出符合第幾組第幾條主要或佐證條件。因整張傳票條件列入的分錄標為「傳票條件成立」，不新增逐列的另一套命中判定；只有命中傳票，沒有
待判定。傳票清單表頭可點排序，上方有「依傳票號碼查看」。原有命中列查詢仍保留相容入口。

第五步分為「篩選與檢視」和「已儲存情境與矩陣」。切換只改畫面，不清除草稿、值或預覽。一般桌面寬度下，
左側選條件，右側調整本次篩選並看結果；窄視窗改成上下排列。配色沿用 JET 既有暖米白和文字、狀態色。

左側可選「KCT 條件 A 到 J」或「自訂篩選條件」。分頁名稱寫出 KCT 的字母範圍，自訂裡的舊表條件都標明「舊表」，兩邊的字母
不會混淆；KCT 卡片保留完整名稱、選取狀態及停用原因。
A 納入曆年季底和查核期末，讀回列出合併後的日期區間。B 已可加入，預設包含下層，兩側分類留待審計員選擇；
科目配對沒有非空白分類時仍列於「尚不可用」，分類留空時「尚需補齊」指出組號與條號。
B 卡說明先新增並配對固定資產、營業費用，在建工程不能放在固定資產及其下層。C 卡及編輯區說明：
「現金不算一般對方科目；要排除現金銷貨，改用預篩選條件『未預期借貸組合』。」報告的 C 條件讀回不變。
A 到 E 的自動動機採用 KCT 評估說明，每張卡一行；F 到 J 沿用卡名，已儲存及手改文字保留。自訂先選欄位、科目分類或分錄特徵，再按「加入條件」。
加入後左側回到未選取，右側固定顯示所選欄位名稱；換欄位時移除再加。
兩者都加入目前選定的條件組，多組時用「新增條件到」選擇目標。「查看全部分錄」放在左側，開啟既有標準化資料預覽。
「常用範例」是另外可展開的入口，保留六筆既有範本：「借現金、貸非現金」「貸現金、借非現金」

### 6. 匯出底稿

使用者選擇報告並啟動匯出。進度事件只顯示正在準備、寫入或發布哪一部分；只有 action 成功回應才
顯示完成。報告清單每筆顯示檔名、時間與大小；檔案在 JET 之外被改過或已不存在時，多一個狀態標示
（「已在 JET 之外修改」、「檔案不存在，重新匯出即可」），只提醒不阻擋。Working Paper 每次匯出新增
一個版本檔；第六步的「工作底稿版本紀錄」列出全部版本，最新在上，每頁最多 50 份。較早資料或
條件產生的底稿標示「先前資料或條件的版本」；這些紀錄不影響目前流程是否完成。按「開啟資料夾」
會在檔案總管選取該檔，讓使用者自行開啟；已刪除的版本保留提醒並停用這個按鈕。重新匯出後立即保留
新舊兩筆，不必重新開案。科目配對範本由第四步的卡片產生，不在這份清單裡。
流程總覽第六階段的「檔案大小」和報告清單一樣以兩位小數的 MB 顯示，不顯示位元組數。

匯出前列出採用的情境及條件儲存時間。已有可用的驗證結果及已儲存情境即可進入第六步，不要求另一份報告檔存在。
工作底稿版本紀錄不依賴情境：情境全部刪除或無法套用目前規則時，只要已經有任何工作底稿版本紀錄，
仍可進入第六步查看。這時匯出按鈕停用；沒有已儲存情境時，畫面寫「目前沒有已儲存的篩選情境，無法匯出工作底稿。
請到「進階條件篩選」儲存至少一個篩選情境，再匯出工作底稿。」。情境與版本紀錄都沒有時，第六步照舊鎖住並寫出原因。
底稿匯出使用目前資料重新計算已儲存條件。條件篩選報告尚未產生、過期或被刪除，都不阻擋底稿；不會順便重建該報告。
新增篩選條件的完整說明一併寫入底稿，未儲存草稿不會自動納入。已儲存情境無法套用目前規則，
而且還沒有任何工作底稿版本紀錄時，第六步維持鎖定，步驟檢查列出的原因是「修改無法套用目前規則的篩選情境」。
流程與總覽的短句維持「需先儲存篩選情境」，具體原因由步驟檢查說明。
已有版本紀錄時可以進入查看，畫面照舊逐筆列出無法套用的情境，匯出按鈕停用。
匯出頁與總覽都以目前版本的工作底稿表示完成，不要求條件篩選報告同時存在。

清單即將超過 4,096 筆時，JET 才整理已確認檔案不存在的底稿紀錄；現存或無法確認的檔案紀錄會保留，
不刪除任何實體底稿。發布前再次確認檔案狀態，仍超限就提示自行整理舊底稿後重試。匯出成功後立即
同步整理後的完整清單。

### 各步明細表的排序與搜尋

完整性差異、借貸不平、空值紀錄、總帳入帳日空白、抽樣樣本、預篩選命中、篩選命中、傳票矩陣、分錄明細與命中
傳票清單的表頭可點排序，點一下升冪、再點一下降冪，箭頭標示目前方向；表上方有「依傳票號碼查看」輸入框
（科目層的表是「依科目編號查看」），送出後只留含該文字的列，按「清除」還原。換排序或搜尋時清掉列從
第一頁重載，「載入更多」接續同一排序；排序與搜尋都在資料庫端，空值排最後。
第四步因其他狀態更新而重繪時，一般明細、INF 樣本及預篩選明細保留已載入的列、游標、排序、搜尋、展開狀態與捲動位置。
讀取失敗也保留已載入內容，重試接續原位置。切換案件、重新開案或產生新結果後才丟掉舊分頁；晚到回應不能寫入新案件或新結果。
缺傳票號碼與缺科目編號分開呈現，各自排序、搜尋與分頁；同筆同時缺兩欄會分別出現。
兩類均可搜尋傳票號碼、科目編號或摘要，搜尋失敗保留原結果並可重試。表頭明示總帳入帳日，不泛稱日期。
表格正在讀取時按「查看」或「清除」不會被忽略：畫面說明會在讀完後接著執行，只保留最後一次要求；
目前的讀取成功或失敗後都會接著執行，失敗後也可以再按。

- `wwwroot/js/state.js` 保存目前畫面、案件 metadata、摘要與 request id，不保存完整 GL／TB。
- 下一步是否可用，以後端結果與 `ui-core.js` 的單一進入條件檢查呈現為準。
- 切換步驟可以保存位置，但不能把「看過某頁」誤寫成「業務條件已完成」。
- 上游資料、mapping 或規則版本改變後，前端不沿用舊結果；結果清除與重新執行的狀態依實際相依關係處理，不加全頁重跑警語。
- Background response 必須確認仍屬同一案件與同一 request，不能覆寫後來載入的 state。
- 通知慣例（2026-09-01 收斂，整個前端唯一）：凡是會改變任何衍生畫面輸出的 store 寫入一律
  bump（`contentVersion` 進版、面板重建）；「只 notify」僅限「唯一視覺反映就是使用者正在編輯的
  那個控制項本身」的連續文字輸入，且必須在 blur 後延遲一次 bump 收斂。select／radio／checkbox
  是離散提交，永遠直接 bump。重建後的輸入焦點與捲動由 `app.js` 的 `renderContent` 依焦點識別
  屬性與 `data-preserve-scroll` 標記統一還原，步驟模組不得各自發明保留機制。已文件化的
  例外包括 filter-step 的規則值編輯、科目勾選和拖曳的暫時選取，以及欄位配對的借方代碼與攸關資料元素
  顯示名稱。這些操作就地同步相關控制項，避免重繪打斷輸入、指標捕捉或滑鼠點擊；
  真正套用分類和保存資料仍依 Store 更新。不能把是否呼叫 bump 當成是否完成業務程序的判定。
  守衛測試：`JET.Tests.Architecture.StoreNotificationConventionFrontendTests`。

欄位配對的必填鐵軌與「確認配對」按鈕都由同一份 draft 推導。文字輸入就地更新兩者，不重建；下拉選擇會立即 bump；中央內容重建後，
只依每個控制項明示且唯一的 `data-focus-key` 還原焦點，並還原 `data-preserve-scroll` 容器。這避免右側
仍顯示「待指派」、按鈕維持停用，或重繪把焦點送回錯誤控制項。

## 診斷日誌

「狀態與訊息」只加入 info 或 warn 等級的非空白文字，未指定等級時使用 info。
後端拒收格式錯誤的訊息時，先記入去識別支援日誌，前端再跳過該筆，繼續保存後面的訊息。
忙碌、資料庫或傳輸失敗仍保留原筆重試，不當成已保存；切換案件後不把舊案訊息寫入新案。

- 「輸出支援日誌」是 Release 可用的去識別紀錄，案件尚未成功載入時也能從 picker 使用。
- Debug 的「DEV — 診斷日誌匯出」保留較完整的原始紀錄；面板版要先開啟案件，picker 錯誤回饋上的
  「輸出診斷日誌（DEV）」則不用，並帶該次失敗的 correlation。畫面明示內容可能含案件資料。
- 兩種輸出都由後端直接寫入目前案件目錄。前端不接受任意路徑，也不自行組合或過濾 NDJSON。
- 非預期的錯誤（錯誤碼 `bridge_error`）在畫面上只顯示固定訊息「發生非預期的錯誤，這個動作沒有完成。
  請按畫面上方的「輸出支援日誌」，把檔案交給支援人員。」，不顯示例外原文、本機路徑或例外型別；
  錯誤碼與 correlation 照舊回給畫面。後端已知的錯誤照舊顯示原本的中文訊息。

## 作業、取消與關閉

長作業一次只允許一項會改動案件資料的操作。前端顯示 busy 狀態與取消入口；`operation.cancel` 只表示
已提出取消，最終結果仍看原 request。
檢視與預覽來源，以及各項匯入都能取消。逐檔檢視取消時停止剩下的檔案，保留已檢視的清單，不把取消當成讀檔失敗後繼續。
若串接作業的前一階段已完成，取消只停止後續步驟，畫面明說已完成的結果仍保留，不宣稱整串作業都已回滾。

案件清單保留 `project.json` 無法讀取或解析的案件，顯示下一步而不假裝資料庫種類為 SQLite。
使用者可以先檢查檔案是否被鎖住，或從備份復原；損壞時也可另建案件重新匯入，其他正常案件仍可使用。
開始填寫建案表單後，背景資料庫設定結果只更新 SQL Server 選項是否可用及其提示，不重建表單，不替使用者切換已選的資料庫。
未知狀態不等於未設定；確認未設定時停用選項並說明改選 SQLite 或 DuckDB，之後確認已設定時重新啟用。晚到的案件清單回應仍由離開首頁的守衛忽略。

離開案件或關閉視窗時，要先停止新 request、處理在途作業並釋放案件鎖。畫面不能因為 Bridge 尚未
回應，就自行假設鎖已經釋放。
頂列按鈕稱為「退出」，不暗示未儲存草稿也會儲存；此次沒有新增自動儲存或額外確認步驟。
