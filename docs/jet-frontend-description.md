# JET 前端說明

更新日期：2026-09-09

一般操作提示說明查找條件、結果或下一步，不夾帶程式沿革與內部資料格式。
例如借現金範本說明「借方為現金，而整張傳票沒有貸方現金的分錄」，不附程式相容來源。
範本提示與新套用的動機使用同一份文字；已保存的動機保留使用者原有內容。

右側面板標題為「資料預覽」，標題、頁籤、選單、提示與表格統一使用 Noto Sans TC。
一般文字及表格為 12px，狀態標題為 13px；數字保留等寬數字與右對齊，寬表在面板內捲動。
資料名稱為「GL 原始資料」「GL 測試母體」「GL 未納入測試母體」「TB 原始資料」「TB 標準化資料」
與「科目配對」，頁籤、其他資料選單及載入提示使用相同名稱。
流程總覽的母體數字、日期、階段編號與圖表刻度也使用 Noto Sans TC，保留原有字級、粗細與數字對齊。

頂部案件摘要的標籤、中文、英文與數字統一使用 Noto Sans TC，數字使用等寬數字設定。
右上角顯示「操作人員：帳號」，由既有 system.whoAmI 提供目前 Windows 身分，不以案件建立時的操作人員取代。
預覽工具以範例帳號呈現，合成資料提醒只放在工具列。退出按鈕顯示「退出」，不承諾保存未保存的草稿。
當前步驟的「進行中」和未完成提醒集中在標題下方；建立案件收合時只顯示「案件基本資料已建立」，
詳細資料仍可展開查看。第五步以「保存情境」為主要按鈕，「查看符合的傳票」為次要操作，保存流程和規則不變。

頂列按鈕文字為「總覽」「資料夾」「切換案件」「退出」，完整用途保留在懸停說明。
工作區標題和附註、流程步驟的號碼、標題與狀態也統一使用 Noto Sans TC。
篩選結果先顯示「符合條件：N 筆分錄（M 張傳票）」，展開「結果說明」才顯示查核期間及參考分錄的解釋。
第五步未完成原因只在標題下方顯示，頁尾不重複列出，下一步是否可用仍依原有判定。

條件組的結合方式與比對範圍集中在組標頭下，範圍入口明示同一分錄或同一傳票，
不放在條件清單尾端。組框與設定區以中性色、位置和分隔線表示層級，保留編輯器的小圓角。
只有正在編輯的條件使用主要藍色高亮；新增目標由左側選單指出，整組不高亮。
錯誤條件保留紅色，外層畫面配色不變。檢視設計時須同時查看多組與跨組選取的畫面，避免局部調整產生多個競爭焦點。

左側固定為條件總覽，右側固定為組設定與條件編輯，不搬移或在組內嵌入整套選單。
寬度超過 900px 時保留左右排列；高度足夠時，左側總覽保持可見，長清單在面板內捲動。
較窄畫面保留上下排列。KCT 先呈現可用條件，停用項目放在「尚不可用」內，展開仍可查看完整名稱與原因。
右側資料預覽展開後，若第五步工作區剩餘寬度不足 660px，也使用上下排列，避免條件卡被擠窄。
多組時，左側以獨占一列的「新增條件到」下拉選擇唯一的加入目標；單組時不顯示。右側組標頭只顯示組號，
不另設單選鈕或目標標籤。編輯某組中的條件會同步左側下拉與 KCT 勾選。切換目標不重繪輸入欄，
不移動焦點或捲軸，也不令預覽過期。組內不設僅作跳轉的「加入條件」按鈕。
「新增條件組」位於右側「條件組合」標頭，建立新組並選取該組。左右排列時定位新組；
上下排列時定位條件總覽的加入選單，讓使用者直接選條件。新增組與單獨選組會清除舊條件高亮，加入後定位新條件。
非營業日 I 維持情境層級，不改為加入目前組。

每條條件先顯示名稱，再顯示具體設定。預篩選條件的名稱為「預篩選訊號」，下拉顯示「假日核准」等值；
其他分錄特徵沿用現有條件型別名稱。條件名稱只協助辨識，不參與 payload 或審計判定。
單邊分類和舊式條件也有標題。篩選方式與訊號下拉沿用共用焦點鍵，變更後仍可接續鍵盤操作。

桌面版的主要動作列在條件編輯區底部保持可見；窄版與矮視窗使用正常排列，避免遮住輸入欄。
開啟保存表單時，先收起預覽與保存入口，表單明示保存的是所有條件組。
取消編輯放在編輯情境標頭，保存表單開啟時也能使用。零結果不顯示沒有用途的傳票搜尋，
有結果或已輸入搜尋字詞時仍保留搜尋與清除功能。條件變更後以短句提醒更新預覽，不繼續顯示舊命中數。
查看完成後定位預覽結果。傳票分錄的狀態先顯示「命中分錄」或「參考分錄」，展開可看完整原因，
避免長說明把其他欄位推遠；內容直接沿用後端回傳，不由前端重新解釋命中條件。

JET 的前端是放在 WinForms WebView2 裡的 HTML、CSS 與 JavaScript。它負責讓使用者操作案件、查看摘要
與有界明細；審計規則、資料有效性與報告內容由後端決定。

## 畫面結構

進入案件後，主要畫面有四個區域：

1. 頂部案件摘要：顯示案件識別、客戶、查核期間與目前階段；操作人員顯示在右上方。
2. 左側流程目錄：列出六個步驟與已完成狀態。
3. 中央內容：只展開目前步驟，其他步驟顯示一行摘要。
4. 右側資料預覽：查看來源資料、測試母體與有界明細；狀態訊息在左下角展開。

流程總覽使用 modal 呈現既有 state 的摘要。它不是第二套導航，也不重新計算每個步驟是否完成。

## 案件選擇

啟動後先顯示本機案件。SQLite 與 DuckDB 可以在沒有 SQL Server 的情況下使用。只有使用者要求同步
線上案件時，才查詢 SQL Server registry；線上失聯不能清空已顯示的本機清單。

建立案件時選定 provider。案件名稱錯誤由後端用結構化 `error.field = "caseName"` 指回欄位，前端不
解析錯誤句子猜測焦點。

載入或刪除失敗時，picker 在原操作位置保留錯誤，並提供「複製錯誤」與「輸出支援日誌」。後者使用
同一次錯誤回應的 correlation id，把去識別紀錄直接寫到該案件目錄；不需要先成功載入案件，也不依賴
Release 中不會顯示的 DEV 面板。Debug 組建在同一處另有「輸出診斷日誌（DEV）」，把含 SQL 與參數的原始
紀錄連同該次 correlation 寫到同一個案件目錄；DEV 面板裡的「輸出日誌」要先載入案件才能用，載入本身
失敗時就靠這個按鈕。報告檔在 JET 之外被改寫或刪除不會讓載入失敗；那只會在第六步清單標示狀態。

## 六個步驟

### 1. 建立案件

收集案件名稱、代碼、公司顯示名稱、操作者與期間。建立成功後才進入工作流程。
查核期間決定要測試的分錄；期末財報準備日用於相關核准日風險條件，畫面在欄位旁說明兩者用途。

### 2. 匯入資料

GL 與 TB 可以由一個或多個檔案匯入。前端先讓使用者選檔，再呼叫 inspect／preview／import actions。
授權編製人員、科目配對、假日與補班日是支援資料，不是每個案件都必填。
加入來源仍先進入匯入清單，由使用者確認；重新匯入同一資料集的按鈕明示取代資料。成功後說明哪些
配對及計算結果需要更新，已保存情境設定和既有底稿會保留。

### 3. 欄位配對

前端顯示來源欄位、JET 目標欄位與值摘要，讓使用者確認 GL／TB mapping。自動建議只是草稿；只有
`mapping.commit.gl` 或 `mapping.commit.tb` 成功後，後端才建立標準資料。

核准日方式與來源欄位在同一區。指定來源欄時自動切換成「由來源欄提供」；選不提供或沿用總帳日期時
清除來源欄配對。兩種編輯畫面和自動建議共用相同的連動。「還原為已提交版本」一起還原欄位、金額模式
和所有 GL 設定，避免留下未還原的日期或分類設定。點選必填清單的欄位名稱，會在簡易清單定位對應控制項。

### 4. 資料驗證與測試

畫面先顯示有效母體、來源品質與驗證摘要，再讓使用者以分頁查看差異或問題明細。預篩選可在此執行，
但它只是風險訊號，不是進階篩選的必要前置。

驗證完成後產生兩份驗證報告，並建立尚不存在的科目配對範本。範本已有檔案時保留，已填分類不會被
重新驗證覆蓋。畫面分別說明報告和範本的處理結果；其中一項失敗仍保留驗證與其他已完成輸出，可在
對應區塊重試。手動按「重新產生空白範本（覆寫現有檔案）」才覆寫原檔。取消後不啟動後續輸出。

### 5. 進階條件篩選

使用者建立條件情境，先預覽，再保存。條件編輯器只產生後端接受的結構；不在 JavaScript 組 SQL 或
自行計算命中結果。預設用 `query.filterVoucherPage` 顯示傳票清單，展開時透過
`query.filterVoucherRowsPage` 取得該傳票查核期間內的完整分錄，每頁 50 筆。命中分錄、同傳票佐證與
參考分錄分開顯示，各列指出符合第幾組第幾條主要或佐證條件，傳票層條件另外說明；只有命中傳票，沒有
待判定。傳票清單表頭可點排序，上方有「依傳票號碼查看」。原有命中列查詢仍保留相容入口。

第五步分為「篩選與檢視」和「已保存情境與矩陣」。切換只改畫面，不清除草稿、值或預覽。一般桌面寬度下，
左側選條件，右側調整本次篩選並看結果；窄視窗改成上下排列。配色沿用 JET 既有暖米白和文字、狀態色。

左側可選「KCT條件」或「自訂篩選條件」。KCT 保留 A–J 完整名稱、選取狀態及停用原因；自訂先選欄位、科目
分類或分錄特徵，再按「加入條件」。加入後左側回到未選取，右側固定顯示所選欄位名稱；換欄位時移除再加。
兩者都加入目前選定的條件組，多組時用「新條件加入」選擇目標。「查看全部分錄」放在左側，開啟既有標準化資料預覽。
「常用範例」是另外可展開的入口，保留六筆既有範本：「借現金、貸非現金」「貸現金、借非現金」
「非營業日且排除指定日期」「期末最後 7 天的人工分錄」「空白摘要或空白核准人員」及「特定人員的大額分錄」。
套用會替換本次條件，並帶入可改的名稱與動機；前置條件不足時停用並說明原因。
範例不再使用星星符號，也不再充當自訂條件入口。

每條條件右上方都有「移除」，不再用家族小標與叉號辨識操作。一般草稿不另顯示「本次篩選」與未保存提示；
編輯已保存情境時仍顯示情境名稱。欄位、借貸別與人工或自動分錄的名稱固定，列內只調整其值。
科目分類的對象是借方科目、貸方科目或借貸組合，單邊
三選一（屬於、不屬於、整張傳票的這一側都不屬於）。借貸組合依序顯示查找方式、借方分類與貸方分類，
不用 A、B 對照。排除側明寫「整張傳票不得有這些借方分類」或貸方分類；下方一句說明結果列出哪一側分錄。
分類選項可換行，各區留出間距。
風險樣態的對象是預篩選訊號、尾數位數、編製人員張數、科目張數與 KCT 專屬條件。「判定說明」展開後寫明範本留白的科目
視為 Others、未在配對檔的科目不屬於任何分類，沒有科目配對時，相應科目選項停用並說原因。沒有排除區；
要排除就用條件的否定模式（不屬於、不在區間、不包含）。舊情境裡的文字清單、
日期區間等歷史型別仍能顯示與編輯，標成「舊式」，不再提供新建。

同組有兩條以上條件才顯示「AND（全部符合）」或「OR（任一符合）」。比對範圍另收在「跨分錄比對設定」，
選同一傳票後標示「同一傳票內比對」，並保留第一條為主要條件及組內固定 AND 的說明。
「新增條件組」直接放在條件下方；多組時顯示組號、加入目標與移除組操作。組與組之間用
「AND（所有組）」或「OR（任一組）」連接。多條條件的完整摘要收在「檢查完整條件」，仍保留實際括號與順序。

欄位條件先選「保留」或「排除」，再選篩選方式及值。日期方式包含指定日期、日期區間、每月幾日、日期先後、
空白日期及查核期末最後幾天；文字包含關鍵字、完整內容相同、開頭、結尾及空白內容。
金額分指定金額、金額區間、高於金額、低於金額及空白金額。
高於或低於金額可勾「含門檻金額」。這些選擇對應既有比較規則，不改變空白、正負號或邊界的判定。
主要方式已涵蓋原有運算子，不再重複顯示「其他比較方式」選單；開啟原有情境時不會默默轉換原規則。

指定日期以日曆多選，已選日期逐筆顯示且可移除；每月幾日填 1 到 31，例如 28,31。
「查核期末最後幾天」直接顯示天數和計算後的起迄日期，不再另外按套用；保存仍使用既有日期區間，重開以固定日期顯示。
日期清單貼上、金額基準與空白值處理依當前方式提供，沒有適用設定時不顯示展開入口。
總帳日期空白原本不在查核期間母體內，因此不提供把空白加回來的勾選框；其他日期欄位以
「沒有日期的分錄也列入結果」說明選項。勾選空白或含正負號時，收起設定仍顯示已啟用的選項。
日曆支援方向鍵、空白鍵、換月及 Escape，關閉後回到開啟按鈕。
日期錯誤或區間倒置時說明修正方式，保留輸入內容。值條件預設不列入空白。

條件列採相同的標題與控制項間距，借貸別及人工或自動分錄也把名稱放在控制項上方。
條件以「選取中」和原有色系邊線標示目前調整的區塊，不會因時間經過或焦點移開而消失。
新增自訂條件時自動選取新列；滑鼠點選或鍵盤移入其他條件時移轉選取，始終只標示一列。
新增時必要的捲動與編輯焦點保留；選取狀態不改條件順序、查詢結果，也不寫入案件或底稿。
選取外框只標示整條條件，內部控制項不顯示焦點外框；鍵盤定位採低調底線，真正的錯誤提示仍保留。
日期與金額區間的起訖欄位成對排列；空間不足時整組換行，更窄時才改成上下排列。
文字清單從單行高度開始，與旁邊的選單垂直置中；增加內容時自動增高，最高 160 像素後在欄位內捲動。

條件變更後標示預覽過期，使用者按預覽才重查。預覽或保存時後端指出某條規則有問題，那一列標紅、下方一行
寫原因並捲到第一個有問題的規則。已保存情境可編輯、更新、另存副本及取消編輯；成功更新前保留原版，
失敗不留下部分修改。更新不占新名額，副本受十個情境上限限制。舊情境保留原有結合順序與空白規則，開啟時
說明既有設定。未保存草稿不會留到下次開啟。
初始畫面先顯示「查看符合的傳票」，名稱與動機在按「保存情境」後才出現。「繼續調整條件」關閉保存區，
保留內容；保存成功後移到已保存清單。預覽不要求名稱或動機，保存自訂情境時才檢查，KCT 沿用原有例外。
自訂情境首次開啟保存區時，依所選條件帶入名稱與動機草稿；名稱最多 64 字，動機最多 180 字。
條件較多時，名稱列前兩項及總數，動機過長則摘要列出篩選對象；完整判斷仍以條件說明為準。
未手改的草稿隨條件更新，已手改或原有 KCT、範本及保存情境的非空文字保留；清空欄位後可重新帶入。
建議名稱遇到現有同名情境時附上數字。文字由本機既有條件說明組成，不新增網路服務或推測審計結論。
新情境保留 KCT 卡片來源，重開後
還原勾選和預設群組；取消卡片只移除該來源條件。舊情境缺少來源時顯示說明，保留原條件與 KCT 來源，
不憑名稱猜字母，仍可直接編輯。條件說明與錯誤留在對應欄位旁正常換行。
保存區的欄位與按鈕保留間距；命中傳票表的查看內容欄固定在右側，寬表仍在自己的容器內捲動。

已保存清單以「查看結果」為主要操作，編輯、另存副本與移除收在「操作」選單內；展開不推高整列，Escape 可關閉並回到選單。
已保存條件與編輯時共用完整說明，直接用「且」或「或」連接；只有表示實際分組時才加括號。
新建欄位條件在畫面與新產生的底稿都將區間寫為「介於」，金額基準直接寫在欄位名稱後，不再附「含兩端」或括號旁註。
區間仍包含起訖值，空白處理、借貸語意與條件結合順序不變；既有已匯出檔案不會被改寫。
高風險條件矩陣可切換「命中摘要」、
「傳票交叉表」和「分錄明細」，只顯示及載入選中的表。C1 等欄位同時顯示情境名稱，原有位置對照、排序、搜尋
與分頁查詢保留。條件篩選報告的產生操作也位於「已保存情境與矩陣」，上游資料過期提示會指向這個位置。
離開已保存工作區後，重繪條件區不會載入隱藏矩陣。兩個矩陣明細表使用既有允許併行的唯讀查詢，
產生報告時重建畫面也能載入資料。取消或確認移除後，焦點回到最新清單中的可見查看按鈕。

### 6. 匯出底稿

使用者選擇報告並啟動匯出。進度事件只顯示正在準備、寫入或發布哪一部分；只有 action 成功回應才
顯示完成。報告清單每筆顯示檔名、時間與大小；檔案在 JET 之外被改過或已不存在時，多一個狀態標示
（「已在 JET 之外修改」、「檔案不存在，重新匯出即可」），只提醒不阻擋。Working Paper 每次匯出新增
一個版本檔；第六步的「Working Paper 版本紀錄」列出全部版本，最新在上，每頁最多 50 份。較早資料或
條件產生的底稿標示「先前資料或條件的版本」；這些紀錄不影響目前流程是否完成。按「在資料夾中顯示」
會在檔案總管選取該檔，讓使用者自行開啟；已刪除的版本保留提醒並停用這個按鈕。重新匯出後立即保留
新舊兩筆，不必重新開案。科目配對範本由第四步的卡片產生，不在這份清單裡。

匯出前列出採用的情境及保存時間。上游資料變更後，提示說明先前的條件篩選報告已不能用，並指路回
「進階條件篩選」按「重新產生條件篩選報告」再回來匯出；匯出按鈕停用時旁邊是同一句話。新增篩選條件的
完整說明一併寫入底稿，未保存草稿不會自動納入。

清單即將超過 4,096 筆時，JET 才整理已確認檔案不存在的底稿紀錄；現存或無法確認的檔案紀錄會保留，
不刪除任何實體底稿。發布前再次確認檔案狀態，仍超限就提示自行整理舊底稿後重試。匯出成功後立即
同步整理後的完整清單。

### 各步明細表的排序與搜尋

完整性差異、借貸不平、空值紀錄、來源品質、抽樣樣本、預篩選命中、篩選命中、傳票矩陣、分錄明細與命中
傳票清單的表頭可點排序，點一下升冪、再點一下降冪，箭頭標示目前方向；表上方有「依傳票號碼查看」輸入框
（科目層的表是「依科目編號查看」），送出後只留含該文字的列，按「清除」還原。換排序或搜尋時清掉列從
第一頁重載，「載入更多」接續同一排序；排序與搜尋都在資料庫端，空值排最後。空值紀錄的「傳票號／科目」
兩鈕共用一張表，維持只接續載入，不提供排序與搜尋。2026-09-07 的分清單研究見現行計畫，尚未改動介面。

- `wwwroot/js/state.js` 保存目前畫面、案件 metadata、摘要與 request id，不保存完整 GL／TB。
- 下一步是否可用，以後端結果與 `ui-core.js` 的單一 gate 呈現為準。
- 切換步驟可以保存位置，但不能把「看過某頁」誤寫成「業務條件已完成」。
- 上游資料、mapping 或規則版本改變後，前端要顯示 stale，不沿用舊結果。
- Background response 必須確認仍屬同一案件與同一 request，不能覆寫後來載入的 state。
- 通知慣例（2026-09-01 收斂，整個前端唯一）：凡是會改變任何衍生畫面輸出的 store 寫入一律
  bump（`contentVersion` 進版、面板重建）；「只 notify」僅限「唯一視覺反映就是使用者正在編輯的
  那個控制項本身」的連續文字輸入，且必須在 blur 後延遲一次 bump 收斂。select／radio／checkbox
  是離散提交，永遠直接 bump。重建後的輸入焦點與捲動由 `app.js` 的 `renderContent` 依焦點識別
  屬性與 `data-preserve-scroll` 標記統一還原，步驟模組不得各自發明保留機制。已文件化的唯一
  例外是 filter-step 的規則值編輯（連續輸入且重建成本高，以就地抽換 read-back 與預覽面板收斂）。
  守衛測試：`JET.Tests.Architecture.StoreNotificationConventionFrontendTests`。

欄位配對的必填鐵軌與「確認配對」按鈕都由同一份 draft 推導。下拉選擇會立即 bump；中央內容重建後，
只依每個控制項明示且唯一的 `data-focus-key` 還原焦點，並還原 `data-preserve-scroll` 容器。這避免右側
仍顯示「待指派」、按鈕維持停用，或重繪把焦點送回錯誤控制項。

## 診斷日誌

- 「輸出支援日誌」是 Release 可用的去識別紀錄，案件尚未成功載入時也能從 picker 使用。
- Debug 的「DEV — 診斷日誌匯出」保留較完整的原始紀錄；面板版要先開啟案件，picker 錯誤回饋上的
  「輸出診斷日誌（DEV）」則不用，並帶該次失敗的 correlation。畫面明示內容可能含案件資料。
- 兩種輸出都由後端直接寫入目前案件目錄。前端不接受任意路徑，也不自行組合或過濾 NDJSON。

## 作業、取消與關閉

長作業一次只允許一項會改動案件資料的操作。前端顯示 busy 狀態與取消入口；`operation.cancel` 只表示
已提出取消，最終結果仍看原 request。

離開案件或關閉視窗時，要先停止新 request、處理在途作業並釋放案件鎖。畫面不能因為 Bridge 尚未
回應，就自行假設鎖已經釋放。
頂列按鈕稱為「退出」，不暗示未保存草稿也會保存；此次沒有新增自動保存或額外確認步驟。
