# JET 前端說明

更新日期：2026-10-27

一般操作提示說明查找條件、結果或下一步，不夾帶程式沿革與內部資料格式。
例如借現金範本說明「借方為現金，而整張傳票沒有貸方現金的分錄」，不附程式相容來源。
範本提示與新套用的動機使用同一份文字；已儲存的動機保留使用者原有內容。

六步驟共同完成同一案件的分錄測試：設定查核範圍、匯入來源、確認欄位、檢查 GL 及分類、選取待查核分錄，
最後產生底稿。同一資料與動作跨頁沿用名稱；提示只回答操作當下的問題，不要求使用者理解程式狀態或遷移背景。
按鈕須能從鄰近標題辨認對象，存在多種檔案時直接寫出檔案用途。必要的欄位說明直接可見；細節展開只用於選用內容。
狀態以文字說明，不使用看似單選鈕的空心圈。相依欄位、操作及結果就近排列，間距與按鈕尺寸使用共用樣式。

第五步的自訂條件可加入比對同一筆分錄的「子條件組」或判斷整張傳票的「整張傳票條件」。
子條件組內可再加入子條件組，各條子條件各自選「且」「或」。整張傳票條件可選至少一筆、全部符合或不存在符合；要限定借貸方向時，另加「借貸別」子條件。
畫面與報表都列出完整括號及條件範圍，並說明全部符合需要至少一筆分錄。
第四步科目配對以科目清單為主要操作。審計員搜尋科目並整批勾選，一次套用同一分類後儲存。
科目清單和 Excel 配對工作檔使用已確認欄位配對的科目，不要求先有資料驗證結果。
每頁最多 200 個科目，可全選本頁，支援編號與名稱搜尋。勾選欄可用滑鼠拖曳連選，Shift 點選則選取區間。
從已勾選的科目開始拖曳會取消該區間；拖回時縮小區間，原本區間外的選擇保留。
拖到清單邊緣會捲動本頁，不跨頁載入。Esc 或指標操作中斷會取消這次拖曳；換頁、搜尋及套用後重新建立 Shift 連選的起點。
單點與鍵盤勾選仍可使用。選取即時更新勾選、列底色與筆數，不重繪表格，也不套用或儲存分類。
科目名稱仍可反白複製；拖曳只從勾選欄開始。「本頁」文字與勾選框在同一列置中對齊。
使用者 2026-10-08 裁定「跨頁保留，一次儲存」：勾選與已套用的分類在換頁、搜尋後都保留，換頁不需要先儲存。
筆數寫出已選幾個科目，以及其中幾個在其他頁，可以按「全部取消」取消勾選；筆數、取消按鈕與分類工具垂直對齊。
套用分類用下拉選單，下層分類以縮排和「└」標出所屬的上層。選定分類後仍要按「套用至已選科目」，最後再儲存。
2026-10-14 的元件統一曾把這裡改成可展開、收合的分類樹，使用者 2026-10-15 要求改回下拉選單，第五步的分類樹不受影響。
第四步科目搜尋、第五步「從科目樹選取」與表格搜尋共用搜尋框，按「搜尋」或 Enter 才送出查詢。
「清除」清空搜尋字詞並重新查詢。第四步每頁最多 200 個科目，第五步科目樹每次讀取最多 100 個科目。
第五步的分類樹共用縮排與展開收合外觀，可將分類中的科目編號加入條件清單；第四步只選一個分類，不使用分類樹。
左下角以左箭頭、目前頁數與總頁數、右箭頭切換頁面；第一頁停用左箭頭，最後一頁停用右箭頭。
不因勾選或尚未儲存而停用翻頁。「套用至已選科目」套用到所有頁的勾選，
「本頁」只切換這一頁的勾選。按「儲存科目分類」一次儲存所有頁有改動的科目，超過 500 個時分批送出；
某一批失敗時，已存的部分保留，其餘仍待儲存，可以再按一次儲存。其他科目與 Excel 已匯入的分類保留。
還有沒儲存的分類時，離開第四步、執行預篩選、回首頁或結束前，會先詢問「儲存並繼續」、不儲存也繼續，或「留在這裡」。
對話框同時寫出儲存會清除什麼：預篩選結果，以及第五步的篩選情境與還沒存的條件。會清除篩選情境時，焦點預設停在「留在這裡」，
按 Enter 不會直接儲存。同一時間只開一個對話框。儲存後，原本要去的步驟若因情境被清除而不能進入，改到最遠還能進入的一步。
預篩選與後續步驟只使用已儲存的分類；不儲存而離開第四步時，改動仍留在畫面上，回來可以再儲存，回首頁或結束則不保留。
GL 或 TB 重新匯入、附加來源或重新確認欄位配對後，已存科目配對和未儲存草稿都清除，分類定義保留。回到第四步時依新資料重新配對，不沿用舊科目與勾選。
「在 JET 配對」與「用 Excel 配對」只顯示所選方式，支援方向鍵移動分頁焦點、Enter 或空白鍵選取。
分類設定是獨立子畫面，返回時保留原方式及未儲存草稿。Excel 依取得、填寫與匯入排列，匯入覆蓋和重建清空的提醒保留。
「分類設定」可新增或調整名稱，日常操作不必處理分類用途與階層。「進階設定」才展開分類用途與上層分類。
第五步分類清單仍區分分類本身、包含下層與相同分類用途；分類用途獨立設定，不由父分類繼承。
含巢狀條件的編輯器讓底部操作列隨頁面排列，避免固定操作列遮住子條件。

右側面板標題為「資料預覽」，標題、頁籤、選單、提示與表格的中文用 Noto Sans TC，英文與數字用 Instrument Sans。
一般文字及表格為 12px，狀態標題為 13px；數字保留等寬數字與右對齊，寬表在面板內捲動。
資料名稱為「PBC-GL」「GL」「GL(未納入測試)」「PBC-TB」「TB」與「科目配對」，頁籤、其他資料選單及載入提示使用相同名稱。
這組名稱是使用者 2026-10-08 的裁定，取代先前的「GL 原始資料」「納入測試的分錄」「未納入測試的分錄」「TB 原始資料」
「已確認配對的試算表」。名稱的權威是 `DataPreviewDatasetLabels`，前端逐字鏡射。
「GL」與「GL(未納入測試)」列同一組欄位，依已確認的 GL 配對決定，欄名和欄位配對畫面相同，例如「傳票文件項次」「會計科目編號」「傳票摘要」。
最前面是傳票號碼、傳票文件項次、總帳日期、會計科目編號、會計科目名稱、傳票摘要、金額與借貸別，接著是已配對的選填欄位與攸關資料元素欄位；
未配對的欄位不列，借方與貸方金額也不分欄。這是使用者 2026-10-22 的裁定。人工或自動分錄有配對時兩頁都列，顯示「人工」「自動」，沒有判定時顯示「—」；
PBC-GL 與第五步篩選預覽不加這一欄。只有金額欄靠右對齊，傳票文件項次、會計科目編號這類文字欄照樣靠左。
資料預覽的金額固定顯示四位小數，例如 1,234.5000；GL、GL(未納入測試) 與 TB 的金額欄，以及 GL 下方統計列的金額都是如此。
PBC-GL 與 PBC-TB 照匯入的來源文字顯示。這也是使用者 2026-10-22 的裁定，其他畫面仍是兩位小數。
「GL(未納入測試)」最後一欄是未納入原因，寫「總帳日期空白」「早於查核期間」「晚於查核期間」或「過帳狀態不符」，表格下方列出這四種原因各自的筆數。
使用者 2026-10-21 裁定把原本合稱的「日期不符」分成前三種。這份資料的頁籤下方另有「未納入原因」下拉選單，預設「全部」；
選了一種原因後只列這種原因的分錄，總筆數與換頁也只算它，下方四個筆數仍是全部未納入測試的分錄。
換到別的資料表時這一列收起，回來時從「全部」開始。下拉選單是 28px 的緊湊欄位，和表格裡的下拉選單相同。
表格下方的筆數與概況以「｜」分項，欄寬不夠時整項移到下一行，名稱、金額與日期不從中間斷開。
流程總覽的數字、日期與圖表刻度也使用 Instrument Sans。第四步統計和總覽統計共用字級、字重與行高；表格與圖表刻度維持各自閱讀層級。

頂部案件摘要的中文用 Noto Sans TC，英文與數字用 Instrument Sans，數字使用等寬數字設定。
摘要列只保留案件名稱、客戶名稱與查核期間，是這一頁的標題：排成一行，標籤在值的左邊，項目之間以細線分隔，案件名稱用深墨色。
視窗寬度至少 1536px 時，摘要和名稱、操作按鈕在頂部標題列的同一列，從中欄的左緣開始，三組的中線在同一條水平線上；
名稱特別長時，案件名稱與客戶名稱以刪節號縮短，查核期間完整顯示。比較窄的視窗把摘要放在標題列的第二列，和名稱同一條左緣；
一行放不下時換行，每一行開頭的項目都對齊同一條左緣，不帶分隔線。
目前階段由左側目前步驟表示，不在頂部重複。
左側的進度仍表示已完成步驟數，不因切換目前步驟而增加。
頂部顯示「目前帳號：帳號」，由既有 `system.whoAmI` 提供目前 Windows 身分；它在名稱「JE Tool」的下一行，兩行對齊同一條左緣，
不再加表示連線的色點，連線失敗時直接寫「應用程式連線失敗」，和訊息面板的說法相同。
建立案件也使用同一個 Windows 短帳號，表單不提供另一個可修改的操作人員欄位。
案件已建立後，第一步摘要與總覽將原先保存的身分標為「建案者」，不與頂部的目前帳號混用。
預覽工具以範例帳號呈現，合成資料提醒只放在工具列。退出按鈕顯示「退出」，不承諾儲存未儲存的草稿。
當前步驟的「進行中」和未完成提醒接在標題同一行；建立案件收合時只顯示「案件基本資料已建立」，
詳細資料仍可展開查看。第五步以「儲存情境」為主要按鈕，「查看符合的傳票」為次要操作，儲存流程和規則不變。

收合步驟排成一行，名稱後面接資料摘要，展開箭頭在最右；例如「匯入資料」後面顯示總帳明細與試算表筆數。
第六步還沒匯出目前版本的工作底稿時寫「匯出工作底稿」，已匯出時寫「已匯出工作底稿」與匯出時間，
和左側進度、第六步的完成用同一個判斷。
第四、五、六步及總覽使用「GL」稱呼納入測試的分錄，以查核期間與過帳狀態說明哪些分錄列入 GL。
驗證與預篩選報告使用相同的操作列；已有當次報告時提供「開啟資料夾」，尚未產生時提供產生按鈕。
資料夾入口依已登錄報告的識別值呼叫既有主程式功能，不由前端猜測檔案位置。
報告是測試做完之後拿到的檔案，不是另一個測試項目（使用者 2026-10-11 指出「驗證報告與抽樣清單」看起來和測試程序同一層，會讓人誤解）。
所以第四步的「驗證報告與抽樣清單」與「預篩選報告」放在各自工作面底部一塊低一階的區域，橫跨整個工作面；
第五步的「條件篩選報告」與第六步的「工作底稿版本紀錄」直接放在畫布上，是一塊比畫布明顯低一階的托盤。
這塊托盤原本和畫布只差一點點，使用者 2026-10-13 選擇加深。每份檔案是一張文件卡，
左邊有灰色文件圖示，名稱、檔名與建立時間排在中間；預篩選報告也有自己的標題。
產生或重新產生報告的按鈕都是白底細框的次要按鈕，放在報告區標題右邊；第五步的「產生條件篩選報告」因此不再是實心藍色，
這一步的實心主要按鈕只留給「下一步：匯出底稿」。

欄位配對的簡易清單與對照表格都只顯示目前金額模式適用的欄位。多個用途共用來源欄時，表格列出全部用途，
並可切到簡易清單各自調整；切換介面不改已選配對。欄位鍵、標籤、必填模式與字面值欄位均以領域目錄為依據。
簡易清單的「傳票核准日」在該列使用單一下拉，選項是「—」「與總帳日期相同」，以及各個來源欄；「—」表示未配對。
對照表格只從表頭指派核准日來源，不再在表格下方重複選欄。未指派核准日來源時，可勾選「核准日與總帳日期相同」。
切換兩種介面保留同一份草稿；從表頭指定來源欄後，核准日改由該欄提供。同一來源欄已被多個欄位使用時，表頭保留其對應名稱，可回簡易清單調整。
這是使用者 2026-10-09 第 6 則註解的調整，送出的 `approvalDateMode` 三個值與後端規則不變。
2026-10-08 後續註解移除兩種日期的用途說明及核准日正常狀態的常駐文字；必填、衝突與相關測試無法執行時仍使用既有提示。
匯入步驟的四個展開入口與已儲存情境的選單均稱「操作」，並提供含對象名稱的無障礙標籤。
展開後的「開始匯入」「編輯」「移除」仍使用明確動詞，不把所有按鈕改成同一名稱。

頂部、瀏覽器與桌面視窗標題使用 `JE Tool`。頂部的名稱是字標：JE 放在石板藍的圓角方形裡，Tool 接在後面，JE 就是 Journal Entry。
使用者 2026-10-11 兩次認為圖形標誌看不出意思，勾記號像勾選框，一頁分錄加光帶又像一般的清單圖示，所以改成字標，不再用圖形。
字標只出現在頂部這一次。
側欄標題為「流程」；每個步驟前有一個石板藍的圖示，還不能開始的步驟圖示是灰色。
已完成的步驟在右側打勾，可開始與未開始的步驟不另加符號，靠字色區分；目前步驟是一片淡藍的按鍵，藍字加左側短藍條。
換步驟時這一片照原樣、同樣大小平移到新的步驟，不浮起也不拉長（使用者 2026-10-12 認為放大縮小過於醒目）；
新的步驟名稱等這一片快到時才變粗、變藍。
左側目錄與中欄的步驟列都在按下滑鼠時就換步驟，和 macOS 側邊欄一樣，放開時不再換一次；鍵盤的 Enter 與空白鍵照舊。
使用者 2026-10-15 反映按下後要頓一下才開始移動，原因是原本要等放開才換步驟。觸控與觸控筆按下時可能是要捲動，照舊在放開時換。
按下時正在編輯的欄位先失焦，先存好它的值再重建中欄；換步驟開出的確認對話框會保有焦點。
換步驟時中欄先停在原本的捲動位置，再和原本那一步收起來用同一條彈簧捲回頂部，不再第一格就跳到頂部或瞬間捲到新步驟的標題。
頂列按鈕文字為「總覽」「開啟案件資料夾」「回首頁」「退出」，高度、字級與內距一致，後三個前面有圖示；
四個按鈕收在標題列裡同一個淡白的框裡，表示它們是一組；按鈕本身平時沒有底與框。
「回首頁」沿用原本離開案件並返回案件清單的行為。
整個介面的中文用 Noto Sans TC，英文字母與數字用 Instrument Sans；不另用等寬或襯線字體。
工作區不重複顯示 WORKPAPER、案件名稱與期間，中央流程列與流程總覽的六個階段卡都不顯示 01、02 等編號；頂部案件摘要及左側流程目錄保留。

## 畫面結構

進入案件後，主要畫面有四個區域：

1. 頂部標題列：一整片橫跨視窗的淺色玻璃；左邊是名稱與目前帳號，案件摘要是這一頁的標題，
   右邊是操作組，目前步驟顯示在左側流程。視窗寬度至少 1536px 時標題列只有一列，案件摘要從中欄的左緣開始；
   比較窄時分成兩列，案件摘要在第二列。
2. 左側流程目錄：貼齊視窗左緣、比畫布低一階的紙，列出六個步驟、步驟圖示與已完成狀態。
   下方的「進度」計算六個步驟中已完成的數量。流程目錄、中欄與右側資料預覽都從視窗頂端開始，上緣藏在標題列下面。
3. 中央內容：左側一條流程軸線串起六個步驟，只展開目前步驟，其他步驟各排成一行摘要。
4. 右側資料預覽：貼齊視窗右緣，以細線和中欄分開，查看 PBC-GL、GL 等資料的有界明細；狀態訊息在左下角展開。

左下角的「訊息」那一列是唯一的開關，固定在流程目錄的底部，右邊的細箭頭收合時朝上、展開時朝下。

視窗矮、流程目錄放不下時，訊息區黏在目錄底部，展開後開關仍在原位、兩個操作仍看得到；流程步驟從它後面捲過去，

### 分類樹與科目選取

分類設定、套用分類的下拉及第五步的分類樹都顯示上下層。分類設定可一次建立上層與下層；新增下層先帶上層用途，手動改過的用途保留。
使用者 2026-10-11 認為分類設定看不出分類之間的上下層，甚至像單純的排版問題，所以分類設定裡每一層的名稱欄往內縮 24px，
下層分類用一條深灰的細線接到上層，同一個上層底下的分類共用一條直線，最後一個轉角接到名稱。
JET 內建的分類在右邊標出「內建」，說明它可以改名但沒有「移除分類」；名稱輸入框的右緣一律對齊，右邊固定一欄放「移除分類」或「內建」，
打開「進階設定」時，分類用途與上層分類在每一列也對齊同一條欄線。
移除上層前列出受影響的直接下層，確認後接到原分類的上一層，儲存前仍可取消。新增分類後焦點移到名稱欄，進階設定切換保留焦點。
第五步的分類樹保留勾選與收合，不提供分類搜尋。新卡與常用查核條件新加入的分類條件預設包含下層，舊情境沒有選取方式時仍按原本分類用途判斷。
條件說明寫出方式與實際納入分類；草稿引用已刪除的分類時提醒重新選擇，不顯示內部 ID。
科目編號的完整值清單可從分類樹查詢本案科目，搜尋及換頁只取有界資料；勾選仍寫進原有科目編號清單，保留前置零。
勾整個分類時不把第一頁當成全部；搜尋框有字時勾分類，也是選整個分類，搜尋框一併清空，清單改列整個分類，
這是使用者 2026-10-19 的裁定，原本只選到符合搜尋字的科目。若超過既有 100 個值上限，原清單不變，提示縮小範圍或改用科目分類條件；查詢失敗可重試，晚到回應不改其他案件或已移除的條件。
## 案件選擇

啟動後先顯示本機案件。SQLite 與 DuckDB 可以在沒有 SQL Server 的情況下使用。只有使用者要求同步
線上案件時，才查詢 SQL Server registry；線上失聯不能清空已顯示的本機清單。開啟案件時，前端把清單列上的
資料庫種類一起交給 `project.load`。本機找不到案件資料夾時，只有 SQL Server 案件會再查線上登錄，
SQLite 與 DuckDB 案件直接顯示找不到案件。開案後只有 SQL Server 案件定時送出心跳。

建立案件時選定 provider。案件名稱錯誤由後端用結構化 `error.field = "caseName"` 指回欄位，前端不
解析錯誤句子猜測焦點。

案件清單的每個按鈕放在它作用的內容旁邊，不在清單下方排成一列；使用者 2026-10-20 指出原本底部那排按鈕看不出用途。
「新增案件」放在標題右側，是淡藍底的新增按鈕，建立哪一種資料庫的案件都從這裡開始。
「同步線上案件」放在線上資料庫的區標題右側，「重新整理本機」放在本地資料庫的區標題右側，兩個都是低調按鈕。

開啟或刪除案件失敗時，picker 在清單上方的錯誤框寫出發生什麼事與能做什麼，錯誤框裡沒有按鈕
（使用者 2026-10-13 選「從錯誤框拿掉，改成一般工具」）。案件清單的「輸出支援日誌」只給開發人員用，
和 DEV 面板一樣只在 Debug 組建出現，Release 看不到（使用者 2026-10-20 選「只藏案件清單的」）；
開案後訊息面板的「輸出支援日誌」在 Release 照舊。Debug 組建的這顆按鈕放在案件卡片下方靠右的頁尾，
按下時 `support.log.export` 不帶 `projectId`，後端把記憶體裡全部去識別紀錄寫到 logs 資料夾，
完成後按鈕下方寫「支援日誌已輸出：路徑」，不需要先開啟案件。剛發生開案或刪除失敗時，頁尾另有「輸出診斷日誌（DEV）」，
把含 SQL 與參數的原始紀錄連同該次 correlation 寫到那個案件目錄；DEV 面板裡的「輸出日誌」要先開啟案件才能用，
開案本身失敗時就靠這個按鈕。報告檔在 JET 之外被改寫或刪除不會讓開案失敗；那只會在第六步清單標示狀態。

刪案確認先讀取 JET 紀錄中仍存在的報告與工作底稿份數，並明說整個案件資料夾及其他檔案一併刪除、無法復原。
讀取失敗時數量顯示未知，可重試，也仍可依原確認流程刪除；不把未知寫成零。SQL Server 案件另提醒這會影響所有共用者。

## 六個步驟

已有篩選情境時，更改前面步驟已設定的資料會清除後面步驟的設定（使用者 2026-10-07 裁定）。會清除的修改，是讓篩選結果過期的那些：
重新匯入或重新確認總帳與試算表配對、假日與補班日、每週非工作日、科目配對、授權名單、期末財報準備日與分類設定。
總帳與試算表的匯入或配對確認使用同一條規則，資料驗證、預篩選與篩選命中一起失效，全部已存情境清除。
清除後第五步回到預設狀態，訊息只寫一句請重新設定篩選情境，等級是需要注意；沒有情境或草稿可清時不新增訊息。
修改失敗時保留原情境。成功修改後，條件篩選報告與底稿照既有規則標成過期，已匯出的檔案不會改寫。
修改前不另加確認。已有篩選情境時，第二到四步顯示一句「更改已設定好的資料，會清除後面步驟的設定。」；
第一步只在打開「修改案件資料」後顯示同一句，案件摘要不顯示。不列出清除的細節。

### 1. 建立案件

案件名稱、查核起始日與查核截止日必填；案件編號、客戶名稱及期末財報準備日可以留空，標籤不另加「（選填）」。
資料儲存方式的下拉選單下方寫「建立案件後不能變更。」，標籤本身不夾限制說明。
操作人員由系統取得目前 Windows 短帳號，使用者不能在表單改成別人。表單上方的操作人員提示讀取
`system.whoAmI` 的結果；身分晚於表單出現時，只更新操作人員那一行，不重建表單，已輸入的內容、選取範圍與焦點都保留。客戶名稱留空時，案件清單及工作區
以案件名稱作為主標題，不會顯示成空白案件。
查核期間決定要測試的分錄；期末財報準備日用於相關核准日風險條件，畫面在欄位旁說明兩者用途。
案件名稱只含空白或全形空白時要求填寫，查核起始日比截止日晚時就地指出日期問題，不送出建立請求。
期末財報準備日早於查核起始日，或晚於查核截止日超過一年時，欄位旁提醒確認年份，但仍可建立或儲存。
建案後可在同一頁按「修改案件資料」，只編輯客戶名稱、案件編號與期末財報準備日；案件名稱、查核期間、建案者與資料庫種類仍只讀。
取消不改原資料，失敗保留輸入。成功後更新抬頭和摘要，未儲存的篩選草稿保留；需要重算的結果依後端回應更新。
畫面也說明既有匯出檔不會被改寫，之後匯出才採新資料。第五步缺財報準備日時指向這個入口，不顯示內部欄位名稱。
第一步另顯示驗證保存的同號多入帳日提醒，分開列出號碼數與涉及分錄筆數。同月不同日也包含在內，傳票比對鍵不變。
尚未驗證、舊摘要缺欄或結果過期時寫尚未確認；只有實際量測到零才顯示零。這是供審計員確認來源資料的提醒，不阻擋操作。
「資料儲存方式」的「SQL Server（共用實例）」只在啟動時的 `system.databaseInfo` 明確回報這台電腦沒有設定
線上資料庫時停用，選單下方寫「這台電腦沒有設定線上資料庫，請改選 SQLite 或 DuckDB。」。結果還沒回來時
維持可選，不因查詢慢而擋人；已設定但連不上時也維持可選，建立案件時照舊回報錯誤。

### 2. 匯入資料

四類資料的入口按鈕統一為「操作」，展開後仍使用各自原有操作。未匯入授權清單只顯示「未匯入」，
不以「解鎖」描述用途。頁首提示簡述支援格式及合併條件；收合摘要以「總帳明細 N 筆 / 試算表 M 筆」呈現。
清單未完成符號為橫線，實際狀態仍以「未匯入」等文字呈現。授權清單的說明只寫比對名單外編製人員的用途，
選檔後才要求人員識別欄與 GL 一致，不夾帶 R5 人員彙總的背景。
日曆資料的匯入列稱為「假日與補班日」，展開後可匯入清單或設定每週非工作日，不顯示資料庫用語「日期維度」。
這張卡片只有「上傳假日檔」、「上傳補班檔」與每週非工作日設定，另有一句說明：假日檔讀 `Date_of_Holiday` 欄，補班檔讀 `Date_of_MakeUpday` 欄，日期寫成 2026-12-31 的格式。
卡片不提供取得範本或開啟案件資料夾的按鈕。

GL 與 TB 支援 `.xlsx`、`.xlsm`、`.xls`、`.csv`、`.txt`、`.mdb` 與 `.accdb`。GL 可合併欄位相同的來源；TB 提示先整理好本次要比對的資料，不暗示能把期初、期末兩份檔案自動配成餘額。`.xlsm` 由 JET 直接唯讀
活頁簿內容，不啟動 Excel 或執行巨集。前端先讓使用者選檔，再要求後端檢視、預覽及匯入。
右側只顯示有界的少量預覽；完整資料直接寫進案件資料庫，不會整批放進 WebView2。
Access 使用現有 Office ACE 16 讀取一般資料表，沿用來源預覽及匯入清單；不執行儲存查詢或巨集，.xlsb 不支援。
授權編製人員、科目配對、假日與補班日是支援資料，不是每個案件都必填。
授權清單匯入須明確選來源欄位，可查看原始預覽及有效識別值。匯入與重開案件後都顯示原始資料列數、略過空白與重複數，
並說明標頭與完全空白列不計入；舊名單沒有保存統計時照實提示。原檔上方有標題列時，提示先在 Excel 刪除標題列再匯入。
有效名單另顯示出現在 GL 傳票建立人員的人數，一位都對不上時只提醒確認所選的清單欄位是人員代號或姓名，不擋後續操作；尚未確認 GL 建立人員
配對時提示先確認，確認後會更新比對。所選識別欄完全沒有有效值時，要求改選欄位或換檔重試，保留原名單。
取消或失敗保留原清單；移除會清除該清單和相依結果，保留 GL、TB 與驗證結果，預篩選需重新執行；已儲存的篩選情境依下方規則清除。
「加入」先進入匯入清單，由使用者確認；「更換」用來重新匯入同一資料集。成功後說明哪些
配對及計算結果需要更新；已匯出的底稿檔案不會改寫。
追加後若後端發現檔名、工作表與實際列數都和既有來源相同，顯示可能重複的提醒，本次匯入仍成功；
這和下方「尚未送出的清單不重複加入」是兩件事，不會刪除已匯入資料。
一次選多個檔案時逐檔檢視，某一檔讀不出來不會中斷其餘檔案：那一列留在清單上，寫出原因，勾選框停用，
不能被送出；文字檔可以在同一列改選編碼或分隔符立刻重試，其他格式按「重新檢視」。再選一次已在清單上的
檔案或工作表不會重複加入，訊息區會說明哪些已在清單中。後端回的提醒（例如文字檔只讀到一欄，可能是報表格式）
顯示在該列下方，不擋匯入。尚未匯入的檔案「預覽」只顯示表頭與前 10 列，供確認檔案格式。

一般條件、舊式 typed 條件與加入子條件的選單共用這份文字。自訂分頁的欄位按鈕與範例就地選欄位時，按鈕只寫欄位名稱，
和其他欄位同名時才加「（來源欄名）」，完整文字放在滑鼠提示與報讀名稱。
兩個同名欄位也分得出來；條件仍以欄位識別碼儲存，讀回文字只寫欄位名稱。
攸關資料元素欄位可全選或全部取消。全選只勾選尚未被核心配對使用的來源欄，預設沿用來源欄名並先視為文字；
使用者仍可逐欄調整名稱與型別。後端最後檢查欄位是否存在、名稱與型別是否合法、欄位識別碼是否沿用正確，
以及來源欄有沒有重複。
勾選或改型別後保留清單捲動位置；全選和全部取消後，焦點留在仍可操作的控制項。編輯已確認的配對時先保留提示區高度，
第一次修改不會把下方清單推走。TB 與 GL 一樣，必填文字欄整欄空白時在成功確認後提醒使用者檢查配對。

各有「列出科目」。兩份清單依有效 GL 與 TB 的科目聯集比對，不把配對檔本身當成本案科目來源。
額外科目保留在配對檔，不會出現在篩選結果；未列科目不屬於任何分類，與留白視為 Others 不同。
畫面只顯示兩份清單的名稱、筆數與「列出科目」，不再附這兩句說明，這是使用者 2026-10-10 的選擇。
「用 Excel 配對」的「1. 取得配對檔」與「2. 匯入配對檔」各占一列，標題在左、說明在中、按鈕靠右；

重開案件時先顯示「尚未核對」，不自動重掃 GL；按「列出科目」才取得本次筆數。
Excel 檔有篩選或隱藏列仍會全部匯入。調換新舊範本的欄序時，先以確切欄名辨識，不因分類欄含 Name 而讀成科目名稱。

畫面先顯示 GL 分錄數、傳票數、借貸淨額與驗證摘要，再讓使用者以分頁查看差異或問題明細。
不重列查核期間，也不另外顯示納入與未納入的分錄摘要；明細可從右側資料預覽查看。
預篩選可在此執行，但它只是風險訊號，不是進階篩選的必要前置。
不在第四、五步頂端重複顯示結果過期的全頁黃框。驗證和預篩選各自執行、各自更新狀態，不能互相視為完成。
成功後清除對應旗標；資料變更只清相依結果，沒有執行過的程序不標成過期。案件載入最後採用後端旗標。
完整性差異保留為警示，已完成驗證即可繼續篩選與匯出；流程可繼續不等於完整性通過。

資料缺漏輔助檢視只有這兩類；空白摘要只在預篩選的卡片與第五步條件出現，這裡不再另列明細頁。

完整性測試先確認 JET 存下的分錄沒有少、也沒有重複，明細兩欄是「確認配對時算出」與「存下後重新計算」的筆數、借方合計及貸方合計，

只有第一項不符時，卡片狀態寫「存下的分錄數字不一致」；舊案件沒有這組數字時寫「存下的分錄無法核對」，不寫泛稱的「未通過」。
借貸不平測試逐張傳票檢查借方與貸方金額是否相等；判讀句照使用者原件寫「借貸不平代表傳票編號、金額欄位可能有誤」。
資料可靠性測試抽出分錄樣本，供審計員核對傳票附件及篩選欄位。說明寫明先確認 RDE 可靠性，再執行高風險篩選條件；這是審計作業順序，不是新增操作關卡。程式維持固定且可重現的抽樣，
不替審計員判定可靠性，也不增加額外門檻。ValidationReport 與 INF 報表內的「INF 抽樣測試」名稱保留，
畫面在報告清單標示用途並保留實際檔名，不在測試說明交代沿革；DPP 範本指引不改寫。

畫面金額維持兩位小數。完整性與借貸不平的非零差額若會顯示成 0.00，改寫「不足 0.01」並提示完整數字在驗證報告；負數差額仍標明是負值。
這只改畫面格式，不改差異判斷、報告或底稿精度。不存在或尚未執行的摘要顯示未知或原因，不把 null 當成 0。

畫面的「總帳日期空白」目前只列 PBC-GL 中總帳日期空白的來源列；這些列無法判斷是否在查核期間，因此列入
GL(未納入測試)。日期在查核期間外不列在這裡。既有 action 回應仍使用 `sourceQuality` 與 `nullPostDate`，畫面不顯示
內部分段名稱 Part A 或 Part B。

重新驗證覆蓋。畫面分別說明報告和範本的處理結果；其中一項失敗仍保留驗證與其他已完成輸出，可在
對應區塊重試。手動按「重建科目配對檔」才覆寫原檔，按鈕旁明示會清空已填分類。取消後不啟動後續輸出。

科目配對檔的完整狀態顯示在「用 Excel 配對」分頁。正在準備或準備失敗時，預設的「在 JET 配對」分頁也在
科目清單上方顯示一行狀態。失敗時寫出原因並提供重試按鈕，按下後切到「用 Excel 配對」分頁，焦點移到
「準備科目配對檔」。已建立或已保留時只在 Excel 分頁顯示，不打擾直接在 JET 配對的審計員。

上方統計列的「GL 分錄數」指符合查核期間與過帳狀態設定的分錄，直接複述後端計數，不在畫面自行相減。
各步報告清單先顯示「資料驗證報告」「資料可靠性抽樣清單」「預篩選報告」「條件篩選報告」或「工作底稿」，

報告列的按鈕垂直置中，窄版整顆換行，文字不被擠成直排。
重新開啟案件時，預篩選的定位說明使用目前版本的文字；原本保存的結果、不適用原因、計數、執行識別與日期都照原樣顯示，不回寫原紀錄。

預篩選規則無法執行時，狀態寫「無法執行」，滑鼠提示與展開的明細只顯示後端寫的原因；句子已寫出缺什麼、到哪裡補，
畫面不另接補救文字，完整性測試卡也一樣。原本前端會在後端原因後面再接一句，有的兩句互相矛盾，有的同一件事說兩次；
使用者 2026-10-22 裁定把這件事放進預篩選收斂計畫的階段四修正。週末與假日兩張卡各含過帳與核准兩側。只缺傳票核准日的配對時，

科目分類名稱輸入只更新本地草稿與就地提示，保留原輸入框及中文組字狀態；儲存、取消、新增與移除

### 5. 進階條件篩選

使用者建立條件情境，先預覽，再儲存。條件編輯器只產生後端接受的結構；不在 JavaScript 組 SQL 或

`query.filterVoucherRowsPage` 取得該傳票查核期間內的完整分錄，每頁最多 200 筆。符合條件的分錄、同傳票佐證與
參考分錄分開顯示，各列指出符合第幾組第幾條主要或佐證條件。因整張傳票條件列入的分錄標為「傳票條件成立」，不新增逐列的另一套命中判定；只有命中傳票，沒有
待判定。傳票清單表頭可點排序，上方有「依傳票號碼查看」。原有命中列查詢仍保留相容入口。

第五步分為「篩選與檢視」和「已儲存情境與矩陣」。切換只改畫面，不清除草稿、值或預覽。一般桌面寬度下，
左側選條件，右側調整本次篩選並看結果；窄視窗改成上下排列。配色依「畫面結構」的外觀說明。

左側可選「KCT 條件」「預篩選」或「自訂篩選條件」三個分頁。三格依名稱長短分配寬度、不換行，名稱不省略；
為了放得下完整名稱，視窗寬 901 到 1100px 而且左右排列時，左欄是 220px。KCT 卡片保留字母、完整名稱、選取狀態及停用原因；
自訂分頁不使用任何字母代號，兩邊不會混淆。

「預篩選」分頁是使用者 2026-10-16 要求的入口。審計員習慣直接套用預篩選條件，原本要先在常用查核條件加入

可再和其他條件組合。」，下面列出十二條規則：財報準備日起核准、摘要特定描述、未預期借貸組合、金額尾數連續 6 個 0、
週末過帳、週末核准、假日過帳、假日核准、空白摘要、非授權編製人員、編製分錄較少的人員（11 筆以下）、使用較少的科目（11 筆以下）。

每列只有名稱和「加入」，按下就把那一條帶入目前選定的條件組，卡片仍是「預篩選條件」，之後也能在下拉改選。
規則需要的資料不足時停用，原因寫在該列下方，和第四步這條規則無法執行時讀同一張表、寫同一組句子：例如需要的 GL 欄位尚未選擇來源欄、

按鈕停用、不能按，和其他停用按鈕一樣是灰底灰字。區塊下方用一句話列出這些欄位，例如
「「傳票核准日」「傳票建立人員」尚未選擇來源欄，請回第三步欄位配對補上」。傳票文件項次沒有來源時由系統自動編號，
傳票核准日選「與總帳日期相同」時由總帳日期帶入，兩者都算已配對。
按欄位按鈕就在目前作用中的組加入一條該欄位的條件，焦點移到新條件；比較方式仍在右側條件卡片上選。
第二區「常用查核條件」依審計目的分成五類，一次只展開一類，預設展開第一類，重繪後記得目前展開哪一類。
每項只有名稱和「加入」：
- 日期與時點：總帳日期在週末、總帳日期在國定假日、總帳日期在非營業日、傳票核准日在非營業日、財報準備日起核准的分錄、
  指定日期區間、查核期末最後幾天。
- 金額：大額分錄、金額尾數連續多個 0。
- 摘要：摘要含特定字詞、空白摘要。
- 科目與借貸：只看借方或貸方、科目屬於指定分類、借方與貸方分類組合、借方與貸方科目編號組合、未預期的借貸組合、
  較少使用的科目。
- 人員與分錄性質：人工分錄、編製分錄較少的人員。

原本的第六類「預篩選結果：沿用第四步預篩選規則」已由「預篩選」分頁取代（使用者 2026-10-16 要求）。

「金額尾數連續多個 0」帶入子條件組，內容是尾數 000000 與金額絕對值至少 1 元。
「摘要含特定字詞」帶入傳票摘要的「包含任一文字」，預設使用第四步的 25 個字詞，兩者都可直接修改。
「較少使用的科目」以科目編號計算分錄筆數，「編製分錄較少的人員」以傳票建立人員計算，預設都是小於或等於 11 筆，和第四步相同。
「指定日期區間」與「大額分錄」的起訖或門檻留空，加入後焦點直接移到要填的值；「查核期末最後幾天」由查核截止日往前帶入 7 天。
用到的欄位或資料不足時停用，並在該項下方寫原因，判斷和句子都和預篩選分頁相同：GL 欄位尚未選擇來源欄、沒有期末財報準備日、
科目配對沒有需要的分類，或尚未匯入授權編製人員清單。這是使用者 2026-10-22 的裁定，取代 2026-10-04 對未配對欄位「不修」的裁定；
沒有匯入假日清單時仍不停用，也不另加提示。
欄位按鈕與常用查核條件都加入目前選定的條件組，多組時用「新增條件到」選擇目標。
查看全部分錄改由右側資料預覽選「GL」，第五步頁首不另設捷徑按鈕。
每一組標頭直接提供「加入子條件組」與「加入整張傳票條件」；只有一組時也顯示。
子條件組原稱「條件括號」，把其中條件放在一起判斷，仍比對同一筆分錄，不改條件連接順序。

左側「條件總覽」標題旁有「從範例開始」，按下後在同側展開範例清單，清單上方寫
「套用後會替換目前的條件，已儲存的情境不受影響。」清單只列名稱，動機放在滑鼠提示。共有十個範例：
「借現金、貸非現金」「貸現金、借非現金」「非營業日且排除指定日期」「期末最後 7 天的人工分錄」「空白摘要或空白核准人員」
「特定人員的大額分錄」「週末人工分錄的特定摘要」「人工分錄的特定部門」「指定借貸科目組合的大額分錄」及「財報準備期間的人工假日分錄」。
後四個由 2024 篩選表的範例轉入，條件與示例值照原範例；原範例 4 和「金額尾數連續多個 0」重複，不另列。
套用會替換本次條件，名稱就是範例名稱，遇到已儲存的同名情境才附數字，並帶入可改的動機，同時收起範例清單；
範例用到的欄位或資料不足時停用並在下方寫原因，判斷和常用查核條件相同，同一個範例缺好幾個欄位時合成一句。
例如「空白摘要或空白核准人員」需要傳票核准人員已配對，「財報準備期間的人工假日分錄」需要期末財報準備日，
以及傳票核准日與人工/自動分錄已配對。查核截止日在建立案件時必填，範例不再因此停用。
「人工分錄的特定部門」需要一個文字型攸關資料元素欄位：沒有時停用並寫「需要先在欄位配對加入部門等文字欄位」；
只有一個時直接帶入；兩個以上時就地列出欄位按鈕讓審計員選，按「取消」或 Esc 不改動草稿。
正在編輯已存情境時套用範例，會成為另一個新情境，原情境不動（使用者 2026-10-07 裁定維持）。
兩個現金範本和新建的分類條件一樣，選取方式是「包含下層分類」，也就是 Cash 加上它底下的所有分類。
「非營業日且排除指定日期」把 KCT I 與排除日期放在同一個條件組，依序是第 1 條與第 2 條。
範例或草稿還有條件沒填值時，預覽前的「尚需補齊」會寫出第幾組第幾條與條件名稱，例如
「第 1 組第 2 條「總帳日期」請填 1 到 100 個值」；條件括號裡的子條件寫成「第 1 組第 2 條的第 1 項」。
值清單超過上限時，逐條寫出位置，請審計員拆成每條不超過 100 個值，再放進「任一符合」子條件組；否定清單則用「全部符合」。
套用範例後，焦點移到第一個要填的欄位，JET 不代填任何值。範例值可修改，不從目前資料猜科目、部門或審計理由。
儲存後重開以實際條件及情境名稱讀回。2024 篩選表的代號對應到新選單的位置，寫在 `jet-guide.md` 第 6 節。

多值輸入在框旁說明分隔方式。值清單是固定五行高的輸入框，放在保留或排除與比較方式的下方；貼上或拆成多行時高度不變，
內容較多時在框內捲動，審計員可自行往下拉高。清單下方顯示「已輸入 N 個值」，輸入時就地更新。
`fieldValue` 清單沿用 100 個值上限並顯示上限；KCT E、F、H 改用相同欄位條件，也採用這個上限及拆組提示。
N 與實際送出的清單相同，去掉空白與完全相同的重複值；尾數清單使用相同計數方式。摘要關鍵字、尾數、每月幾日、人員代號與科目編號可用換行、逗號、全形逗號、頓號或 Tab；
其他文字值清單一行一個，值內逗號保留。人員或科目編號本身含這些分隔字元時不能用來代表單一值，輸入前須確認代碼格式。
只收一個值的開頭、結尾等比較，貼入多行時提醒；金額和出現次數先檢查格式，絕對值基準的負數只提醒，不禁止送出。
指定日期接受 GL 相同的明確格式與案件的民國年開關，未知的寬鬆格式仍交後端判斷，不用瀏覽器猜日期。
整張傳票條件只選量詞，要限定方向時加入「借貸別」子條件。分類與欄位條件不附帶方向，也不從外層繼承方向。
子條件中的人員和科目編號預設完整值清單；科目分類只提供屬於與不屬於。
已儲存條件的選項暫時不能用時，保留目前值並說明原因，不默默顯示第一項。預篩選條件「未預期借貸組合」與常用查核條件「未預期的借貸組合」的停用條件和第四步相同。
條件卡片的欄位下拉也一樣：GL 還沒選擇來源欄的欄位不能選，選項後面寫「（尚未選擇來源欄，請回第三步欄位配對補上）」；
已經選了這種欄位的條件，下拉照樣顯示它，原因寫在卡片上。

每條條件右上方都有「移除」，不再用家族小標與叉號辨識操作。一般草稿不另顯示「本次篩選」與未儲存提示；
編輯已儲存情境時仍顯示情境名稱。欄位、借貸別與人工或自動分錄的名稱固定，列內只調整其值。
科目分類只選屬於或不屬於指定分類，不另選借方科目或貸方科目。要查整張傳票沒有某側分類，
另加「不存在符合」的整張傳票條件，子條件選借貸別與科目屬於指定分類。借貸組合依序顯示查找方式、借方分類與貸方分類，
不用 A、B 對照。排除側明寫「整張傳票不得有這些借方分類」或貸方分類；展開「查找說明」後，可查看結果列出哪一側分錄、KCT 補充說明及分類留白的處理。
分類選項可換行，各區留出間距。
風險樣態的對象是預篩選條件、科目與人員統計及 KCT 專屬條件。摘要關鍵字、空白摘要、特定人員與尾數都使用欄位條件。
舊情境裡的編製人員分錄筆數與科目分錄筆數已停用：讀回時照原樣顯示名稱，開案的待修正檢查、預覽與儲存都寫出停用原因與重建方式；
重建改用「科目與人員統計」條件，統計對象選傳票建立人員或會計科目編號，計算單位選分錄筆數，比較方式選小於或等於，填入原本的筆數。
科目分類說明保留「範本留白視為 Others」和「未在配對檔的科目不屬於任何分類」；借貸組合的說明收在「查找說明」，其他條件仍就地顯示。
沒有科目配對時，相應科目選項停用並說原因。沒有排除區；
要排除就用條件的否定模式（不屬於、不在區間、不包含）。舊情境裡的文字清單、
日期區間等歷史型別仍能顯示與編輯，標成「舊式」，不再提供新建。

10 月以前存下的舊情境若還帶排除區，編輯時在條件組下方顯示唯讀的「舊排除區」，列出原本每一條排除條件，
寫明排除的是符合的分錄或整張傳票，再寫後端那句原因「使用了已移除的「排除區域」，請改用條件中的「不屬於」或「不在區間」」，
標題旁有「移除」。沒有移除就儲存，後端照舊擋下，提示寫「儲存失敗：」加上這句原因，區塊留在原處。
按「移除」後區塊收起，焦點移到最後一個條件組，再儲存時就不帶排除區。JET 不自動把排除區轉成否定條件，
因為條件組之間可以選「OR（任一組）」，整個情境的排除沒有一定等價的寫法。原本編輯器看不到排除區，
修改這個情境後存回去就默默丟掉，這是使用者 2026-10-22 勾選要修的事項。

同組有兩條以上條件才顯示「AND（全部符合）」或「OR（任一符合）」，不再因比對範圍鎖住連接方式。
組內不顯示「主要條件」「設為主要條件」或「同一傳票」標記。要查其他分錄是否符合，使用整張傳票條件。
「新增條件組」在條件組合標題列。每組都有「清除」，只清該組內容，保留其他組與手寫的情境名稱、動機；空組時停用。
多組時仍提供「移除」，可報讀名稱指明各按鈕的條件組；組與組之間用「AND（所有組）」或「OR（任一組）」連接。這些操作只改目前草稿，不直接修改已儲存情境。
多條條件的完整摘要保留實際括號與順序。

欄位條件先選「保留」或「排除」，再選篩選方式及值。日期方式包含指定日期、日期區間、每月幾日、日期先後、
空白日期、每月月初幾天、每月月底幾天及查核期末最後幾天；文字包含關鍵字、完整內容相同、開頭、結尾及空白內容。
金額分指定金額、金額區間、高於金額、低於金額及空白金額。
高於或低於金額可勾「含門檻金額」。這些選擇對應既有比較規則，不改變空白、正負號或邊界的判定。
主要方式已涵蓋原有運算子，不再重複顯示「其他比較方式」選單；開啟原有情境時不會默默轉換原規則。

日期輸入共用建立案件的原生日期框，單日、區間與指定日期清單都沿用系統的日期選擇器。
指定日期選好後按「加入」或 Enter，日期會加入清單並清空輸入框，焦點留在日期框。重複日期不重複加入。
已選日期逐筆顯示且可移除，也能貼上日期清單。每月幾日填 1 到 31，例如 28,31。
每月月初、月底填 1 到 31 天，含當天，儲存後仍保留按月判斷，不展開成某一年的固定日期。
總帳日和核准日可各自加上排除條件，不共用加班日期清單。
科目編號與科目名稱不附帶「分錄方向」。要指定方向時，用「全部符合」子條件組放入借貸別與科目清單。
「借方與貸方科目編號組合」帶入兩個「至少一筆符合」的整張傳票條件，各自含借貸別與科目清單。
分類依原本選取方式判斷，不因方向條件獨立而改變分類結果。
「查核期末最後幾天」直接顯示天數和計算後的起迄日期，不再另外按套用；儲存仍使用既有日期區間，重開以固定日期顯示。
日期清單貼上、金額基準與空白值處理依當前方式提供，沒有適用設定時不顯示展開入口。
總帳日期空白的分錄原本就不在 GL 中，因此不提供把空白加回來的勾選框；其他日期欄位以
「沒有日期的分錄也列入結果」說明選項。核心金額只比較絕對值，額外數值欄位仍可選含正負號。
勾選空白或額外數值欄位的含正負號時，收起設定仍顯示已啟用的選項。
日期選擇器的鍵盤操作由系統提供，不再維護另一套多選月曆。
日期錯誤或區間倒置時說明修正方式，保留輸入內容。值條件預設不列入空白。

條件列採相同的標題與控制項間距，借貸別及人工或自動分錄也把名稱放在控制項上方。
條件以「選取中」和原有色系邊線標示目前調整的區塊，不會因時間經過或焦點移開而消失。
新增自訂條件時自動選取新列；滑鼠點選或鍵盤移入其他條件時移轉選取，始終只標示一列。
新增時必要的捲動與編輯焦點保留；選取狀態不改條件順序、查詢結果，也不寫入案件或底稿。
選取外框只標示整條條件，內部控制項不顯示焦點外框；鍵盤定位採低調底線，真正的錯誤提示仍保留。
日期與金額區間的起訖欄位成對排列；空間不足時整組換行，更窄時才改成上下排列。
文字清單從單行高度開始，與旁邊的選單垂直置中；增加內容時自動增高，最高 160 像素後在欄位內捲動。

條件變更後標示預覽過期，使用者按預覽才重查。預覽或儲存時後端指出某條規則有問題，那一列標紅、下方一行
寫原因並捲到第一個有問題的規則。已儲存情境可編輯、更新、另存為新情境及取消編輯；成功更新前保留原版，
失敗不留下部分修改。儲存與移除只送正在處理的那一個情境，其他情境由後端照原樣保留。更新不占新名額，副本受十個情境上限限制。舊情境保留原有結合順序與空白規則，開啟時
說明既有設定。未儲存草稿不會留到下次開啟。

舊情境使用已停用的組合寫法時，開案會列為待修正，逐條說明用了什麼與要怎麼重建，不自動改寫定義。
範圍包含欄位或分類內的借貸方向、整張傳票的借貸範圍、分類的不存在模式、核心金額含正負號、
條件組的同一傳票範圍，以及舊式摘要關鍵字和金額尾數條件。待修正原因沿用現有清單呈現，不另加確認流程。
情境用到 GL 還沒選擇來源欄的欄位時，開案也列為待修正，原因寫「第 N 組第 M 條：「欄位名稱」尚未選擇來源欄」。
原條件仍如實顯示；修改成功前，其他已儲存情境保持原樣。舊格式不接受預覽或儲存，審計員可依原因重新加入條件。
名稱與動機常駐，按一次「儲存情境」就送出。新增、修改或另存成功後清空草稿與預覽，顯示儲存結果，焦點移回標題；
等待回應時若又改了草稿，保留後來的修改。預覽不要求名稱或動機，儲存自訂情境時才檢查，KCT 沿用原有例外。
自訂情境依所選條件帶入名稱與動機草稿，兩個欄位常駐；名稱最多 64 字，動機最多 180 字。
條件較多時，名稱列前兩項及總數，動機過長則摘要列出篩選對象；完整判斷仍以條件說明為準。
未手改的草稿隨條件更新，已手改或已儲存情境的非空文字保留；清空欄位後可重新帶入。
同一組裡同時有 KCT 卡片與自訂條件時，名稱寫成「G+自訂」這種形式，動機在 KCT 說明下面每條自訂條件多一行「自訂：」加上條件說明。
範例帶入的名稱與動機，在只填值或改值時保留；加入或移除條件後改用自動名稱，手改過的文字仍保留。
KCT 名稱、範例名稱與自訂建議名稱遇到已儲存的同名情境時都附上數字，例如「G 2」。文字由本機既有條件說明組成，不新增網路服務或推測審計結論。
名稱和其他已儲存情境相同時不送出，名稱欄旁與儲存按鈕上方說明原因；後端仍以名稱不可重複為準，比對時去掉前後空白，大小寫不同視為不同名稱。
條件完全相同、名稱不同的情境可以並存，矩陣各佔一欄（使用者 2026-10-07 裁定維持）。
KCT 卡片帶入的條件在列內改成別的條件後，例如 G 改成摘要包含文字、I 子條件改成週末，就不再算那張卡：
卡片取消勾選，名稱、動機與命名來源跟著改。天數、清單、尾數等審計員要填的值不影響卡片。
新情境保留 KCT 卡片來源，重開後
還原勾選；取消卡片只移除目前組裡該來源的條件。舊情境缺少來源時顯示說明，保留原條件與 KCT 來源，
不憑名稱猜字母，仍可直接編輯。條件說明與錯誤留在對應欄位旁正常換行。
儲存區的欄位與按鈕保留間距；命中傳票表的查看內容欄固定在右側，寬表仍在自己的容器內捲動。

已儲存清單以「查看結果」為主要操作，編輯、另存副本與移除收在「操作」選單內；展開不推高整列，Escape 可關閉並回到選單。
已儲存條件與編輯時共用完整說明，直接用「且」或「或」連接；只有表示實際分組時才加括號。
新建欄位條件在畫面與新產生的底稿都將區間寫為「介於」，金額基準直接寫在欄位名稱後，不再附「含兩端」或括號旁註。
區間仍包含起訖值，空白處理、借貸語意與條件結合順序不變；既有已匯出檔案不會被改寫。
高風險條件矩陣可切換「符合條件摘要」與「傳票交叉表」，只顯示及載入選中的表。分錄明細由審計員在底稿檢視，
矩陣不再提供這個頁籤。傳票交叉表的條件欄表頭只寫 C1、C2 等代號，停留可讀完整情境名稱，名稱對照在「符合條件摘要」；
勾選和代號一起靠左。十個條件的交叉表因此在一般桌面寬度不必橫向捲動（使用者 2026-10-16 選定）。
原有位置對照、排序、搜尋與分頁查詢保留。條件篩選報告可在「已儲存情境與矩陣」獨立產生，不是匯出底稿的前置。
離開已儲存工作區後，重繪條件區不會載入隱藏矩陣。傳票交叉表使用既有允許併行的唯讀查詢，
產生報告時重建畫面也能載入資料。取消或確認移除後，焦點回到最新清單中的可見查看按鈕。

欄位按日期、金額、人員、會計科目及其他文字分組。人員預設使用完整識別值清單，可保留或排除，
不將姓名與員工代碼自行互換。「科目與人員統計」另外選對象、分錄筆數或傳票張數（同號只算一張）、比較方式與門檻。
統計以 GL 為準，條件讀回寫成「GL 中」。尾數條件的讀回寫「金額整數部分（不含小數）末 N 位 = 樣態」。
日曆條件可選週末、假日、補班日及非營業日；金額可選整數特定尾數；文字可排除指定開頭或結尾。
這些計算說明使用一般提示色，實際錯誤才用錯誤樣式。精確規則見 `jet-guide.md` 第 6 節。

JET 更新篩選規則後，不要求審計員逐案重新儲存情境。開啟案件時，JET 先用目前的規則逐一檢查已儲存的情境；
已是目前規則版本的情境也一樣檢查（使用者 2026-10-13 裁定），所以分類或欄位配對改變後不合格的情境，開案時就會列出。
全部仍然有效時，自動改用新規則並清掉舊的命中，畫面顯示一則提示，說明已用新規則重新計算幾個情境，
先前的條件篩選報告與底稿已標為過期；第一次查看命中或匯出時，JET 才用新規則重算。
只要有一個情境不符合目前規則，開案時整批都不動。第五步上方的「GL：查核期間內的分錄」區塊逐一列出是哪個情境、哪裡不符合，
請審計員到「進階條件篩選」修改後儲存。GL 不是依查核期間建立、規則版本無法辨識，或條件內容讀不出來的情境，也列在這裡，不自動改版。
每個原因只寫哪裡不符合，例如「「傳票日期」已移除，請刪除此條件」；條件內容損毀的情境不論有幾條，只寫一次「條件內容無法讀取」。
儲存時條件內容損毀，那一條條件下方寫「此條件內容有誤，無法儲存。請刪除此條件後重新設定。」。
依使用者 2026-10-13 的裁定，這些情境可以一個一個修改或移除：儲存或移除一個情境時，其他情境照原樣保留，
改好或刪掉的情境從清單消失，改沒問題的情境也不會被擋。全部處理完之後，JET 才改用目前規則，
矩陣、完整命中和條件篩選報告才會顯示，第六步也才能匯出。
「重新檢查並儲存情境」按鈕用目前規則重新檢查全部情境：能套用的改用目前規則，還不能套用的照原樣保留並留在清單上，
不會因為其中一個不合格而整批失敗。完成後訊息說明更新了幾個、還有幾個要修改。

### 6. 匯出底稿

使用者選擇報告並啟動匯出。進度事件只顯示正在準備、寫入或發布哪一部分；只有 action 成功回應才
顯示完成。報告清單每筆顯示檔名、時間與大小；檔案在 JET 之外被改過或已不存在時，多一個狀態標示
（「已在 JET 之外修改」、「檔案不存在，重新匯出即可」），只提醒不阻擋。Working Paper 每次匯出新增
一個版本檔；第六步的「工作底稿版本紀錄」列出全部版本，最新在上，每頁最多 50 份。較早資料或
條件產生的底稿標示「先前資料或條件的版本」；這些紀錄不影響目前流程是否完成。按「開啟資料夾」
會在檔案總管選取該檔，讓使用者自行開啟；已刪除的版本保留提醒並停用這個按鈕。重新匯出後立即保留
新舊兩筆，不必重新開案。科目配對範本由第四步的卡片產生，不在這份清單裡。
流程總覽第六階段的「檔案大小」和報告清單一樣以兩位小數的 MB 顯示，不顯示位元組數。

匯出前列出採用的情境及條件儲存時間。已有可用的驗證結果及已儲存情境即可進入第六步，不要求另一份報告檔存在。
工作底稿版本紀錄不依賴情境：情境全部刪除或無法套用目前規則時，只要已經有任何工作底稿版本紀錄，
仍可進入第六步查看。這時匯出按鈕停用；沒有已儲存情境時，畫面寫「還沒有已儲存的篩選情境，
請先到「進階條件篩選」儲存，再匯出工作底稿。」。情境與版本紀錄都沒有時，第六步照舊鎖住並寫出原因。
底稿匯出使用目前資料重新計算已儲存條件。條件篩選報告尚未產生、過期或被刪除，都不阻擋底稿；不會順便重建該報告。
新增篩選條件的完整說明一併寫入底稿，未儲存草稿不會自動納入。已儲存情境無法套用目前規則，
而且還沒有任何工作底稿版本紀錄時，第六步維持鎖定，步驟檢查列出的原因是「修改無法套用目前規則的篩選情境」。
流程與總覽的短句維持「需先儲存篩選情境」，具體原因由步驟檢查說明。
已有版本紀錄時可以進入查看，畫面照舊逐筆列出無法套用的情境，匯出按鈕停用。
匯出頁與總覽都以目前版本的工作底稿表示完成，不要求條件篩選報告同時存在。

清單即將超過 4,096 筆時，JET 才整理已確認檔案不存在的底稿紀錄；現存或無法確認的檔案紀錄會保留，
不刪除任何實體底稿。發布前再次確認檔案狀態，仍超限就提示自行整理舊底稿後重試。匯出成功後立即
同步整理後的完整清單。

### 各步明細表的分頁、排序與搜尋

明細表每頁最多 200 筆，超過一頁時表格左下方只有左箭頭、`目前頁數/總頁數`、右箭頭；第一頁停用左箭頭，最後一頁停用右箭頭。
只有一頁時不顯示分頁列，第一頁讀到之前也不先顯示空的頁碼。第六步的工作底稿版本紀錄一頁 50 份，換頁也用同一個分頁外觀。
總頁數依後端的完整查詢總筆數計算。後端只在第一頁計數，換頁時沿用第一頁的總頁數；搜尋或排序後回到第一頁，總頁數隨結果更新。
畫面只保存當頁資料和已走過的游標，不累積整份明細。

完整性差異、借貸不平、空值紀錄、總帳日期空白、抽樣樣本、預篩選命中、篩選命中、傳票矩陣與命中
傳票清單的表頭可點排序，點一下升冪、再點一下降冪，箭頭標示目前方向；表上方有「依傳票號碼查看」輸入框
（科目層的表是「依科目編號查看」），送出後只留含該文字的列，按「清除」還原。換排序或搜尋時清掉列從
第一頁重載。排序與搜尋先在資料庫對完整查詢範圍執行，再取當頁資料，空值排最後；未提供完整資料排序的預覽表不放排序按鈕。
第四步因其他狀態更新而重繪時，一般明細、INF 樣本及預篩選明細保留目前頁、游標、排序、搜尋、展開狀態與捲動位置。
讀取失敗也保留已載入內容，重試接續原位置。切換案件、重新開案或產生新結果後才丟掉舊分頁；晚到回應不能寫入新案件或新結果。
缺傳票號碼與缺科目編號分開呈現，各自排序、搜尋與分頁；同筆同時缺兩欄會分別出現。
兩類均可搜尋傳票號碼、科目編號或摘要，搜尋失敗保留原結果並可重試。表頭明示總帳日期，不泛稱日期。
「核准日不在期間」等異常明細在展開時直接查詢該類別的第一頁，不從混合摘要樣本推斷有沒有資料。
完整性測試的「核對項目」表只呈現核對數字，表上方不另放說明段落。
表格正在讀取時按「查看」或「清除」不會被忽略：畫面說明會在讀完後接著執行，只保留最後一次要求；
目前的讀取成功或失敗後都會接著執行，失敗後也可以再按。

- `wwwroot/js/state.js` 保存目前畫面、案件 metadata、摘要與 request id，不保存完整 GL／TB。
- 下一步是否可用，以後端結果與 `ui-core.js` 的單一進入條件檢查呈現為準。
- 切換步驟可以保存位置，但不能把「看過某頁」誤寫成「業務條件已完成」。
- 上游資料、mapping 或規則版本改變後，前端不沿用舊結果；結果清除與重新執行的狀態依實際相依關係處理，不加全頁重跑警語。
- Background response 必須確認仍屬同一案件與同一 request，不能覆寫後來載入的 state。
- 通知慣例（2026-09-01 收斂，整個前端唯一）：凡是會改變任何衍生畫面輸出的 store 寫入一律
  bump（`contentVersion` 進版、面板重建）；「只 notify」僅限「唯一視覺反映就是使用者正在編輯的
  那個控制項本身」的連續文字輸入，且必須在 blur 後延遲一次 bump 收斂。select／radio／checkbox
  是離散提交，永遠直接 bump。重建後的輸入焦點與捲動由 `app.js` 的 `renderContent` 依焦點識別
  屬性與 `data-preserve-scroll` 標記統一還原，步驟模組不得各自發明保留機制。已文件化的
  例外包括 filter-step 的規則值編輯、科目勾選和拖曳的暫時選取，以及欄位配對的借方代碼與攸關資料元素
  顯示名稱。這些操作就地同步相關控制項，避免重繪打斷輸入、指標捕捉或滑鼠點擊；
  真正套用分類和保存資料仍依 Store 更新。不能把是否呼叫 bump 當成是否完成業務程序的判定。
  守衛測試：`tools/tests/frontend-journey-mapping.test.cjs` 在第三步畫面上檢查重繪次數、焦點、捲動與連續輸入。

欄位配對的必填鐵軌與「確認配對」按鈕都由同一份 draft 推導。文字輸入就地更新兩者，不重建；下拉選擇會立即 bump。
中央內容重建後，`app.js` 把焦點放回重建前的同一個控制項，並還原 `data-preserve-scroll` 容器。
控制項有 `data-focus-key` 時照它找；沒有時，比對所在區塊的 `data-motion-key`、元素種類、名稱、無障礙標籤與不會變動的 data 屬性，
同樣條件的按鈕再加上去掉數字後的按鈕文字。重建前後都只對到一個控制項時才還原，對不到或對到好幾個就不移動焦點。
這避免右側仍顯示「待指派」、按鈕維持停用，或重繪把焦點送回錯誤控制項。

按下的控制項在重建後不見或停用時，步驟模組用 `JetFocus.deferFirst` 把焦點交給接替它的控制項。
例如第五步移除一條條件後，焦點移到下一條的「移除」，沒有下一條時依序是上一條、所屬的子條件組與條件組；
第一步、第二步與第三步的編輯、取消與確認，也各自把焦點交給換上來的按鈕或第一個輸入框。
執行中整個中欄暫時不能操作，結束後焦點回到按下的控制項。第四步的「篩選結果」記得有沒有展開，重建後維持原狀。
這些是使用者 2026-10-13 指示直接處理的修正，原本重建後焦點會落到整個頁面上，按 Tab 又從步驟標題開始。

控制項也可以自己宣告接替者：`data-focus-successor` 寫選擇器清單，用分號隔開。中欄重建後原控制項不見時，`app.js` 依序找第一個可見、
可按且不在退場動畫裡的接替者，把焦點交給它並捲進畫面；原控制項還在就照上面的規則放回去。第三步的兩顆「讀取來源值」按鈕用這個方式，
依序是「讀取來源值中…」的提示、讀取失敗的「重新載入」、讀出的值清單第一個選項，最後是清單本身；提示與清單用 `tabindex="-1"` 拿焦點，
不進 Tab 順序。既有的 `deferFirst` 呼叫保留，新按鈕用宣告就好。這是 2026-10-24 預篩選收斂計畫階段八加的，
之前按「讀取來源值」後焦點掉到頁面本身，代碼清單有時被捲出畫面。

## 診斷日誌

「狀態與訊息」只加入 info、warn 或 error 等級的非空白文字，未指定等級時使用 info。
error 是操作失敗，warn 是需要注意，info 是一般說明與完成紀錄（使用者 2026-10-13 裁定訊息分三級）。
後端 `log.append` 與三種資料庫的訊息紀錄表接受同樣三個值；舊案件開啟時資料庫升版，原本的 warn 照樣是 warn，不回頭重新分類。
開案讀回訊息時，不認得或缺少的等級一律當一般訊息顯示。
後端拒收格式錯誤的訊息時，先記入去識別支援日誌，前端再跳過該筆，繼續保存後面的訊息。
忙碌、資料庫或傳輸失敗仍保留原筆重試，不當成已保存；切換案件後不把舊案訊息寫入新案。

長操作成功時只留一則完成訊息，耗時接在完成句後面，例如「已在案件資料夾產生工作底稿（12 張工作表），耗時 4.2 秒。」；
沒有自己完成句的操作寫「重建科目配對檔完成，耗時 4.2 秒。」這類句子。
失敗與取消時把耗時寫在括號裡，有進度時再接最後進度，括號後加句號，例如「產生工作底稿失敗：原因（耗時 4.2 秒，最後進度：工作底稿正在寫入「工作表」，已完成 3 張工作表、寫入 1,500 列）。」；
最後進度不再重複耗時，接進訊息時拿掉「工作底稿：」的冒號，按「取消作業」後的「當時進度」也一樣（使用者 2026-10-14 第三輪勾選頁確認）。後端判定前置條件還沒完成時寫「產生工作底稿尚無法執行：原因。」，
另一項作業還在進行時寫「另一項作業還在進行，請等它完成後再試。」，這兩種都沒有開始做事，不附耗時（使用者 2026-10-13 勾選頁確認）。
耗時不到 60 秒寫一位小數的秒，四捨五入是 0.0 秒時寫「耗時不到 0.1 秒」，60 秒以上寫「2 分 51 秒」，一小時以上寫「1 小時 3 分」；
產生報告或工作底稿時，忙碌遮罩上的進度每個階段一句，例如「工作底稿：正在寫入「工作表」，已完成 3 張工作表、寫入 1,500 列，經過 4.2 秒」，
經過的時間也用同一種寫法（使用者 2026-10-13 裁定保留耗時，改成秒並合併）。

- 「輸出支援日誌」是去識別紀錄。訊息面板的按鈕在 Release 也有，匯出目前案件的紀錄；案件清單頁尾的按鈕
  只在 Debug 組建出現，不帶案件，匯出全部紀錄到 logs 資料夾，案件還沒開啟時也能用。
- Debug 的「DEV — 診斷日誌匯出」保留較完整的原始紀錄；面板版要先開啟案件，案件清單頁尾的
  「輸出診斷日誌（DEV）」則不用，並帶該次失敗的 correlation。畫面明示內容可能含案件資料。
- 支援日誌由後端寫入目前案件目錄或 logs 資料夾，診斷日誌寫入案件目錄。前端不接受任意路徑，也不自行組合或過濾 NDJSON。
- 非預期的錯誤（錯誤碼 `bridge_error`）在畫面上只顯示固定訊息「發生非預期的錯誤，此操作未完成。請再試一次。」，
  不顯示例外原文、本機路徑或例外型別；
  錯誤碼與 correlation 照舊回給畫面。後端已知的錯誤照舊顯示原本的中文訊息。

## 作業、取消與關閉

長作業一次只允許一項會改動案件資料的操作。前端顯示 busy 狀態與取消入口；`operation.cancel` 只表示
已提出取消，最終結果仍看原 request。
取消送達時若資料庫正在執行語句，三種資料庫都會中斷它，不等它跑完；原 request 以 `operation_cancelled` 結束。
檢視與預覽來源，以及各項匯入都能取消。逐檔檢視取消時停止剩下的檔案，保留已檢視的清單，不把取消當成讀檔失敗後繼續。
若串接作業的前一階段已完成，取消只停止後續步驟，畫面明說已完成的結果仍保留，不宣稱整串作業都已回滾。

案件清單保留 `project.json` 無法讀取或解析的案件，顯示下一步而不假裝資料庫種類為 SQLite。
使用者可以先檢查檔案是否被鎖住，或從備份復原；損壞時也可另建案件重新匯入，其他正常案件仍可使用。
開始填寫建案表單後，背景資料庫設定結果只更新 SQL Server 選項是否可用及其提示，不重建表單，不替使用者切換已選的資料庫。
未知狀態不等於未設定；確認未設定時停用選項並說明改選 SQLite 或 DuckDB，之後確認已設定時重新啟用。晚到的案件清單回應仍由離開首頁的守衛忽略。

離開案件或關閉視窗時，要先停止新 request、處理在途作業並釋放案件鎖。畫面不能因為 Bridge 尚未
回應，就自行假設鎖已經釋放。
頂列按鈕稱為「退出」，不暗示未儲存草稿也會儲存；此次沒有新增自動儲存或額外確認步驟。
