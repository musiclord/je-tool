# JET 前端說明

更新日期：2026-11-01

一般操作提示說明查找條件、結果或下一步，不夾帶程式沿革與內部資料格式。
例如借現金範本說明「借方為現金，而整張傳票沒有貸方現金的分錄」，不附程式相容來源。
範本提示與新套用的動機使用同一份文字；已儲存的動機保留使用者原有內容。

六步驟共同完成同一案件的分錄測試：設定查核範圍、匯入來源、確認欄位、檢查 GL 及分類、選取待查核分錄，
最後產生底稿。同一資料與動作跨頁沿用名稱；提示只回答操作當下的問題，不要求使用者理解程式狀態或遷移背景。
按鈕須能從鄰近標題辨認對象，存在多種檔案時直接寫出檔案用途。必要的欄位說明直接可見；細節展開只用於選用內容。
狀態以文字說明，不使用看似單選鈕的空心圈。相依欄位、操作及結果就近排列，間距與按鈕尺寸使用共用樣式。

第五步的自訂條件可加入比對同一筆分錄的「子條件組」或判斷整張傳票的「整張傳票條件」。
子條件組內可再加入子條件組，各條子條件各自選 AND 或 OR。整張傳票條件可選至少一筆、全部符合或不存在符合；要限定借貸方向時，另加「借貸別」子條件。
畫面與報表都列出完整括號及條件範圍，並說明全部符合需要至少一筆分錄。
第四步科目配對以科目清單為主要操作。審計員搜尋科目並整批勾選，一次套用同一分類後儲存。
科目清單和 Excel 配對工作檔使用已確認欄位配對的科目，不要求先有資料驗證結果。
每頁最多 200 個科目，可全選本頁，支援編號與名稱搜尋。勾選欄可用滑鼠拖曳連選，Shift 點選則選取區間。
從已勾選的科目開始拖曳會取消該區間；拖回時縮小區間，原本區間外的選擇保留。
拖到清單邊緣會捲動本頁，不跨頁載入。Esc 或指標操作中斷會取消這次拖曳；換頁、搜尋及套用後重新建立 Shift 連選的起點。
單點與鍵盤勾選仍可使用。選取即時更新勾選、列底色與筆數，不重繪表格，也不套用或儲存分類。
科目名稱仍可反白複製；拖曳只從勾選欄開始。「本頁」文字與勾選框在同一列置中對齊。
勾選與已套用的分類在換頁、搜尋後都保留，換頁不需要先儲存（裁定 2026-10-08-01）。
筆數寫出已選幾個科目，以及其中幾個在其他頁，可以按「全部取消」取消勾選；筆數、取消按鈕與分類工具垂直對齊。
套用分類用下拉選單，下層分類以縮排和「└」標出所屬的上層（裁定 2026-10-15-12）。選定分類後仍要按「套用至已選科目」，最後再儲存。
第四步科目搜尋、第五步「從科目樹選取」與表格搜尋共用搜尋框，按「搜尋」或 Enter 才送出查詢。
「清除」清空搜尋字詞並重新查詢。第五步科目樹每次讀取最多 100 個科目。
第五步的分類樹共用縮排與展開收合外觀，可將分類中的科目編號加入條件清單；第四步只選一個分類，不使用分類樹。
換頁用和明細表相同的分頁列，不因勾選或尚未儲存而停用。「套用至已選科目」套用到所有頁的勾選，
「本頁」只切換這一頁的勾選。按「儲存科目分類」一次儲存所有頁有改動的科目，超過 500 個時分批送出；
某一批失敗時，已存的部分保留，其餘仍待儲存，可以再按一次儲存。其他科目與 Excel 已匯入的分類保留。
還有沒儲存的分類時，離開第四步、執行預篩選、回首頁或結束前，會先詢問「儲存並繼續」、不儲存也繼續，或「留在這裡」。
對話框同時寫出儲存會清除什麼：預篩選結果，以及第五步的篩選情境與還沒存的條件。會清除篩選情境時，焦點預設停在「留在這裡」，
按 Enter 不會直接儲存。同一時間只開一個對話框。儲存後，原本要去的步驟若因情境被清除而不能進入，改到最遠還能進入的一步。
預篩選與後續步驟只使用已儲存的分類；不儲存而離開第四步時，改動仍留在畫面上，回來可以再儲存，回首頁或結束則不保留。
GL 或 TB 重新匯入、附加來源或重新確認欄位配對後，已存科目配對和未儲存草稿都清除，分類定義保留。回到第四步時依新資料重新配對，不沿用舊科目與勾選。
「在 JET 配對」與「用 Excel 配對」只顯示所選方式，支援方向鍵移動分頁焦點、Enter 或空白鍵選取。
分類設定是獨立子畫面，返回時保留原方式及未儲存草稿。Excel 依取得、填寫與匯入排列，匯入覆蓋和重建清空的提醒保留。
「分類設定」只填分類名稱：分類是內建的預設分類與審計員自訂新增的分類，和 IDEA 版 JET 的科目配對一樣。
含巢狀條件的編輯器讓底部操作列隨頁面排列，避免固定操作列遮住子條件。

右側面板標題為「資料預覽」，標題、頁籤、選單、提示與表格的中文用 Noto Sans TC，英文與數字用 Instrument Sans。
一般文字及表格為 12px，狀態標題為 13px；數字保留等寬數字與右對齊，寬表在面板內捲動。
資料名稱為「PBC-GL」「GL」「GL(未納入測試)」「PBC-TB」「TB」與「科目配對」，頁籤、其他資料選單及載入提示使用相同名稱。
這組名稱依裁定 2026-10-08-04 與 2026-10-08-05。名稱的權威是 `DataPreviewDatasetLabels`，前端逐字鏡射。
「GL」與「GL(未納入測試)」列同一組欄位，依已確認的 GL 配對決定，欄名和欄位配對畫面相同，例如「傳票文件項次」「會計科目編號」「傳票摘要」。
最前面是傳票號碼、傳票文件項次、總帳日期、會計科目編號、會計科目名稱、傳票摘要、金額與借貸別，接著是已配對的選填欄位與攸關資料元素欄位；
未配對的欄位不列，借方與貸方金額也不分欄（裁定 2026-10-22-09）。人工或自動分錄有配對時兩頁都列，顯示「人工」「自動」，沒有判定時顯示「—」；
PBC-GL 與第五步篩選預覽不加這一欄。只有金額欄靠右對齊，傳票文件項次、會計科目編號這類文字欄照樣靠左。
TB 與科目配對也一樣，欄名和欄位配對畫面相同，例如「會計科目編號」「會計科目名稱」「年度變動金額」。
PBC-GL 與 PBC-TB 只把已確認配對到金額的來源欄靠右，數值照來源文字；還沒確認配對時全部靠左。
第三步已確認配對的來源表用同一個判斷，還沒確認的草稿表全部靠左（裁定 2026-11-05-04）。
資料預覽的金額固定顯示四位小數，例如 1,234.5000；GL、GL(未納入測試) 與 TB 的金額欄，以及 GL 下方統計列的金額都是如此（裁定 2026-10-22-06）。
其他畫面是兩位小數。PBC-GL 與 PBC-TB 是匯入的原貌，顯示來源文字（做法見裁定總表 2026-10-22-10）。
「GL(未納入測試)」最後一欄是未納入原因，寫「總帳日期空白」「早於查核期間」「晚於查核期間」或「過帳狀態不符」，表格下方列出這四種原因各自的筆數（裁定 2026-10-21-04）。
這份資料的頁籤下方另有「未納入原因」下拉選單，預設「全部」；
選了一種原因後只列這種原因的分錄，總筆數與換頁也只算它，下方四個筆數仍是全部未納入測試的分錄。
換到別的資料表時這一列收起，回來時從「全部」開始。下拉選單是 28px 的緊湊欄位，和表格裡的下拉選單相同。
表格下方的筆數與概況以「｜」分項，欄寬不夠時整項移到下一行，名稱、金額與日期不從中間斷開。
流程總覽的數字、日期與圖表刻度也使用 Instrument Sans。第四步統計和總覽統計共用字級、字重與行高；表格與圖表刻度維持各自閱讀層級。

頂部案件摘要的中文用 Noto Sans TC，英文與數字用 Instrument Sans，數字使用等寬數字設定。
摘要列只保留案件名稱、客戶名稱與查核期間，是這一頁的標題：排成一行，標籤在值的左邊，項目之間以細線分隔，案件名稱用深墨色。
視窗寬度至少 900px 時，摘要和名稱、操作按鈕在頂部標題列的同一列，從中欄的左緣開始，三組的中線在同一條水平線上；
名稱特別長時，案件名稱與客戶名稱以刪節號縮短，查核期間完整顯示。寬度不到 1536px 時，例如 1280×720 的小筆電，
摘要各項之間的間距收窄，「案件名稱」「客戶名稱」「查核期間」三個標籤照樣寫（裁定 2026-11-05-09）。比較窄的視窗把摘要放在標題列的第二列，和名稱同一條左緣；
一行放不下時換行，每一行開頭的項目都對齊同一條左緣，不帶分隔線。
目前階段由左側目前步驟表示，不在頂部重複。
左側的進度仍表示已完成步驟數，不因切換目前步驟而增加。
頂部顯示「目前帳號：帳號」，由既有 `system.whoAmI` 提供目前 Windows 身分；它在名稱「JE Tool」的下一行，兩行對齊同一條左緣，
不再加表示連線的色點，連線失敗時直接寫「應用程式連線失敗」，和訊息面板的說法相同。
建立案件也使用同一個 Windows 短帳號，表單不提供另一個可修改的操作人員欄位。
案件已建立後，第一步摘要與總覽將原先保存的身分標為「建案者」，不與頂部的目前帳號混用。
預覽工具以範例帳號呈現，合成資料提醒只放在工具列。退出按鈕顯示「退出」，不承諾儲存未儲存的草稿。
當前步驟的標題旁寫和流程總覽同一套的狀態字「✓ 完成」「可處理」或「等待前置步驟」，判斷也和總覽相同，
後面接未完成提醒「尚缺：…」；收合起來的那一列寫同一個狀態字（裁定 2026-10-30-21）。
建立案件收合時只顯示「案件基本資料已建立」，
詳細資料仍可展開查看。第五步以「儲存情境」為主要按鈕，「查看符合的傳票」為次要操作，儲存流程和規則不變。

收合步驟排成一行，名稱後面接資料摘要，展開箭頭在最右；例如「匯入資料」後面顯示總帳明細與試算表筆數。
第六步還沒匯出目前版本的工作底稿時寫「匯出工作底稿」，已匯出時寫「已匯出工作底稿」與匯出時間，
和左側進度、第六步的完成用同一個判斷。
第四、五、六步及總覽使用「GL」稱呼納入測試的分錄，以查核期間與過帳狀態說明哪些分錄列入 GL。
驗證與預篩選報告使用相同的操作列；已有當次報告時提供「開啟資料夾」，尚未產生時提供產生按鈕。
資料夾入口依已登錄報告的識別值呼叫既有主程式功能，不由前端猜測檔案位置。
報告是測試做完之後拿到的檔案，不是另一個測試項目（裁定 2026-10-11-11）。
第四步的「驗證報告與抽樣清單」與「預篩選報告」放在各自工作面底部一塊低一階的區域，橫跨整個工作面；
第五步的「條件篩選報告」與第六步的「工作底稿版本紀錄」直接放在畫布上，是一塊比畫布明顯低一階的托盤（裁定 2026-10-13-07）。每份檔案是一張文件卡，
左邊有灰色文件圖示，名稱、檔名與建立時間排在中間；預篩選報告也有自己的標題。
產生或重新產生報告的按鈕都是白底細框的次要按鈕，放在報告區標題右邊；第五步的「產生條件篩選報告」也是次要按鈕，
這一步的實心主要按鈕只留給「下一步：匯出底稿」。
第四步的驗證與預篩選已有結果且沒有過期時，「重新執行驗證」「重新執行預篩選」是白底細框的次要按鈕；還沒執行或結果過期時照舊是藍色（裁定 2026-11-05-22）。

欄位配對的簡易清單與對照表格都只顯示目前金額模式適用的欄位。多個用途共用來源欄時，表格列出全部用途，
並可切到簡易清單各自調整；切換介面不改已選配對。欄位鍵、標籤、必填模式與字面值欄位均以領域目錄為依據。
簡易清單的「傳票核准日」在該列使用單一下拉，選項是「—」「與總帳日期相同」，以及各個來源欄；「—」表示未配對。
對照表格只從表頭指派核准日來源，不再在表格下方重複選欄。未指派核准日來源時，可勾選「核准日與總帳日期相同」。
切換兩種介面保留同一份草稿；從表頭指定來源欄後，核准日改由該欄提供。同一來源欄已被多個欄位使用時，表頭保留其對應名稱，可回簡易清單調整。
送出的 `approvalDateMode` 三個值與後端規則不變（裁定 2026-10-08-09、2026-10-09-01）。
畫面不寫兩種日期的用途說明，也不常駐核准日正常狀態的文字；必填、衝突與相關測試無法執行時仍使用既有提示（裁定 2026-10-08-18）。
匯入步驟四列的按鈕寫出要做的事：還沒匯入寫「匯入」，國定假日與補班日還沒設定寫「設定」，已有資料寫「更改」（裁定 2026-11-05-20）。
已儲存情境的選單稱「操作」。兩者都提供含對象名稱的無障礙標籤。
展開後的「開始匯入」「編輯」「移除」仍使用明確動詞，不把所有按鈕改成同一名稱。

頂部、瀏覽器與桌面視窗標題使用 `JE Tool`。頂部的名稱是字標：JE 放在石板藍的圓角方形裡，Tool 接在後面，JE 就是 Journal Entry。
頂部不用圖形標誌（裁定 2026-10-11-08）。字標只出現在頂部這一次。
側欄標題為「流程」；每個步驟前有一個石板藍的圖示，還不能開始的步驟圖示是灰色。
已完成的步驟在右側打勾，可開始與未開始的步驟不另加符號，靠字色區分；目前步驟是一片淡藍的按鍵，藍字加左側短藍條。
換步驟時這一片照原樣、同樣大小平移到新的步驟，不浮起也不拉長（裁定 2026-10-12-02）；
新的步驟名稱等這一片快到時才變粗、變藍。
左側目錄與中欄的步驟列都在按下滑鼠時就換步驟，和 macOS 側邊欄一樣，放開時不再換一次（裁定 2026-10-15-09）；鍵盤的 Enter 與空白鍵照舊。
觸控與觸控筆按下時可能是要捲動，在放開時換。
按下時正在編輯的欄位先失焦，先存好它的值再重建中欄；換步驟開出的確認對話框會保有焦點。
換步驟時中欄先停在原本的捲動位置，再和原本那一步收起來用同一條彈簧捲回頂部，不會第一格就跳到頂部或瞬間捲到新步驟的標題。
頂列按鈕文字為「總覽」「開啟案件資料夾」「回首頁」「退出」，高度、字級與內距一致，後三個前面有圖示；
視窗寬度不到 1536px 時只留圖示，按鈕的字仍給螢幕閱讀器報讀，滑鼠停在按鈕上看得到說明（裁定 2026-11-05-09）；
四個按鈕收在標題列裡同一個淡白的框裡，表示它們是一組；按鈕本身平時沒有底與框。
「回首頁」沿用原本離開案件並返回案件清單的行為。
整個介面的中文用 Noto Sans TC，英文字母與數字用 Instrument Sans；不另用等寬或襯線字體。
工作區不重複顯示 WORKPAPER、案件名稱與期間，中央流程列與流程總覽的六個階段卡都不顯示 01、02 等編號；頂部案件摘要及左側流程目錄保留。
篩選結果上方是相連的統計列，分開顯示「符合條件的傳票數量」與「符合條件的分錄筆數」（裁定 2026-10-16-08）。

## 畫面結構

進入案件後，主要畫面有四個區域：

1. 頂部標題列：一整片橫跨視窗的淺色玻璃；左邊是名稱與目前帳號，案件摘要是這一頁的標題，
   右邊是操作組，目前步驟顯示在左側流程。視窗寬度至少 900px 時標題列只有一列，案件摘要從中欄的左緣開始，
   不到 1536px 時操作組只留圖示；更窄時分成兩列，案件摘要在第二列。
2. 左側流程目錄：貼齊視窗左緣、比畫布低一階的紙，列出六個步驟、步驟圖示與已完成狀態。
   下方的「進度」計算六個步驟中已完成的數量。流程目錄、中欄與右側資料預覽都從視窗頂端開始，上緣藏在標題列下面。
3. 中央內容：左側一條流程軸線串起六個步驟，只展開目前步驟，其他步驟各排成一行摘要。
4. 右側資料預覽：貼齊視窗右緣，以細線和中欄分開，查看 PBC-GL、GL 等資料的有界明細；狀態訊息在左下角展開。

左下角的「訊息」那一列是唯一的開關，固定在流程目錄的底部，右邊的細箭頭收合時朝上、展開時朝下。
展開時訊息清單與「複製紀錄」「輸出支援日誌」從它上方長出來，收合時收回它後面，所以展開後要收合仍按同一個位置（裁定 2026-10-12-02）。
兩個操作按鈕可整個換行，不把按鈕文字拆成直排；長日誌內容可換行並在區內捲動。
視窗矮、流程目錄放不下時，訊息區黏在目錄底部，展開後開關仍在原位、兩個操作仍看得到；流程步驟從它後面捲過去，
這時訊息區和標題列一樣變成玻璃，後面沒有東西時維持目錄原本的底色。用鍵盤移到被訊息區蓋住的步驟時，
目錄會先捲到讓那一步露在訊息區上方。

訊息分成錯誤、需要注意與一般三級，和提示框的紅色、琥珀色與中性灰相同（裁定 2026-10-13-15）。
錯誤與需要注意的訊息在時間前面有一個圓形「!」，時間也換成同一個顏色；一般訊息沒有符號。訊息的文字三級都一樣。
收合時「訊息」開關上的數字照未讀裡最嚴重的一級顯示：有錯誤是紅底加「!」，有需要注意是琥珀底加「!」，
其他是灰底。讀屏軟體會念出「3 則新訊息，含錯誤」這類說明。出錯時不自動展開訊息區。
「複製紀錄」複製最近 100 則，由舊到新一則一列，用 Tab 分成案件名稱、案件編號、資料庫、時間、等級與訊息六欄，
可以直接貼進 Excel。時間是這台電腦的當地日期與時間，等級寫錯誤、需要注意或一般，和畫面一致。

審計員自己按的操作失敗時，目前步驟的標題下方會出現紅色提示框，寫出哪個動作失敗與原因，例如
「產生工作底稿失敗：原因。」；不在看得到的範圍時平順捲過去，焦點不動。後端判定前置條件還沒完成而擋下時，
同一個位置改用琥珀色，寫「產生工作底稿尚無法執行：原因。」。另一項作業還在進行與審計員自己取消時不出現。
已經有就地錯誤框的操作照舊寫在自己的錯誤框，不在步驟上方重複，例如確認欄位配對、建立案件、修改案件資料、
儲存情境與案件清單上的操作。第四步產生驗證階段報告、準備或重建科目配對範本失敗時，區塊內已寫「報告尚未產生」或「範本尚未產生」，
也不重複。預覽篩選情境只有把原因標到條件列時才算就地顯示，標不到時照樣出現提示框。
只把焦點放回按鈕的操作，例如移除篩選情境，失敗時也會出現提示框（裁定 2026-10-13-16）。
再按任何一個操作、換步驟、開案、換案或回案件清單時，提示框就拿掉。耗時與最後進度只寫在訊息區。

外觀的結構採用「深藍框架」的四個共用結構（裁定 2026-10-11-06），重點色只用一個藍色。
色系是暖紙色系，保留能看出結構與層級的強調色（裁定 2026-10-08-14、2026-10-11-07）。頂部是一整條淺色標題列（裁定 2026-10-11-10）。
整個 JE Tool 帶有 Liquid Glass 的質感：通透、有自然的光澤，不用漸層填色（裁定 2026-10-11-09、2026-10-12-01）。現在的外觀如下：

- 頂部是一整片橫跨視窗的淺色玻璃，不是色帶也沒有漸層。名稱、目前帳號、案件摘要與操作組都貼在這一片上，
  流程目錄、中欄與資料預覽從視窗頂端開始，上緣藏在它下面，所以頂部讀起來是一整塊，操作組也不再獨自浮在角落。
  靜止時透出底下各欄的明暗；內容捲上來時從它下面經過，只剩柔和的色塊，這時玻璃霧一點、下緣的影子加深，字仍然清楚。
  操作組是貼在玻璃上的一層淡白。
- 明暗照「內容在前」排：左側流程目錄比畫布低一階；工作內容放在最亮的近白紙面工作面 #FFFEFB 上，工作面有淡框、12px 圓角，
  只有貼著的接觸影；右側資料預覽的表格底色比工作面低一階，讓目前步驟的工作面最醒目。
- 材質分兩層。內容層是不透明的實物：畫布、流程目錄、工作面、表格、條件組、資料預覽與流程總覽是紙，按鈕是按鍵，
  輸入框、分段切換的底槽、進度條與托盤往下凹。功能層是玻璃，浮在內容上方，底下真的有內容經過：
  標題列、表格固定的表頭、選單、對話框、總覽圖表的提示框、加入條件時帶過去的標籤，以及分段切換滑動中的選取。
  玻璃模糊背後的內容並提高一點飽和度；光從左上方來，邊緣左上最亮、右下淡一點。不用漸層填色或上半部的亮面，玻璃上不再疊玻璃。
- 層級用實物之間的關係表達：低一階的托盤放東西，白紙寫內容，文件卡代表檔案。第五步的條件總覽與條件組是托盤，
  條件總覽三個分頁的清單與組裡的條件清單是白紙；各步驟的報告區是工作面底部低一階的區域，裡面是文件卡。
- 影子跟著高度：按鍵與分段切換選中的那一格貼著淺影，選單與對話框浮得最高。
  對話框與流程總覽打開時，背後的畫面變暗但仍看得到。
- 按鈕是實體按鍵：藍色主要按鈕上緣接到一道光、底部有厚度，影子帶一點藍；白色次要按鈕上緣一道光，底下貼著淺影。
  按下時立刻再深一階並稍微鼓起，放開後彈回，這是 macOS 27 替玻璃控制項加的回饋；只放大不縮小，按在邊緣的點擊仍然落在按鈕上。
  藍色主要按鈕被按下時，光從按下的位置亮起來，放開後淡掉。滑鼠移上去只有淡淡的底色，不跟著指標發光。
  左欄步驟或案件列按下時立刻再深一階。
- 換分段切換時，選取浮起來變成玻璃：它在字的上面、字透得過來，朝目的地拉長，前緣先到、後緣跟上，到了再落回原本的一片。
  換頁籤時底線也是前緣先到。左側流程目錄換步驟時不浮起也不拉長，見前面側欄的說明。
  選中的字也跟著選取一起換：目的地的字等選取快到時才變粗、變色，
  滑到一半改去別的步驟時也一樣。
  整段重繪或滑到一半又重繪時，從當下看到的位置與速度接著滑。同一個區塊裡的選項組重繪後仍是同一組，
  上方同時多了提示、整組被往下推時也一樣。例如第三步按「重新配對」後切換金額欄位的格式，選取會滑過去，
  「配對已修改」的提示從 0 長出來（裁定 2026-10-12-03）。
  選單從打開它的按鈕長出來，關閉時在原處淡掉；選單打開時畫面剛好重繪，也是淡掉，不會一下不見。
  對話框從畫面中央浮現，關閉時淡出；長作業的「處理中」遮罩結束時同樣淡出。選單和對話框出現時都從稍小、稍霧變清楚。
- 動態都用 Apple 的彈簧，分成兩種性格（裁定 2026-10-12-03、2026-10-15-05）。
  浮在內容上、被操作的玻璃帶一點點回彈：分段切換的選取約 0.28 秒，加入條件時帶過去的標籤約 0.24 秒到標題上，
  選單與對話框約 0.25 秒，按鍵放開約 0.28 秒。最多只超過目標 0.6%，看不出在彈，只是早一點到、收尾俐落。
  內容的版面改變不回彈：長出來、展開與原地改變約 0.28 秒，收起約 0.22 秒，流程欄與底線頁籤的選取約 0.28 秒。
  淡入約 0.15 秒，淡出約 0.12 秒，比長出來與收起都短（裁定 2026-10-13-10）。
  上面的秒數已經是為進階條件篩選加快後的數值：JET 全部畫面共用同一組彈簧，選取、長出來、收起來與選單同比例縮短約兩成，曲線形狀與節奏不變；移除前的晃動與淡入淡出不在此列（裁定 2026-10-15-08）。
  被下一個操作打斷時，帶著當下的速度轉向，不會頓一下再重新起跑。這些都只是呈現，不改變操作結果。
- 使用者切到 Excel 等其他程式時，標題列、表頭、選單與對話框的玻璃改成不透明、不模糊背景，回到 JE Tool 時恢復。
  這是 Apple 對不在作用中視窗的做法，只改外觀。
- JetMotion 收起或淡掉的舊內容是重繪前的複本，會拿掉 `data-action` 這類給程式找元素用的屬性，所以元件的樣式掛在 class 上。
  會新增東西的按鈕用 `.btn--add`，第二步「預覽」、第四步「進階設定」、日期錯誤提示與科目勾選欄也把樣式掛在 class 上，架構測試會擋下新的同類寫法（裁定 2026-10-15-11）。
- 加入、移除、清除與換掉的東西在整個 JE Tool 都用同一種動態（裁定 2026-10-12-02）：
  新出現的從 0 長到自己的高度，字晚一點淡入；拿掉的字先淡出、再收起，下面的內容跟著平順上移，不會一次跳動。
  例如第五步的條件、條件組與已儲存情境，第四步的分類與報告區，第二步的待匯入檔案與每一列按鈕打開的面板，
  第三步接受的過帳值與代碼，案件清單的案件，以及各步驟新產生的報告檔。
  第三步的人工與自動代碼排成一列，加入與移除時左右收放，清掉中間一格時收起的就是那一格。
  收合目前的步驟時，整段內容先收回標題再換成一行摘要；展開時整段從標題長出來。
  換到另一個步驟時，原本的步驟內容收回它那一列，新的步驟內容同時從它的標題長出來。
  收回的內容排在那一列的展開箭頭之後，和標題之間的距離也一起收掉，收完拿掉時下面各列不會跳（裁定 2026-10-15-10）。
  第五步加入條件時另有一片玻璃標籤從按下的地方帶到新的一列，見上面第五步的說明。
- 使用者自己按下移除、清除或刪除時，要拿掉的東西先在原位輕微快速地左右晃一下（最多偏 4px，約 0.2 秒），
  晃到第二下才開始收起，下面的內容在晃動時不先移動（裁定 2026-10-13-13）。
  例如第五步的條件、條件組與已儲存情境，案件清單刪除的案件，第二步移除的待匯入檔案與授權編製人員清單，
  第三步移除的過帳值與取消勾選的欄位，第四步移除的分類，第五步移除的日期。只是清空、不會從畫面拿掉的東西直接晃一下，
  例如第六步與第四步科目配對的「全部取消」，以及清空搜尋框。切換情境或篩選清單這類讓東西消失的重繪不晃。
- 原地改變的區塊在同一個位置換過去，不會一閃而過。高度從原本的平順變成新的高度，下面的內容跟著移動；
  只改了幾個字的地方在原處交叉淡化；內容差很多的整塊先淡掉舊的、再淡入新的，兩份內容不會疊在一起。
  例如第三步換金額欄位格式時，對照表與表格上方的必填欄位原地改變，借方欄換成金額欄，多出來的貸方欄收起；
  按「重新配對」時，摘要在原處換成編輯畫面。正在輸入文字時，跟著變的字直接換，不會每打一個字就閃一次。
- 展開的內容從它的標題往下長出來，收起時也收回標題，兩個方向都有，例如第四步規則的明細、
  「從情境範例開始」、已儲存情境、傳票分錄與「篩選結果」，畫面不會閃（裁定 2026-10-12-02）。頁籤底下原地切換的內容同樣先淡掉舊的、再淡入新的，
  高度平順改變，裡面原本打開的區塊也不會再長一次。
  錯誤與提醒訊息、匯入進度條、第五步的預覽結果與流程總覽的頁籤內容也照這個方式出現與收起，
  收起時字留到收完才清掉（裁定 2026-10-13-11）。
  同一行裡出現或消失的小東西（例如「已選取」、組號旁的範圍標籤、訊息數量與「清除」鈕）左右收放。
  右側資料預覽收合與展開時寬度平順改變，裡面的內容先淡掉再收起，展開時等寬度快到才淡入。
- 資料預覽與各步驟明細表固定在上方的表頭是一條帶一點灰的玻璃：整列表頭一起固定，列捲到它下面時看得到，只剩柔和的色塊，表頭下緣的影子加深。
  捲到表格裡的某一列時，那一列會停在表頭下方，不會被表頭蓋住。
- Windows 關閉「透明效果」時，所有玻璃改成不透明的紙面，滑動中的選取改成放在字下面的實心一片；
  要求高對比時同樣不透明、邊線加深，按下也不亮。使用高對比佈景時玻璃改成不透明的系統底色，不畫按下的光與滑動的選取底，
  改用系統的反白色外框標出目前步驟、選中的那一格與目前頁籤；圖示、字標方框、文件卡、分類樹的線、
  標題列與表頭的下緣，以及選單與對話框的外框改用系統色。減少動態時，滑動、浮現、長出來、收起、原地改變、移除前的晃動與帶過去的標籤都瞬間完成或不做，按下也不鼓起；
  使用高對比佈景時，展開區、訊息區與對話框同樣直接換。
- 形狀依角色分開：表格直角，按鈕、輸入框、下拉選單、分段切換與字標的 JE 方框 6px，可點的卡片與文件卡 8px，工作面與對話框 12px，
  狀態標籤是膠囊形，流程節點是圓形。主要按鈕是藍色的實體按鍵，次要按鈕是白色按鍵加細框，按鈕不做成膠囊形。
  包住控制項的框和控制項同心：頂部操作組與選單是 10px、內距 4px，裡面的按鈕與項目 6px；分段切換選中的一格 4px。
- 石板藍 #1F6C9F 只用在目前步驟、步驟圖示、頁籤、進度、選取、主要按鈕、字標與焦點框。會新增東西的按鈕與列內按鈕是白色按鍵（裁定 2026-10-29-06）。
  主要按鈕是藍色的實體按鍵，按下時再深一階並稍微鼓起；
  它的焦點框是按鈕裡面一圈白線，因為藍框畫在藍底上看不見。紅色只給錯誤與必填，綠色只給通過與完成，
  琥珀色給需要注意但不擋人的狀態。狀態一律同時有文字或符號。
- 字級只用 12、13、14、18、22、28px 六階：步驟標題與統計數字 28px，對話框與總覽標題 22px，工作面標題 18px，
  分區標題與內文 14px。步驟與工作面標題用深墨色 #183348。中文標籤不加字距、不用全大寫。
- 中文用打包的 Noto Sans TC，英文字母與數字用打包的 Instrument Sans；圖示用打包的 Fluent UI System Icons。
  三者都放在程式裡離線使用，授權檔放在同一資料夾。不打包 Noto Serif TC（裁定 2026-10-08-15）。
  字標用同一套字體畫出，不另外打包圖檔。
- 左欄目前步驟是一片淡藍的按鍵，藍字加左側短藍條。卡片裡不再包一層卡片；卡片內的子區塊用細線分隔。
- 所有步驟名稱、步驟標題與工作面都從流程軸線右側同一條左緣開始，工作面裡的文字再統一內縮 24px。
- 提示框分成錯誤、需要注意與一般說明三種，分別用紅色、琥珀色與中性灰。第一步「傳票號碼是否用於不同總帳日期」的提示，
  尚未確認與未發現時是一般說明，有發現時是需要注意。
- 其餘提示依裁定 2026-10-09-03 逐處分類。操作失敗與必填維持紅色。不擋操作的提醒，以及請使用者確認後果的說明用琥珀色，

- 第三步來源值、第四步科目清單與第五步科目樹的讀取失敗，共用紅色提示與「重新載入」按鈕。

- 條件說明、配對說明、尚未符合前置條件的說明及匯出選取說明，共用 13px 灰字與 1.6 倍行高。
  人員清單的填法也用這種文字，不再包資訊提示框。成對的選取動作統一寫「全選」和「全部取消」。

  條件篩選報告只寫「已儲存的篩選情境尚未套用目前規則，暫時無法產生報告。」（裁定 2026-10-13-04、2026-10-14-01）。

  例如上面的情境無法套用目前規則就是琥珀色。
- 提示文字只說目前狀態和接下來能做什麼，避免專業術語，不寫成系統日誌，也不把後端已經說過的同一句話再接一次（裁定 2026-10-09-03）。
- 黃色提示要簡短，不過度解釋（裁定 2026-10-14-02）：不補充不擋人的保證，例如「仍可照此日期儲存」「已匯出的底稿不受影響」，
  也不說明 JET 內部怎麼處理；按鈕就在提示旁邊時，不再寫「可先按某某按鈕」。必要的欄名、代碼與後果仍要寫出。

- 控制項只有兩種高度。一般按鈕、輸入框與下拉選單是 32px；表格裡、工具列與條件列的緊湊按鈕是 28px。

  第三步的簡易清單與對照表格、金額格式、高風險條件彙總的切換與總覽的圖表切換都相同；金額格式保留單選鈕。

  要存進案件的設定，例如金額格式，仍用選項按鈕；常用篩選條件這類可以同時選很多個的，是各自的開關，寫「加入」與「已加入」。

  右側資料預覽是靠右的抽屜，箭頭同樣指向它要移動的方向：展開時「收合」後面的箭頭朝右，收起來的窄條箭頭朝左。
  資料預覽的「其他資料」與已儲存情境的「操作」這類選單按鈕，以及所有下拉選單的箭頭朝下，也是同一種細箭頭（裁定 2026-10-13-09）；
  使用高對比佈景時，下拉選單仍用系統的原生箭頭。
  整列可點的標題，例如第四步有明細的規則、「用 Excel 配對」結果清單裡可展開的三列、「從情境範例開始」、已儲存情境、
  傳票表裡的傳票與總覽分析，箭頭在字前面，再點一次就收起；流程收合列的箭頭固定在每一列第一行的右緣，見下方版面一段。

  仍是按鍵，字固定不換，箭頭接在字後面（裁定 2026-10-30-28、2026-10-30-36）。
  按鈕打開內容後字固定不換，不改成「收合」「收起」這類字（裁定 2026-10-19-08）。第五步分類樹也用同一種箭頭按鈕；沒有下層的分類留同樣寬的空位，名稱才對齊。
  分類都沒有下層時不留空位，名稱靠左對齊；第一個正式版新增的分類都是平的一層（裁定 2026-11-03-27）。
- 狀態標籤同一尺寸：22px 高、12px 半粗體字的膠囊形，淡底配深字，顏色只分中性、通過、需要注意、錯誤與選取；無法執行用虛線外框。
- 停用的按鈕一律是灰底灰字，主要按鈕停用時不再是淡藍色。浮動選單和對話框是不透明度八成的玻璃，邊緣左上最亮，外面一圈細暗邊加明顯陰影；選單從打開它的按鈕長出來，裡面的項目是無框的一列文字，滑鼠移上去才有淡底。
  已儲存情境每列的「操作」與資料預覽的「其他資料」是同一個選單：按按鈕，或在按鈕上按方向鍵下，打開選單；
  方向鍵上下在項目之間移動，Esc 關閉並回到按鈕，按 Tab 或點選單以外的地方關閉，同一時間只開一個。
  兩者是同一個元件（裁定 2026-10-19-08）。「其他資料」選單浮在下方表格的固定表頭之上，第一項不再被表頭蓋住。

  第六步的報告勾選與案件清單都改成清單列或淺灰區。第四步上方三個統計是一條相連的統計列，和總覽的統計列畫法相同；
  總覽的六個階段是相連的一組格子，選取的格子用藍框。
- 流程填滿中欄，左右間距相同：視窗放大、資料預覽收合或拖窄時，多出的寬度都給內容，不會只在右側空出一塊，流程不設最大寬度（裁定 2026-10-27-02）。
  收合列與目前步驟的標題列共用同一條右緣，右側箭頭固定在每一列第一行的右緣，中欄再窄也不會掉到下一行，換步驟時位置不變；
  視窗寬度不到 1536px 時，目前步驟上方的已完成步驟收成一列「已完成的步驟」，後面寫各步驟名稱，點它或按 Enter 在原地展開回原本的各列，
  再按一次收起；上方只有一步完成時不收，目前步驟下方的步驟照舊一列一步（裁定 2026-11-05-09）；
  摘要換成兩行時，名稱、左側圓點與箭頭仍在第一行。第四步明細最上方的規則說明一行最多約 60 個字。
  建立案件、匯入資料與匯出底稿的內容與頁尾維持 720px 的閱讀寬度。工作面標題是 18px，工作面裡的分區標題是 14px。
- 按鈕只有兩種：每個工作面唯一的主要動作是藍色實心；其他按鈕都是白底深字加細框的按鍵，下緣略深，停用時灰底灰字，
  和欄位條件分頁的「加入」同一種樣子。會新增東西的按鈕，例如「加入」、條件組合的「條件組」「子條件組」「整張傳票」、
  「新增分類」與案件清單的「新增案件」，名稱前多一個灰色加號；每列重複出現的動作，例如移除、第二步的「操作」與已儲存情境的「操作」，
  是 28px 高的同一種小按鍵。
  展開中的按鈕往下凹：灰底、深字、上緣一道內陰影，看得出內容是從這裡打開的（裁定 2026-10-29-06）。
  第二步四列的「操作」一律相同，沒有哪一列另外加框；展開的內容直接接在列下方，不帶卡片的外框、陰影與圓角（裁定 2026-10-16-07）。

  預篩選工作面裡上下幾份清單的狀態欄因此一直在同一條線上。有明細的列整列可點，箭頭在列首（裁定 2026-10-30-36）；沒有明細的列在箭頭的位置留同樣寬的空位，
  每一列的標題上下對齊。狀態文字很長、格子又窄時，標籤裡的字換行，不撐出工作面；清單很窄時，所有項目一起把狀態放到標題下方。

  流程總覽與第四步的統計列用同一種做法，視窗寬度改變或資料預覽開合時重新調整（做法見裁定總表 2026-10-13-01）。
- 第六步的產生按鈕接在「一併產出的報告」工作面底部；已完成的必要來源，「必要」標籤改成灰字。
- 第六步匯出後的「案件流程已完成」是淡綠底，不加框；前面是一個綠色實心圓，裡面打勾，和流程軸線上完成的步驟相同。

- 表格的表頭固定在上方，只有正在排序的欄顯示方向箭頭，其他可排序的表頭在滑鼠移上去時才淡淡提示。
  表格外框是直角；標題統一置左且不換行，金額與筆數的資料格靠右，例如第五步預覽結果的筆數欄、第二步來源清單的列數，
  以及第四步各項明細表裡的筆數、借貸金額與差額欄（裁定 2026-10-13-05）。
  表頭固定置左（裁定 2026-10-16-01）；數字欄只取內容需要的寬度，讓標題和數字留在同一個窄欄。
- 案件清單畫面還沒有開啟案件，頂部不顯示空的案件摘要列。

`.agents/skills/jet-frontend-design/SKILL.md`。

流程總覽使用 modal 呈現既有 state 的摘要。它不是第二套導航，也不重新計算每個步驟是否完成。
頂端小標是「分錄測試流程總覽」，標題是客戶名稱，沒填客戶名稱時改用案件名稱；下方一行寫案件名稱與查核期間，
標題已是案件名稱時不重複。
左側目錄的勾選與進度、流程總覽的完成數，以及第六步的「案件流程已完成」，都用 `ui-core.js` 的同一個完成判斷。
前四步在下一步可以進入時算完成；第五步在已儲存情境可以套用目前規則時算完成；第六步在已有目前版本的
工作底稿時算完成。因此匯出完成後，左側會寫「進度 6/6」，和總覽一致。
打開流程總覽時焦點直接放在右上角的「✕」，按 Escape、點「✕」或點背景都會關閉，關閉後焦點回到「總覽」按鈕。
總覽開著時，Tab 只在總覽裡移動，焦點跑到外面也會拉回來；資料更新讓總覽重畫時，焦點留在原本的頁籤或分析區標題。
流程總覽、刪除案件對話框與「尚未儲存」對話框開著時，都登記在 `app.js` 同一個對話框堆疊；整個頁面只有一個鍵盤監聽，
Escape 與 Tab 只交給最上層。例如刪除案件對話框疊在總覽上時，一次 Escape 只關刪除案件對話框，總覽留著，再按一次才關總覽。
總覽開著時遇到作業進行中，鍵盤交給作業遮罩的「取消作業」。堆疊另外保留一個防衛判斷：日後若有原生 `<dialog>` 開著，鍵盤交給它，
目前畫面沒有這種對話框。總覽的焦點處理依裁定 2026-10-13-02。

畫面上的金額顯示兩位小數加千分位，例如 35,920.33，由 `ui-core.js` 的 `money` 統一格式化。
報表與底稿的金額格式不跟著改（裁定 2026-10-02-01）。輸入框、篩選條件的數值與
送給後端的值不經過這個格式化。唯一的例外是右側資料預覽，金額固定顯示四位小數，見本文件開頭的資料預覽說明。

畫面上的筆數、列數這類數量也加千分位，例如 12,345 列，由 `ui-core.js` 的 `countText` 統一格式化；
後端產生、顯示在畫面上的訊息用 Domain 的 `CountText.Format`，寫法相同（裁定 2026-10-30-19）。
Excel 列號、第幾組第幾條與頁碼這類位置不加，例如「欄名在第 1200 列」；年份、日期、傳票號碼與科目代號是代碼，也不加。
篩選條件說明裡審計員填的數值，以及自動帶入的情境名稱與動機，照舊不經過這個格式化，因為這些文字也寫進報告、底稿與情境紀錄。

### 分類樹與科目選取

分類設定、套用分類的下拉及第五步的分類樹都顯示上下層。第一個正式版隱藏「進階設定」與其中的分類用途、上層分類，審計員建立不了上下層，
新增的分類都是平的一層，用途是「其他」（裁定 2026-11-03-27）。程式、後端與資料都保留，開關是 `ui-core.js` 的 `FEATURES.categoryHierarchy`；
案件裡已有的上下層照下面的方式畫出。打開開關時，分類設定可一次建立上層與下層；新增下層先帶上層用途，手動改過的用途保留。
分類設定裡每一層的名稱欄往內縮 24px（裁定 2026-10-11-12），
下層分類用一條深灰的細線接到上層，同一個上層底下的分類共用一條直線，最後一個轉角接到名稱。
JET 內建的分類在右邊標出「內建」，說明它可以改名但沒有「移除分類」；名稱輸入框的右緣一律對齊，右邊固定一欄放「移除分類」或「內建」，
打開「進階設定」時，分類用途與上層分類在每一列也對齊同一條欄線。
移除上層前列出受影響的直接下層，確認後接到原分類的上一層，儲存前仍可取消。新增分類後焦點移到名稱欄，進階設定切換保留焦點。
第五步的分類樹保留勾選與收合，不提供分類搜尋。常用篩選條件與欄位條件新加入的分類條件預設包含下層，舊情境沒有選取方式時仍按原本分類用途判斷。
「選取依據」下拉在第一個正式版隱藏，條件照舊包含下層分類（裁定 2026-11-03-27）。
條件說明寫出方式與實際納入分類；選的分類都沒有下層時，包含下層與僅分類本身選到的分類相同，條件說明不寫方式與實際納入分類。
草稿引用已刪除的分類時提醒重新選擇，不顯示內部 ID。從科目樹選取時，只有案件裡有分類設上層，才寫「（包含下層分類）」與選分類時包含下層的說明。
科目編號的完整值清單可從分類樹查詢本案科目，搜尋及換頁只取有界資料；勾選仍寫進原有科目編號清單，保留前置零。
勾整個分類時不把第一頁當成全部；搜尋框有字時勾分類，也是選整個分類，搜尋框一併清空，清單改列整個分類（裁定 2026-10-19-13）。
若超過既有 100 個值上限，原清單不變，提示縮小範圍或改用科目分類條件；查詢失敗可重試，晚到回應不改其他案件或已移除的條件。
## 案件選擇

啟動後先顯示本機案件。SQLite 與 DuckDB 可以在沒有 SQL Server 的情況下使用。只有使用者要求同步
線上案件時，才查詢 SQL Server registry；線上失聯不能清空已顯示的本機清單。開啟案件時，前端把清單列上的
資料庫種類一起交給 `project.load`。本機找不到案件資料夾時，只有 SQL Server 案件會再查線上登錄，
SQLite 與 DuckDB 案件直接顯示找不到案件。開案後只有 SQL Server 案件定時送出心跳。

建立案件時選定 provider。案件名稱錯誤由後端用結構化 `error.field = "projectName"` 指回欄位，前端不
解析錯誤句子猜測焦點。

案件清單的每個按鈕放在它作用的內容旁邊，不在清單下方排成一列（裁定 2026-10-20-04）。
「新增案件」放在標題右側，是名稱前有加號的新增按鈕，建立哪一種資料庫的案件都從這裡開始。
「同步線上案件」放在線上資料庫的區標題右側，「重新整理本機」放在本地資料庫的區標題右側，兩個都是小按鍵。
本地資料庫排在上面，線上資料庫（SQL Server）排在下面；標題「選擇案件」下面不另寫說明句（裁定 2026-11-05-06）。

開啟或刪除案件失敗時，picker 在清單上方的錯誤框寫出發生什麼事與能做什麼，錯誤框裡沒有按鈕
（裁定 2026-10-13-26）。案件清單的「輸出支援日誌」只給開發人員用，
和 DEV 面板一樣只在 Debug 組建出現，Release 看不到（裁定 2026-10-20-03）；
開案後訊息面板的「輸出支援日誌」在 Release 照舊。Debug 組建的這顆按鈕放在案件卡片下方靠右的頁尾，
按下時 `support.log.export` 不帶 `projectId`，後端把記憶體裡全部去識別紀錄寫到 logs 資料夾，
完成後按鈕下方寫「支援日誌已輸出：路徑」，不需要先開啟案件。剛發生開案或刪除失敗時，頁尾另有「輸出診斷日誌（DEV）」，
把含 SQL 與參數的原始紀錄連同該次 correlation 寫到那個案件目錄；DEV 面板裡的「輸出日誌」要先開啟案件才能用，
開案本身失敗時就靠這個按鈕。報告檔在 JET 之外被改寫或刪除不會讓開案失敗；那只會在第六步清單標示狀態。

刪案確認先讀取 JET 紀錄中仍存在的報告與工作底稿份數，並明說整個案件資料夾及其他檔案一併刪除、無法復原。
讀取失敗時數量顯示未知，可重試，也仍可依原確認流程刪除；不把未知寫成零。SQL Server 案件另提醒這會影響所有共用者。

## 六個步驟

已有篩選情境時，更改前面步驟已設定的資料會清除後面步驟的設定（裁定 2026-10-07-03、2026-10-07-04）。會清除的修改，是讓篩選結果過期的那些：
重新匯入或重新確認總帳與試算表配對、國定假日與補班日、每週休息日、科目配對、授權編製人員清單、期末財報準備日與分類設定。
總帳與試算表的匯入或配對確認使用同一條規則，資料驗證、預篩選與篩選命中一起失效，全部已存情境清除。
清除後第五步回到預設狀態，訊息只寫一句請重新設定篩選情境，等級是需要注意；沒有情境或草稿可清時不新增訊息。
修改失敗時保留原情境。成功修改後，條件篩選報告與底稿照既有規則標成過期，已匯出的檔案不會改寫。
修改前不另加確認（裁定 2026-10-07-05）。已有篩選情境時，第二到四步顯示一句「更改已設定好的資料，會清除後面步驟的設定。」；
第一步只在打開「修改案件資料」後顯示同一句，案件摘要不顯示。不列出清除的細節。

### 1. 建立案件

案件名稱、查核起始日與查核截止日必填；案件編號、客戶名稱及期末財報準備日可以留空，標籤不另加「（選填）」。
資料儲存方式的下拉選單下方寫「建立案件後不能變更。」，標籤本身不夾限制說明。
操作人員由系統取得目前 Windows 短帳號，使用者不能在表單改成別人。表單上方的操作人員提示讀取
`system.whoAmI` 的結果；身分晚於表單出現時，只更新操作人員那一行，不重建表單，已輸入的內容、選取範圍與焦點都保留。客戶名稱留空時，案件清單及工作區
以案件名稱作為主標題，不會顯示成空白案件。
查核期間決定要測試的分錄；期末財報準備日用於相關核准日風險條件，畫面在欄位旁說明兩者用途。
案件名稱只含空白或全形空白時要求填寫，查核起始日比截止日晚時就地指出日期問題，不送出建立請求。
期末財報準備日早於查核起始日，或晚於查核截止日超過一年時，欄位旁提醒確認年份，但仍可建立或儲存。
建案後可在同一頁按「修改案件資料」，只編輯客戶名稱、案件編號與期末財報準備日；案件名稱、查核期間、建案者與資料庫種類仍只讀。
取消不改原資料，失敗保留輸入。成功後更新抬頭和摘要，未儲存的篩選草稿保留；需要重算的結果依後端回應更新。
既有匯出檔不會被改寫，之後匯出才採新資料；表單只寫「案件名稱與查核期間不能修改。」（裁定 2026-10-29-02）。
第五步缺財報準備日時指向這個入口，不顯示內部欄位名稱。
第一步另顯示驗證保存的同號多入帳日提醒，分開列出號碼數與涉及分錄筆數。同月不同日也包含在內，傳票比對鍵不變。
尚未驗證、舊摘要缺欄或結果過期時寫尚未確認；只有實際量測到零才顯示零。這是供審計員確認來源資料的提醒，不阻擋操作。
「資料儲存方式」的「SQL Server（共用實例）」只在啟動時的 `system.databaseInfo` 明確回報這台電腦沒有設定
線上資料庫時停用，選單下方寫「這台電腦沒有設定線上資料庫，請改選 SQLite 或 DuckDB。」。結果還沒回來時
維持可選，不因查詢慢而擋人；已設定但連不上時也維持可選，建立案件時照舊回報錯誤。

### 2. 匯入資料

四類資料的入口按鈕統一為「操作」，展開後仍使用各自原有操作。未匯入授權編製人員清單只顯示「未匯入」，
不以「解鎖」描述用途。頁首不放說明（裁定 2026-10-29-02），支援的檔案類型寫在建立 GL 或 TB 時選檔的那一行提示裡；收合摘要以「總帳明細 N 筆 / 試算表 M 筆」呈現。
清單未完成符號為橫線，實際狀態仍以「未匯入」等文字呈現。授權編製人員清單的說明只寫比對名單外編製人員的用途，
選檔後才要求人員識別欄與 GL 一致，不夾帶 R5 人員彙總的背景。
日曆資料的匯入列稱為「國定假日與補班日」，展開後可上傳清單或設定每週休息日；沒動過星期勾選時，摘要寫「每週休息日 六、日（預設）」，不顯示資料庫用語「日期維度」。
這張卡片只有「上傳國定假日清單」、「上傳補班日清單」與每週休息日設定，另有一句說明：國定假日清單讀 `Date_of_Holiday` 欄，補班日清單讀 `Date_of_MakeUpday` 欄，日期寫成 2026-12-31 的格式。
卡片不提供取得範本或開啟案件資料夾的按鈕。

GL 與 TB 支援 `.xlsx`、`.xlsm`、`.xls`、`.csv`、`.txt`、`.mdb` 與 `.accdb`。GL 可合併欄位相同的來源；TB 提示先整理好本次要比對的資料，不暗示能把期初、期末兩份檔案自動配成餘額。`.xlsm` 由 JET 直接唯讀
活頁簿內容，不啟動 Excel 或執行巨集。前端先讓使用者選檔，再要求後端檢視、預覽及匯入。
右側只顯示有界的少量預覽；完整資料直接寫進案件資料庫，不會整批放進 WebView2。
Access 使用現有 Office ACE 16 讀取一般資料表，沿用來源預覽及匯入清單；不執行儲存查詢或巨集，.xlsb 不支援。
授權編製人員清單、科目配對、國定假日與補班日是支援資料，不是每個案件都必填。
授權編製人員清單匯入須明確選來源欄位，可查看原始預覽及有效識別值。匯入與重開案件後都顯示原始資料列數、略過空白與重複數，
並說明標頭與完全空白列不計入；舊名單沒有保存統計時照實提示。原檔上方有標題列時，提示先在 Excel 刪除標題列再匯入。
清單另顯示出現在 GL 傳票建立人員的人數，一位都對不上時只提醒確認所選的清單欄位是人員代號或姓名，不擋後續操作；尚未確認 GL 建立人員
配對時提示先確認，確認後會更新比對。所選識別欄完全沒有有效值時，要求改選欄位或換檔重試，保留原名單。
取消或失敗保留原清單；移除會清除該清單和相依結果，保留 GL、TB 與驗證結果，預篩選需重新執行；已儲存的篩選情境依下方規則清除。
「加入」先進入匯入清單，由使用者確認；「更換」用來重新匯入同一份 GL 或 TB。成功後說明哪些
配對及計算結果需要更新。
追加後若後端發現檔名、工作表與實際列數都和既有來源相同，顯示可能重複的提醒，本次匯入仍成功；

讀取，失敗後按「重新載入」會重送請求。重新匯入或切換案件後，舊值摘要與舊配對錯誤不再顯示。

重新匯入 GL 或 TB（取代或附加）會讓已確認的配對失效。同一次開啟中保留目前草稿，重開案件才帶回上次確認的配對；
兩者的提示都是「來源資料已變更，請檢查配對後按「確認配對」。」，不另外說明保留的是哪一份。新資料沒有的來源欄會從草稿拿掉，提示逐一寫出是哪個欄位、
原本選的是哪一欄，例如「總帳日期（原為「日期」）」；人工/自動或過帳狀態的來源欄被拿掉時，它們的代碼設定也一起清掉。
重新整理頁面或重開案件後，`project.load` 帶回上次確認的配對作為草稿，不保存關閉前尚未確認的編輯。
攸關資料元素欄位沿用上次確認時的欄位識別碼。

攸關資料元素欄位另有「傳票建立日」快捷，選未使用的來源後自動勾選、命名並設為日期型別；已有同名欄時更換它的來源，保留既有識別碼。
來源已用於另一欄時，先顯示目前用途，提供「把它改成傳票建立日」與取消。確認後沿用被選欄的識別碼，不刪除其他欄位。
若原來另有傳票建立日欄也會保留，提示會說明；核心配對已使用的來源不能在這裡重複使用。
第五步選欄位時，攸關資料元素欄位的名稱後面會加註來源欄，例如「傳票建立日（來源欄：CreateDate）」，
一般條件、舊式 typed 條件與加入子條件的選單共用這份文字。自訂分頁的欄位按鈕與範例就地選欄位時，按鈕只寫欄位名稱，
和其他欄位同名時才加「（來源欄名）」，完整文字放在滑鼠提示與報讀名稱。
兩個同名欄位也分得出來；條件仍以欄位識別碼儲存，讀回文字只寫欄位名稱。
攸關資料元素欄位可全選或全部取消。全選只勾選尚未被核心配對使用的來源欄，預設沿用來源欄名並先視為文字；
使用者仍可逐欄調整名稱與型別。後端最後檢查欄位是否存在、名稱與型別是否合法、欄位識別碼是否沿用正確，
以及來源欄有沒有重複。
勾選或改型別後保留清單捲動位置；全選和全部取消後，焦點留在仍可操作的控制項。編輯已確認的配對時先保留提示區高度，
第一次修改不會把下方清單推走。TB 與 GL 一樣，必填文字欄整欄空白時在成功確認後提醒使用者檢查配對。

### 4. 資料驗證與測試

「用 Excel 配對」是一個往下凹的托盤：上面一排操作照做事的順序排，下面一張白紙列出匯入的結果（裁定 2026-10-30-35）。
操作依序是「準備科目配對範本」「開啟案件資料夾」與「匯入科目配對範本」；還沒匯入時「匯入科目配對範本」是藍色主要按鈕，
已匯入後改寫「重新匯入科目配對範本」，換成一般按鍵。會清空已填分類的「重建科目配對範本」收進最右邊的「更多」選單，
選項下方寫「重建會清空檔案內已填的分類。」。操作下方一句說明填法：在「Standardized Account Name*」欄填入分類後存檔，
再匯入或重新匯入，也可匯入前一個案件的配對檔（裁定 2026-11-01-06）；已匯入時另寫「重新匯入會覆蓋目前全部配對。」。
選檔視窗的標題是「選擇科目配對範本或工作底稿（科目編號、科目名稱、科目分類）」。
選了有多個工作表的 Excel 檔，例如前一個案件的工作底稿，操作列下方先出現一句「「檔名」有多個工作表，請選擇科目配對所在的工作表。」，
下面是「工作表」選單、「匯入這個工作表」與「取消」（裁定 2026-11-05-07）。
選單只列有欄名的工作表；檔案裡有「自動化工具-科目配對資訊」時預先選它。選工作表時藍色主要按鈕是「匯入這個工作表」，
上面的匯入按鈕暫時改成一般按鍵；匯入成功或按「取消」後選單收起，取消時不送出匯入、也不記訊息。
只有一個有欄名的工作表時直接匯入，文字檔不讀工作表清單。JET 自己匯出的科目配對範本另有分類清單，照舊直接匯入範本那一張；
JET 報告裡審計員在 Excel 看不到的中繼資料工作表不列進選單。
結果清單依序是「已儲存的科目配對」「分類留白，視為 Others」「本案沒有的科目」與「配對檔未列的科目」，名稱在左、科目數在右。
「已儲存的科目配對」旁邊是打開右側資料預覽的「資料預覽」，還沒匯入時寫「尚未匯入」；後三列整列可點，就地展開科目清單。
第一列在箭頭的位置留空。
分類留白的清單上方寫「可在「在 JET 配對」整批調整分類，或修改科目配對範本後重新匯入。」。
兩份差異清單依有效 GL 與 TB 的科目聯集比對，不把配對檔本身當成本案科目來源。
額外科目保留在配對檔，不會出現在篩選結果；未列科目不屬於任何分類，與留白視為 Others 不同。
畫面只顯示兩份清單的名稱與科目數，不附這兩句說明（裁定 2026-10-10-02）。
清單按需載入，可分頁與失敗重試；畫面重繪保留已載入頁，案件或資料變更後不沿用舊回應。
重開案件時先顯示「尚未核對」，不自動重掃 GL；點開清單才取得本次的科目數。
GL 還沒確認配對時，托盤只寫「GL 尚未確認配對，請先按「確認配對」。」。
Excel 檔有篩選或隱藏列仍會全部匯入。調換新舊範本的欄序時，先以確切欄名辨識，不因分類欄含 Name 而讀成科目名稱。

畫面先顯示 GL 分錄數、傳票數、借貸淨額與驗證摘要，再讓使用者以分頁查看差異或問題明細。
不重列查核期間，也不另外顯示納入與未納入的分錄摘要；明細可從右側資料預覽查看。
預篩選可在此執行，但它只是風險訊號，不是進階篩選的必要前置。
不在第四、五步頂端重複顯示結果過期的全頁黃框。驗證和預篩選各自執行、各自更新狀態，不能互相視為完成。
成功後清除對應旗標；資料變更只清相依結果，沒有執行過的程序不標成過期。案件載入最後採用後端旗標。
完整性差異保留為警示，已完成驗證即可繼續篩選與匯出；流程可繼續不等於完整性通過。
空白傳票號碼和空白科目編號各有明細、排序、搜尋與分頁。同筆同時缺兩欄時分別列示，不把兩類相加當作總分錄數。
資料缺漏輔助檢視只有這兩類；空白摘要只在預篩選的卡片與第五步條件出現，這裡不再另列明細頁。

完整性測試有兩項檢查。第一項是存入筆數與合計核對，確認 JET 存下的分錄沒有少、也沒有重複，明細兩欄是「確認配對時算出」與「存下後重新計算」的筆數、
借方合計及貸方合計；第二項是 GL 與 TB 逐科目比對。卡片與明細都寫明第一項不和來源檔自己的合計比對。判讀句寫「金額不符時，要確認 GL 分錄是否完整。」（裁定 2026-10-30-20）。
沒有 TB 也能往下做（裁定 2026-10-29-16、2026-10-30-16）：第三步只要匯入 PBC-GL，第四步只要確認 GL 欄位配對。沒有匯入 TB 時，逐科目比對寫
「沒有匯入 TB，無法執行 GL 與 TB 逐科目比對。」；已匯入 TB 但還沒確認 TB 欄位配對時寫「TB 欄位配對尚未確認，無法執行 GL 與 TB 逐科目比對。」。
只有第一項不符時，卡片狀態寫「存入筆數與合計不一致」，不寫泛稱的「未通過」。
有差異時的提醒開頭寫哪一項沒通過，例如「存入筆數與合計核對未通過：…」（裁定 2026-10-29-27）。
借貸不平測試逐張傳票檢查借方與貸方金額是否相等；判讀句寫「借貸不平時，要確認傳票號碼與金額欄位是否正確。」（裁定 2026-10-30-20）。
資料可靠性測試抽出分錄樣本，供審計員核對傳票附件及篩選欄位。說明寫明先確認攸關資料元素的可靠性，再到第五步進階條件篩選；這是審計作業順序，不是新增操作關卡。程式維持固定且可重現的抽樣，
不替審計員判定可靠性，也不增加額外門檻。ValidationReport 與 INF 報表照舊版範本，INF 報表的工作表仍叫「INF Testing 可靠性測試」；
畫面在報告清單標示用途並保留實際檔名，不在測試說明交代沿革；DPP 範本指引不改寫。

畫面金額維持兩位小數。完整性與借貸不平的非零差額若會顯示成 0.00，改寫「不足 0.01」並提示完整數字在驗證報告；負數差額仍標明是負值。
這只改畫面格式，不改差異判斷、報告或底稿精度。不存在或尚未執行的摘要顯示未知或原因，不把 null 當成 0。

畫面的「總帳日期空白」目前只列 PBC-GL 中總帳日期空白的來源列；這些列無法判斷是否在查核期間，因此列入
GL(未納入測試)。日期在查核期間外不列在這裡。既有 action 回應仍使用 `sourceQuality` 與 `blankGlDate`，畫面不顯示
內部分段名稱 Part A 或 Part B。

驗證完成後產生兩份驗證報告，並建立尚不存在的科目配對範本。範本已有檔案時保留，已填分類不會被
重新驗證覆蓋。畫面分別說明報告和範本的處理結果；其中一項失敗仍保留驗證與其他已完成輸出，可在
對應區塊重試。手動在「更多」選單選「重建科目配對範本」才覆寫原檔，選項下方明示會清空已填分類。取消後不啟動後續輸出。

科目配對範本的完整狀態顯示在「用 Excel 配對」分頁。正在準備或準備失敗時，預設的「在 JET 配對」分頁也在
科目清單上方顯示一行狀態。失敗時寫出原因並提供重試按鈕，按下後切到「用 Excel 配對」分頁，焦點移到
「準備科目配對範本」。已建立或已保留時只在 Excel 分頁顯示，不打擾直接在 JET 配對的審計員。

上方統計列的「GL 分錄數」指符合查核期間與過帳狀態設定的分錄，直接複述後端計數，不在畫面自行相減。
各步報告清單先顯示「資料驗證報告」「資料可靠性抽樣清單」「預篩選報告」「條件篩選報告」或「工作底稿」，
再列實際檔名、建立時間與大小，不重複展開完整路徑。使用者可按「開啟資料夾」定位檔案；遺失檔案停用定位，保留原有提醒。
報告列的按鈕垂直置中，窄版整顆換行，文字不被擠成直排。
重新開啟案件時，預篩選的定位說明使用目前版本的文字；原本保存的結果、不適用原因、計數、執行識別與日期都照原樣顯示，不回寫原紀錄。

預篩選規則無法執行時，狀態寫「無法執行」，狀態的滑鼠提示只顯示後端寫的原因，展開的明細在規則說明之後也只接這句原因；句子已寫出缺什麼、到哪裡補，
畫面不另接補救文字，完整性測試卡也一樣。
週末與假日兩張卡各含過帳與核准兩側。只缺傳票核准日的配對時，
狀態寫「總帳日期 N 筆，傳票核准日 —」，滑鼠提示與明細寫後端那句「只檢查了總帳日期。」再接核准日的原因，明細只能展開總帳日期那一側的分錄。
總帳日期那一側也不能檢查時，例如假日卡還沒上傳國定假日清單，整張卡無法執行。

資料驗證的「核准日不在期間」以傳票核准日判斷，說明寫「傳票核准日落在查核期間之外或空白的分錄。」（裁定 2026-11-05-38）。傳票核准日不可用時，狀態寫「無法執行」，原因的寫法和上一段相同，
不寫「通過」，也沒有分錄可以展開。傳票核准日選「與總帳日期相同」時照常檢查（裁定 2026-10-23-01）。

科目分類名稱輸入只更新本地草稿與就地提示，保留原輸入框及中文組字狀態；儲存、取消、新增與移除
才重建清單。儲存仍由 `accountCategory.save` 檢查名稱與穩定識別碼，並使預篩選及篩選命中失效。
打開分類層級的開關、再開啟進階設定後，角色與上層分類各有可見標籤及就近說明，窄視窗分列。
「科目配對」依序包含本案科目清單、分類設定入口及 Excel 批次操作入口；日常分類不需先開啟 Excel。
批次操作的填檔說明使用範本實際欄名 `Standardized Account Name*`，不只寫 C 欄。
「準備科目配對範本」保留既有檔案，旁邊提供「開啟案件資料夾」；填妥存檔後按「匯入科目配對範本」。
依目前資料重建科目配對範本的操作收在「更多」選單，明示會清空檔內分類。原有分類儲存、範本保存與覆寫行為不變。
預篩選區以「預篩選」為單一標題，兩項彙總後可展開「篩選結果」；不顯示「主要呈現」等額外標籤。
兩項彙總是「依分錄編製者彙總」與「較少使用之科目」；「較少使用之科目」的狀態寫 GL 裡有幾個科目，例如「500 個科目」。
「篩選結果」列八項：財報準備日起核准、摘要特定描述、未預期借貸組合、金額尾數連續 N 個 0、週末、假日、空白摘要與非授權編製人員。
N 是由 GL 借方平均算出的個數（裁定 2026-11-05-25）；卡片另寫「本次門檻：尾數連續 N 個 0。」。
未預期借貸組合的筆數與明細照舊版列出命中傳票的全部分錄，和預篩選報告的 R3 相同；這條規則的說明也寫明這一點，以及在第五步作為條件時符合的是收入貸方的分錄。
「篩選結果」與驗證規則清單的每一項只常駐名稱與狀態，狀態固定在右側。有明細的項目整列可點，箭頭在名稱前面，
點一下就地展開明細，再點一次收起；沒有明細的項目在箭頭的位置留空，名稱照樣對齊（裁定 2026-10-30-36）。
規則在檢查什麼，滑鼠停在名稱上時出現，展開後寫在明細最上方一次。清單很窄時，所有項目一起改成狀態在名稱下方。
規則說明不常駐在名稱下方（裁定 2026-10-29-02）。
兩項彙總並排、以細線分隔，兩格同高，內容從格子頂端排起，狀態一律在名稱下方。點開任一格，明細接在兩格下方、佔滿整寬，
開頭再寫一次是哪一項，另一格不會被撐高（裁定 2026-10-29-05）。
驗證與預篩選明細各自在區塊內顯示讀取狀態，總帳日期與傳票核准日兩側都會送出唯讀查詢。失敗可直接按「再試一次」；
同次讀取不重複發送，已完成表格的排序與分頁在收合再展開後保留。換案件、資料或執行結果後，舊快取與
晚到回應作廢。這些查詢不占用全畫面的作業遮罩，符合 `ActionExecutionPolicy` 的併行查詢分類。

分頁、搜尋、排序及未分類科目明細共用就地讀取流程。請求期間只標記該表忙碌，其他區塊可繼續操作；
失敗保留原有資料與頁面位置。重試使用失敗那次的排序及搜尋值，不偷偷改查另一頁。案件、資料版本、
執行結果或 DOM 已更換時丟棄舊回應。讀取狀態以 `role="status"` 與 `aria-busy` 提供，不移動焦點，
也不顯示沒有依據的進度百分比。此設計參考
[W3C 狀態訊息指引](https://www.w3.org/WAI/WCAG21/Understanding/status-messages)及
[Fluent 等待體驗](https://fluent2.microsoft.design/wait-ux)，實際結果仍由 JET 後端決定。

報告成功產生後，若清單刷新失敗或逾時，保留既有清單並加入新檔，在新檔旁提示可直接開啟案件資料夾，

### 5. 進階條件篩選

使用者建立條件情境，先預覽，再儲存。條件編輯器只產生後端接受的結構；不在 JavaScript 組 SQL 或
自行計算命中結果。預設用 `query.filterVoucherPage` 顯示傳票清單，展開時透過
`query.filterVoucherRowsPage` 取得該傳票查核期間內的完整分錄，每頁最多 200 筆。符合條件的分錄與
參考分錄分開顯示，各列指出符合第幾組第幾條主要條件。因整張傳票條件列入的分錄標為「整張傳票條件成立」，不新增逐列的另一套命中判定；只有命中傳票，沒有
待判定。傳票清單表頭可點排序，上方有「依傳票號碼查看」。原有命中列查詢仍保留相容入口。

傳票清單是同一張表（裁定 2026-10-30-37）。每張傳票是粗體的分組列，寫傳票號碼、總帳日期、「共 N 筆分錄」、「符合 M 筆」與傳票總額；
點整列就在這張傳票下方列出分錄，讀回之前先寫「正在讀取分錄…」，再點一次收起，同時只開一張，焦點留在列首的開關上。
分錄和傳票共用同一組表頭：傳票號碼後面是「項次」，分錄列在這一欄只寫傳票文件項次的數字，傳票號碼那一格留白；傳票列的項次留白（裁定 2026-11-02-01）。
接著是總帳日期、傳票核准日、會計科目、摘要、符合情形與金額，攸關資料元素的欄位接在最後。符合條件的分錄是淡藍底，參考分錄維持白底；分錄超過一頁時，分頁放在這張傳票的最後一列。
表頭可依傳票號碼、總帳日期、符合情形與金額排序。
每一列都只佔一行，分錄列和傳票列一樣高（裁定 2026-11-03-03）：符合情形把第幾組第幾條接在名稱後面，會計科目、摘要與文字型的攸關資料元素太長時以省略號收尾，滑過看全文。
只有分錄才有內容的欄，表頭先留好寬度，展開或收合分錄時欄寬不變。

第五步分為「篩選與檢視」和「已儲存情境」。切換只改畫面，不清除草稿、值或預覽。一般桌面寬度下，
左側選條件，右側調整本次篩選並看結果；窄視窗改成上下排列。配色依「畫面結構」的外觀說明。

左側可選「常用篩選條件」「預篩選」或「欄位條件」三個分頁，開案時停在「常用篩選條件」。三格依名稱長短分配寬度、不換行，名稱不省略；
為了放得下完整名稱，視窗寬 901 到 1100px 而且左右排列時，左欄是 240px；更寬時左欄佔工作區三成，在 280 到 420px 之間（裁定 2026-11-05-08）。
條件總覽只放一次加入一條條件的入口；整份組好的情境範例放在右側條件組合上方的「從情境範例開始」，見下方範例一段（裁定 2026-11-03-05）。

「常用篩選條件」分頁只放十個可以複選的常用條件，一列一個，按「加入」加入目前選取的條件組，按「已加入」移出（裁定 2026-11-05-08），
分頁上方不另寫小標（裁定 2026-11-03-20）。
名稱不寫 KCT，因為 JET 給所有審計員使用，不限於 KCT 小組（裁定 2026-10-29-10）。名稱前不加字母（裁定 2026-10-29-11）。
「在該季度前 X 天借記收入的會計分錄」納入曆年季底和查核期末，讀回列出合併後的日期區間。
「借記固定資產(PPE，不含在建)且貸記費用之分錄」已可加入，預設包含下層，兩側分類留待審計員選擇；
科目配對沒有非空白分類時仍列於「尚不可用」，分類留空時「尚需補齊」指出組號與條號。
這張卡加入後，條件列說明先新增並配對固定資產、營業費用，在建工程不能放在固定資產及其下層。
「貸方為收入但借方非一般對方科目之分錄」加入後，條件列說明「現金不算一般對方科目；要排除現金銷貨，改用預篩選條件『未預期借貸組合』。」
報告裡這項條件的讀回不變。
這兩段說明不寫在條件總覽的列上（裁定 2026-10-29-09）；列上只留名稱與「加入」或「已加入」，停用時另寫原因。
前五張卡的自動動機採用 KCT 小組的評估說明，每張卡一行；後五張沿用卡片名稱，已儲存及手改文字保留。
停用判斷和預篩選分頁相同：用到的 GL 欄位尚未選擇來源欄，或科目配對沒有需要的分類時停用，原因寫在名稱的下一行。
沒有匯入科目配對範本，和匯入了但沒有任何分類，同一張卡寫同一句。

「預篩選」分頁讓審計員直接套用預篩選條件（裁定 2026-10-16-09）。分頁列出十條規則：財報準備日起核准、摘要特定描述、未預期借貸組合、金額尾數連續 N 個 0、
週末過帳、週末核准、假日過帳、假日核准、空白摘要、非授權編製人員。
這十條和第四步的規則登錄在同一份清單（Domain 的 `PrescreenRuleDefinitions`），前端只鏡像一份。
編製分錄較少的人員與使用較少的科目不列在這裡，改用欄位條件分頁的「編製分錄較少的人員」與「較少使用的科目」（裁定 2026-10-29-27）。
「財報準備日起核准」同時列在這裡與欄位條件分頁傳票核准日的常用查法（裁定 2026-11-03-20）。
每列只有名稱和「加入」，按下就把那一條帶入目前選定的條件組，卡片仍是「預篩選條件」，之後也能在下拉改選；
那一條已在這一組時鍵寫「已加入」，再按一下移出（裁定 2026-11-05-08）。
分頁上方不另寫說明，每列的「加入」與停用原因已說明怎麼用（裁定 2026-10-29-02）。
規則需要的資料不足時停用，原因寫在該列下方，和第四步這條規則無法執行時讀同一張表、寫同一組句子：例如需要的 GL 欄位尚未選擇來源欄、
沒有期末財報準備日、未預期借貸組合的分類不足，或尚未匯入授權編製人員清單；缺好幾項時用「；」接起來。
沒有上傳國定假日清單時，假日過帳與假日核准也停用（裁定 2026-11-05-55）。條件卡片的樣態選單只列出能用的規則；已加入的規則變得不能用時，
選單照樣寫它的名稱，原因寫在卡片上。

「欄位條件」分頁依欄位列出，沒有新增條件下拉、目錄下拉或範例（裁定 2026-10-08-06、2026-11-03-05）。
欄位依資料型別分成日期、數字、文字、類別四組（裁定 2026-11-03-06、2026-11-03-18），四組寫在同一張白紙上，用小標分開，組與組之間一條細線；
一列一個欄位，名稱在左，右邊是「加入」（裁定 2026-11-03-32）。名稱只是文字，和預篩選分頁一樣靠左（裁定 2026-11-03-37）。
日期組是總帳日期、傳票核准日，數字組是金額，文字組依序是傳票摘要、會計科目編號、會計科目名稱、傳票建立人員、傳票核准人員、傳票號碼、
分錄來源模組與傳票文件項次，類別組是借貸別、人工/自動分錄與科目分類。已配對的攸關資料元素欄位依型別接在各組核心欄位後面，
滑鼠移到名稱上會寫出來源欄；和其他欄位同名時，名稱後面加上來源欄名。
按「加入」就在目前作用中的組加入一條該欄位的條件，焦點移到新條件；比較方式仍在右側條件卡片上選。有常用查法的欄位，這一條在「加入」打開的選單裡。
類別組的三列各加入一條原有的條件：借貸別預設借方，人工/自動分錄預設人工，科目分類只加入一條科目分類條件，分類留空待選，不預設借方，也不預設 Cash。

有常用查法的欄位，「加入」字後面接向下箭頭，按下打開和整列一樣寬的玻璃選單，打開時「加入」往下凹（裁定 2026-11-03-37）。
選單第一項寫欄位名稱，加入這個欄位的一般條件，和沒有選單的「加入」帶入同一條；下面隔一條細線列出這個欄位的常用查法，每一項寫短名稱。
每一項名稱前和「加入」一樣有灰色加號，加號和欄位名稱左緣對齊（裁定 2026-11-03-35）；滑鼠提示寫完整名稱，按下只加入那一條，選單隨即收起。
也可以在「加入」上按方向鍵下打開，再用方向鍵選、Enter 加入。「加入」都一樣寬，左右兩緣上下對齊。借貸別與人工/自動分錄沒有常用查法（裁定 2026-11-03-20）。
欄位已在作用中的組時，那一列照樣寫「加入」，按下再加入一條（裁定 2026-11-05-12）。
- 總帳日期：週末、國定假日、非營業日、日期區間、期末最後幾天。
- 傳票核准日：週末、國定假日、非營業日、日期區間、財報準備日起核准。
- 金額：大額、尾數連續多個 0。
- 傳票摘要：含特定字詞、空白。
- 會計科目編號：較少使用的科目。
- 傳票建立人員：編製分錄較少的人員。
- 科目分類：借方與貸方分類組合。

「尾數連續多個 0」加入一條金額條件，比較方式是「尾數連續」，預設第四步由 GL 算出的個數（裁定 2026-11-03-07、2026-11-05-26）。只看整數部分，忽略正負號與小數，
整數部分為 0 的金額不符合；個數可以改成 1 到 12。這種比較方式不看正負號，攸關資料元素的金額選它時不出現比較基準。
2026-11-03 以前加入的是「尾數 000000」且「金額絕對值至少 1 元」的子條件組，已儲存的情境照舊能讀，選到的分錄相同。
「含特定字詞」帶入傳票摘要的「包含任一文字」，預設使用第四步的 24 個字詞（裁定 2026-11-05-43），兩者都可直接修改。
「較少使用的科目」以科目編號計算分錄筆數，「編製分錄較少的人員」以傳票建立人員計算，預設都是小於或等於 11 筆。
「日期區間」與「大額」的起訖或門檻留空，加入後焦點直接移到要填的值；「期末最後幾天」由查核截止日往前帶入 7 天。

核心欄位一律列出。GL 還沒選擇來源欄的欄位，名稱變灰，「加入」不能按，有常用查法的名稱也打不開選單，「加入」和其他停用按鈕一樣是灰底灰字。
分頁最後用一句話列出這些欄位，例如「「傳票核准日」「傳票建立人員」尚未選擇來源欄，請回第三步欄位配對補上」（裁定 2026-10-22-05）；
人工/自動分錄要 GL 的人工/自動分錄欄位，科目分類要科目配對已有分類，缺的時候同樣停用，原因接在同一段，用「；」接起來。
傳票文件項次沒有來源時由系統自動編號，傳票核准日選「與總帳日期相同」時由總帳日期帶入，兩者都算已配對。
欄位能用、但常用查法另有前置條件時，例如沒有期末財報準備日，那一項在選單裡停用，原因寫在那一項的下一行，判斷和句子都和預篩選分頁相同。
沒有上傳國定假日清單時，總帳日期與傳票核准日的「國定假日」常用查法也停用，「非營業日」照常可用（裁定 2026-11-05-55）。
欄位與常用查法都加入目前選定的條件組，多組時用條件總覽標題同一列的「加入到第 N 組」選擇目標。
查看全部分錄改由右側資料預覽選「GL」，第五步頁首不另設捷徑按鈕。
每一組標頭直接提供「子條件組」與「整張傳票」兩個按鈕，名稱前是灰色加號；只有一組時也顯示。
報讀名稱寫完整，例如「在第 1 組加入整張傳票條件」（裁定 2026-10-30-32）。
子條件組把其中條件放在一起判斷，仍比對同一筆分錄，不改條件連接順序。

情境範例放在右側條件組合上方的「從情境範例開始」（裁定 2026-11-03-05）。預設收起，按標題打開，同一次開案內記住開合（裁定 2026-11-03-19）。
打開後清單上方寫「套用後會替換目前的條件。」清單只列名稱，動機放在滑鼠提示。共有十一個範例：
「借現金、貸非現金」「貸現金、借非現金」「非營業日且排除指定日期」「期末最後 7 天的人工分錄」「空白摘要或空白核准人員」
「特定人員的大額分錄」「週末人工分錄的特定摘要」「人工分錄的特定部門」「借方與貸方科目編號組合」「指定借貸科目組合的大額分錄」
及「財報準備期間的人工假日分錄」。
「週末人工分錄的特定摘要」「人工分錄的特定部門」「指定借貸科目組合的大額分錄」與「財報準備期間的人工假日分錄」由 2024 篩選表的範例轉入，
條件與示例值照原範例；原範例 4 和「金額尾數連續多個 0」重複，不另列。
「借方與貸方科目編號組合」是借方與貸方各一個整張傳票條件，科目編號由審計員填入（裁定 2026-11-03-08）。
套用會替換本次條件，名稱就是範例名稱，遇到已儲存的同名情境才附數字，並帶入可改的動機，左側條件總覽停在原本的分頁；
範例用到的欄位或資料不足時停用並在下方寫原因，判斷和欄位的常用查法相同，同一個範例缺好幾個欄位時合成一句。
例如「空白摘要或空白核准人員」需要傳票核准人員已配對，「財報準備期間的人工假日分錄」需要期末財報準備日、
傳票核准日與人工/自動分錄已配對，也要國定假日清單與補班日清單（裁定 2026-11-05-55、2026-11-05-66）。
「人工分錄的特定部門」需要一個文字型攸關資料元素欄位：沒有時停用並寫「需要先在欄位配對加入部門等文字欄位」；
只有一個時直接帶入；兩個以上時就地列出欄位按鈕讓審計員選，按「取消」或 Esc 不改動草稿。
正在編輯已存情境時套用範例，會成為另一個新情境，原情境不動（裁定 2026-10-07-09）。
兩個現金範本和新建的分類條件一樣，選取方式是「包含下層分類」，也就是 Cash 加上它底下的所有分類；Cash 沒有下層分類時就是 Cash 本身。
「非營業日且排除指定日期」把「非營業日之分錄」與排除日期放在同一個條件組，依序是第 1 條與第 2 條。
範例或草稿還有條件沒填值時，預覽前的「尚需補齊」會寫出第幾組第幾條與條件名稱，例如
「第 1 組第 2 條「總帳日期」請填 1 到 100 個值」；子條件組裡的子條件寫成「第 1 組第 2 條的第 1 項」。
值清單超過上限時，逐條寫出位置，請審計員拆成每條不超過 100 個值，再放進子條件組，用 OR 連接；否定清單則用 AND 連接。
子條件組的連接在畫面上只寫 AND 與 OR，所以提示不再寫「任一符合」「全部符合」（裁定 2026-10-30-32）。
套用範例後，焦點移到第一個要填的欄位，JET 不代填任何值。範例值可修改，不從目前資料猜科目、部門或審計理由。

多值輸入在框旁說明分隔方式。值清單是固定五行高的輸入框，放在符合或排除與比較方式的下方；貼上或拆成多行時高度不變，
內容較多時在框內捲動，審計員可自行往下拉高。清單下方顯示「已輸入 N 個值」，輸入時就地更新。
`fieldValue` 清單沿用 100 個值上限並顯示上限；特定人員、特定摘要與特定尾數三張卡改用相同欄位條件，也採用這個上限及拆組提示。
N 與實際送出的清單相同，去掉空白與完全相同的重複值；尾數清單使用相同計數方式。摘要關鍵字、尾數、每月幾日、人員代號與科目編號可用換行、逗號、全形逗號、頓號或 Tab；
其他文字值清單一行一個，值內逗號保留。人員或科目編號本身含這些分隔字元時不能用來代表單一值，輸入前須確認代碼格式。
只收一個值的開頭、結尾等比較，貼入多行時提醒；金額和出現次數先檢查格式，絕對值基準的負數只提醒，不禁止送出。
指定日期接受 GL 相同的明確格式與案件的民國年開關，未知的寬鬆格式仍交後端判斷，不用瀏覽器猜日期。
整張傳票條件只選量詞，要限定方向時加入「借貸別」子條件。分類與欄位條件不附帶方向，也不從外層繼承方向。
子條件中的人員和科目編號預設完整值清單；科目分類只提供屬於與不屬於。
已儲存條件的選項暫時不能用時，保留目前值並說明原因，不默默顯示第一項。預篩選條件「未預期借貸組合」的停用條件和第四步相同。

每條條件右上方都有「移除」，不再用家族小標與叉號辨識操作。一般草稿不另顯示「本次篩選」與未儲存提示；
編輯已儲存情境時仍顯示情境名稱。欄位、借貸別與人工/自動分錄的名稱固定，列內只調整其值（裁定 2026-11-03-22）。
科目分類只選屬於或不屬於指定分類，不另選借方科目或貸方科目。要查整張傳票沒有某側分類，
另加「不存在符合」的整張傳票條件，子條件選借貸別與科目屬於指定分類。借貸組合依序顯示查找方式、借方分類與貸方分類，
不用 A、B 對照。排除側明寫「整張傳票不得有這些借方分類」或貸方分類；展開「查找說明」後，可查看結果列出哪一側分錄、卡片的補充說明及分類留白的處理。
「借方是 A 且整張傳票沒有 B 貸方」照舊版也標記同一張傳票貸方那一側的全部分錄，提示寫「輸出 A 借列與同傳票所有貸方列。」，
查找說明寫「整張傳票沒有這些貸方分類時，結果列出符合的借方分錄及同傳票全部貸方分錄。」；
反向的「貸方是 B 且整張傳票沒有 A 借方」兩句的借貸對調（裁定 2026-11-05-45）。五種查法的查找說明各自不同。
分類選項可換行，各區留出間距。
風險樣態的對象是預篩選條件、科目與人員統計，以及常用篩選條件卡片專用的條件。摘要關鍵字、空白摘要、特定人員與尾數都使用欄位條件。
條件列的樣態下拉只列同一個來源的條件：從預篩選加入的只列預篩選條件，從常用篩選條件加入的只列卡片專用的條件，選項寫卡片名稱；
自訂的樣態條件只有一種時不放下拉，列標題已寫出名稱（裁定 2026-10-30-30）。
常用篩選條件那一列換成另一張卡時，條件記成新的那張卡。

同組有兩條以上條件時，第一條分隔線上是 AND、OR 兩格的分段切換，只寫 AND 與 OR（裁定 2026-10-30-32），前面不寫「組內條件」（裁定 2026-11-01-07）。
後面分隔線上的字就是這個切換的值；滑過或用鍵盤移到切換時，這組其他分隔線的字與線一起變成重點色，看得出切換控制的是組裡條件之間的連接。
組內不顯示「主要條件」「設為主要條件」或「同一傳票」標記。要查其他分錄是否符合，使用整張傳票條件。
「條件組」按鈕在條件組合標題列，名稱前是灰色加號，報讀名稱是「新增條件組」；空的組寫「從條件總覽選條件加入。」。
每組都有「清除」，只清該組內容，保留其他組與手寫的情境名稱、動機；空組時停用。
多組時仍提供「移除」，可報讀名稱指明各按鈕的條件組。兩組之間是一條橫線，AND、OR 兩格的分段切換接在線上，和「第 N 組」同一條左緣，
線比組內的分隔線深一階（裁定 2026-11-05-16）；切換前面不寫字樣，滑過或用鍵盤移到切換時線變成重點色（裁定 2026-11-01-07）。
螢幕報讀仍讀得到「組與組之間的關係」。分隔線用框線畫，高對比佈景時仍看得到。
這些操作只改目前草稿，不直接修改已儲存情境。
多條條件的完整摘要保留實際括號與順序。

欄位條件先選「符合」或「排除」，再選篩選方式及值（裁定 2026-11-03-10）。日期方式包含指定日期、日期區間、每月幾日、日期先後、
空白日期、每月月初幾天、每月月底幾天及查核期末最後幾天；文字包含關鍵字、完整內容相同、開頭、結尾及空白內容。
金額分指定金額、金額區間、高於金額、低於金額及空白金額。
篩選方式選單依類別分組並加小標：日期分成指定日期、每月固定日、週末與假日，以及空白，金額分成指定金額、特定數字、尾數與空白，
文字分成比對文字與空白（裁定 2026-10-30-31）。週末與假日這組的選項叫「週末」「國定假日」「補班日」「非營業日」，
讀回寫「總帳日期 在國定假日」這類句子；選到後選單下方只寫那一項的來源與本案的資料，例如「第二步上傳的國定假日清單，共 N 天」
「第二步設定的每週休息日：六、日」「週末或國定假日，補班日除外」（裁定 2026-11-03-10）。
沒有上傳國定假日清單時，「國定假日」停用，名稱後面寫原因「尚未上傳國定假日清單，請先在第二步「國定假日與補班日」上傳」（裁定 2026-11-05-55）；
沒有補班日清單時，「補班日」同樣停用，原因寫「尚未上傳補班日清單，請先在第二步「國定假日與補班日」上傳」，和舊版一致（裁定 2026-11-05-66）。
已存的情境用到這些條件時，驗證寫同一句原因，比照未配對的欄位。「非營業日」也看週末，沒有清單時照常可用。
金額與攸關資料元素數值欄位的「特定數字」組只有一項「整數部分的特定數字」，比較方式是「整數部分包含」與排除的「整數部分不包含」（裁定 2026-11-05-46）。
值和整數尾數一樣用逗號分隔，每串 1 到 12 位、最多 100 串，不接金額比較基準。
說明寫「只看整數部分，忽略正負號及小數。」，再接分隔方式與例子「例如 -12,888.45 的整數部分是 12888，包含 888，也包含 28。」

主要方式已涵蓋原有運算子；開啟原有情境時不會默默轉換原規則。

文字欄位的否定比較，也就是不等於、不包含任何文字、開頭不符合、結尾不符合與不在清單中，預設勾選「此欄位空白的分錄也列入結果」，審計員可以取消；

審計員改寫過的動機整段列出（裁定 2026-10-30-02）。存進情境與寫進底稿第三步的動機不變，只有畫面的列法不同。
標題下方不另寫 GL 範圍，第五步上方已說過。
已儲存條件與編輯時共用完整說明，直接用「且」或「或」連接；只有表示實際分組時才加括號。
新建欄位條件在畫面與新產生的底稿都將區間寫為「介於」，金額基準直接寫在欄位名稱後，不再附「含兩端」或括號旁註。
區間仍包含起訖值，空白處理、借貸語意與條件結合順序不變；既有已匯出檔案不會被改寫。
高風險條件彙總用淡底小標籤「查看彙總」就地展開（裁定 2026-10-30-34），可切換「符合條件摘要」與「傳票符合的條件」，只顯示及載入選中的表。
彙總不提供分錄明細頁籤，分錄明細由審計員在底稿檢視（裁定 2026-10-16-05）。「傳票符合的條件」的條件欄表頭只寫 C1、C2 等代號，
停留可讀完整情境名稱，名稱對照在「符合條件摘要」；勾選和代號一起靠左。十個條件的表因此在一般桌面寬度不必橫向捲動
（裁定 2026-10-16-02）。原有位置對照、排序、搜尋與分頁查詢保留。條件篩選報告可在「已儲存情境」獨立產生，不是匯出底稿的前置。
離開已儲存工作區後，重繪條件區不會載入隱藏的彙總。「傳票符合的條件」使用既有允許併行的唯讀查詢，
產生報告時重建畫面也能載入資料。取消或確認移除後，焦點回到最新清單中的可見查看按鈕。

欄位按日期、金額、人員、會計科目及其他文字分組。人員預設使用完整識別值清單，可符合或排除，
不將姓名與員工代碼自行互換。「科目與人員統計」另外選對象、分錄筆數或傳票張數（同號只算一張）、比較方式與門檻。
統計以 GL 為準，條件讀回寫成「GL 中」。尾數條件的讀回寫「金額整數部分（不含小數）末 N 位 = 樣態」。
日曆條件可選週末、假日、補班日及非營業日；金額可選整數特定尾數；文字可排除指定開頭或結尾。
這些計算說明使用一般提示色，實際錯誤才用錯誤樣式。精確規則見 `jet-guide.md` 第 6 節。

JET 更新篩選規則後，不要求審計員逐案重新儲存情境（裁定 2026-10-02-05）。開啟案件時，JET 先用目前的規則逐一檢查已儲存的情境；
已是目前規則版本的情境也一樣檢查（裁定 2026-10-13-25），所以分類或欄位配對改變後不合格的情境，開案時就會列出。
全部仍然有效時，自動改用新規則並清掉舊的命中，畫面顯示一則提示，說明已用新規則重新計算幾個情境，
先前的條件篩選報告與底稿已標為過期；第一次查看命中或匯出時，JET 才用新規則重算。
只要有一個情境不符合目前規則，開案時整批都不動。第五步上方的「GL：查核期間內的分錄」區塊逐一列出是哪個情境、哪裡不符合，
請審計員到「進階條件篩選」修改後儲存。GL 不是依查核期間建立、規則版本無法辨識，或條件內容讀不出來的情境，也列在這裡，不自動改版。
每個原因只寫哪裡不符合，例如「此條件使用的欄位已不存在」；條件內容損毀的情境不論有幾條，只寫一次「條件內容無法讀取」。
儲存時條件內容損毀，那一條條件下方寫「此條件內容有誤，無法儲存。請刪除此條件後重新設定。」。
這些情境可以一個一個修改或移除（裁定 2026-10-13-24）：儲存或移除一個情境時，其他情境照原樣保留，
改好或刪掉的情境從清單消失，改沒問題的情境也不會被擋。全部處理完之後，JET 才改用目前規則，
高風險條件彙總、完整命中和條件篩選報告才會顯示，第六步也才能匯出。
「重新檢查並儲存情境」按鈕用目前規則重新檢查全部情境：能套用的改用目前規則，還不能套用的照原樣保留並留在清單上，
不會因為其中一個不合格而整批失敗。完成後訊息說明更新了幾個、還有幾個要修改。

### 6. 匯出底稿

使用者選擇報告並啟動匯出。進度事件只顯示正在準備、寫入或發布哪一部分；只有 action 成功回應才
顯示完成。報告清單每筆顯示檔名、時間與大小；檔案在 JET 之外被改過或已不存在時，多一個狀態標示
（「已在 JET 之外修改」、「檔案不存在，重新匯出即可」），只提醒不阻擋。工作底稿每次匯出新增一個版本檔；第六步的「工作底稿版本紀錄」列出全部版本，最新在上，每頁最多 50 份。較早資料或
條件產生的底稿標示「先前資料或條件的版本」；這些紀錄不影響目前流程是否完成。按「開啟資料夾」
會在檔案總管選取該檔，讓使用者自行開啟；已刪除的版本保留提醒並停用這個按鈕。重新匯出後立即保留
新舊兩筆，不必重新開案。科目配對範本由第四步的卡片產生，不在這份清單裡。
流程總覽第六階段的「檔案大小」和報告清單一樣以兩位小數的 MB 顯示，不顯示位元組數。

匯出前列出採用的情境及條件儲存時間。每個情境選項下方寫動機，列法和第五步的已儲存情境相同；沒有要列的動機時，改列條件本身。
有可用的驗證結果即可進入第六步，不要求已儲存情境或另一份報告檔存在。沒有已儲存情境，
或有情境但一個都沒勾選時，也能匯出底稿（裁定 2026-10-29-16、2026-10-30-15）；這兩種情況的底稿第三步與第四步留空，匯出按鈕不停用，也不提示先儲存情境。
第五步算完成的條件是已儲存可用的情境，或已經匯出目前版本的工作底稿。
底稿匯出讀儲存情境時存好的結果；結果標成過期時，才先用目前資料重新計算（裁定 2026-10-30-33）。
條件篩選報告尚未產生、過期或被刪除，都不阻擋底稿；不會順便重建該報告。
新增篩選條件的完整說明一併寫入底稿，未儲存的草稿不會納入。第五步還有尚未儲存的條件時，畫面才提醒
「「進階條件篩選」還有尚未儲存的條件，儲存成情境後才會納入底稿。」，其他說明不常駐（裁定 2026-10-29-02）。
已儲存情境無法套用目前規則，
而且還沒有任何工作底稿版本紀錄時，第六步維持鎖定，流程、總覽與步驟檢查都寫「修改無法套用目前規則的篩選情境」。
已有版本紀錄時可以進入查看，畫面照舊逐筆列出無法套用的情境，匯出按鈕停用。
匯出頁與總覽都以目前版本的工作底稿表示完成，不要求條件篩選報告同時存在。

清單即將超過 4,096 筆時，JET 才整理已確認檔案不存在的底稿紀錄；現存或無法確認的檔案紀錄會保留，
不刪除任何實體底稿。發布前再次確認檔案狀態，仍超限就提示自行整理舊底稿後重試。匯出成功後立即
同步整理後的完整清單。

### 各步明細表的分頁、排序與搜尋

明細表每頁最多 200 筆，超過一頁時表格左下方只有左箭頭、`目前頁數/總頁數`、右箭頭；第一頁停用左箭頭，最後一頁停用右箭頭。
只有一頁時不顯示分頁列，第一頁讀到之前也不先顯示空的頁碼。第六步的工作底稿版本紀錄一頁 50 份，換頁也用同一個分頁外觀。
總頁數依後端的完整查詢總筆數計算。後端只在第一頁計數，換頁時沿用第一頁的總頁數；搜尋或排序後回到第一頁，總頁數隨結果更新。
畫面只保存當頁資料和已走過的游標，不累積整份明細。

完整性差異、借貸不平、資料缺漏輔助檢視、總帳日期空白、抽樣樣本、預篩選命中、篩選命中、「傳票符合的條件」與命中
傳票清單的表頭可點排序，點一下升冪、再點一下降冪，箭頭標示目前方向；表上方有「依傳票號碼查看」輸入框
（科目層的表是「依科目編號查看」），送出後只留含該文字的列，按「清除」還原。換排序或搜尋時清掉列從
第一頁重載。排序與搜尋先在資料庫對完整查詢範圍執行，再取當頁資料，空值排最後；未提供完整資料排序的預覽表不放排序按鈕。
第四步因其他狀態更新而重繪時，一般明細、INF 樣本及預篩選明細保留目前頁、游標、排序、搜尋、展開狀態與捲動位置。
讀取失敗也保留已載入內容，重試接續原位置。切換案件、重新開案或產生新結果後才丟掉舊分頁；晚到回應不能寫入新案件或新結果。
缺傳票號碼與缺科目編號分開呈現，各自排序、搜尋與分頁；同筆同時缺兩欄會分別出現。
兩類均可搜尋傳票號碼、科目編號或摘要，搜尋失敗保留原結果並可重試。表頭明示總帳日期，不泛稱日期。
「核准日不在期間」等異常明細在展開時直接查詢該類別的第一頁，不從混合摘要樣本推斷有沒有資料。
完整性測試的「核對項目」表只呈現核對數字，表上方不另放說明段落。
表格正在讀取時按「查看」或「清除」不會被忽略：畫面說明會在讀完後接著執行，只保留最後一次要求；
目前的讀取成功或失敗後都會接著執行，失敗後也可以再按。

- `wwwroot/js/state.js` 保存目前畫面、案件 metadata、摘要與 request id，不保存完整 GL／TB。
- 下一步是否可用，以後端結果與 `ui-core.js` 的單一進入條件檢查呈現為準。
- 切換步驟可以保存位置，但不能把「看過某頁」誤寫成「業務條件已完成」。
- 上游資料、mapping 或規則版本改變後，前端不沿用舊結果；結果清除與重新執行的狀態依實際相依關係處理，不加全頁重跑警語。
- Background response 必須確認仍屬同一案件與同一 request，不能覆寫後來載入的 state。
- 通知慣例（整個前端唯一）：凡是會改變任何衍生畫面輸出的 store 寫入一律
  bump（`contentVersion` 進版、面板重建）；「只 notify」僅限「唯一視覺反映就是使用者正在編輯的
  那個控制項本身」的連續文字輸入，且必須在 blur 後延遲一次 bump 收斂。select／radio／checkbox
  是離散提交，永遠直接 bump。重建後的輸入焦點與捲動由 `app.js` 的 `renderContent` 依焦點識別
  屬性與 `data-preserve-scroll` 標記統一還原，步驟模組不得各自發明保留機制。已文件化的
  例外包括 filter-step 的規則值編輯、科目勾選和拖曳的暫時選取，以及欄位配對的借方代碼與攸關資料元素
  顯示名稱。這些操作就地同步相關控制項，避免重繪打斷輸入、指標捕捉或滑鼠點擊；
  真正套用分類和保存資料仍依 Store 更新。不能把是否呼叫 bump 當成是否完成業務程序的判定。
  守衛測試：`tools/tests/frontend-journey-mapping.test.cjs` 在第三步畫面上檢查重繪次數、焦點、捲動與連續輸入。

欄位配對裡必填欄位的標示與「確認配對」按鈕都由同一份 draft 推導。文字輸入就地更新兩者，不重建；下拉選擇會立即 bump。
中央內容重建後，`app.js` 把焦點放回重建前的同一個控制項，並還原 `data-preserve-scroll` 容器。
控制項有 `data-focus-key` 時照它找；沒有時，比對所在區塊的 `data-motion-key`、元素種類、名稱、無障礙標籤與不會變動的 data 屬性，
同樣條件的按鈕再加上去掉數字後的按鈕文字。重建前後都只對到一個控制項時才還原，對不到或對到好幾個就不移動焦點。
這避免表格上方仍寫著還有欄位沒選、按鈕維持停用，或重繪把焦點送回錯誤控制項。

按下的控制項在重建後不見或停用時，步驟模組用 `JetFocus.deferFirst` 把焦點交給接替它的控制項。
例如第五步移除一條條件後，焦點移到下一條的「移除」，沒有下一條時依序是上一條、所屬的子條件組與條件組；
第一步、第二步與第三步的編輯、取消與確認，也各自把焦點交給換上來的按鈕或第一個輸入框。
執行中整個中欄暫時不能操作，結束後焦點回到按下的控制項。第四步的「篩選結果」記得有沒有展開，重建後維持原狀。
這些焦點處理的做法見裁定總表 2026-10-13-01。

延後移動焦點（`JetFocus.defer`、`deferFirst` 與換步驟時交給步驟標題）排在下一輪，電腦忙時會晚到。
在這之前使用者已經自己點進或用鍵盤移到別的控制項時，焦點留在原處，延後的移動不做，免得接著輸入的字落到別處。

控制項也可以自己宣告接替者：`data-focus-successor` 寫選擇器清單，用分號隔開。中欄重建後原控制項不見時，`app.js` 依序找第一個可見、
可按且不在退場動畫裡的接替者，把焦點交給它並捲進畫面；原控制項還在就照上面的規則放回去。第三步的兩顆「讀取來源值」按鈕用這個方式，
依序是「讀取來源值中…」的提示、讀取失敗的「重新載入」、讀出的值清單第一個選項，最後是清單本身；提示與清單用 `tabindex="-1"` 拿焦點，
不進 Tab 順序。既有的 `deferFirst` 呼叫保留，新按鈕用宣告就好。

## 診斷日誌

「狀態與訊息」只加入 info、warn 或 error 等級的非空白文字，未指定等級時使用 info。
error 是操作失敗，warn 是需要注意，info 是一般說明與完成紀錄（裁定 2026-10-13-15）。
後端 `log.append` 與三種資料庫的訊息紀錄表接受同樣三個值。
開案讀回訊息時，不認得或缺少的等級一律當一般訊息顯示。
後端拒收格式錯誤的訊息時，先記入去識別支援日誌，前端再跳過該筆，繼續保存後面的訊息。
作業進行中先不寫入，作業結束後依序寫入，不和作業搶資料庫。
忙碌、資料庫或傳輸失敗仍保留原筆重試，不當成已保存；切換案件後不把舊案訊息寫入新案。

長操作成功時只留一則完成訊息，耗時接在完成句後面，例如「已在案件資料夾產生工作底稿（12 張工作表），耗時 4.2 秒。」；
沒有自己完成句的操作寫「重建科目配對範本完成，耗時 4.2 秒。」這類句子。
失敗與取消時把耗時寫在括號裡，有進度時再接最後進度，括號後加句號，例如「產生工作底稿失敗：原因（耗時 4.2 秒，最後進度：工作底稿正在寫入「工作表」，已完成 3 張工作表、寫入 1,500 列）。」；
最後進度不再重複耗時，接進訊息時拿掉「工作底稿：」的冒號，按「取消作業」後的「當時進度」也一樣（裁定 2026-10-14-01）。後端判定前置條件還沒完成時寫「產生工作底稿尚無法執行：原因。」，
另一項作業還在進行時寫「另一項作業還在進行，請等它完成後再試。」，這兩種都沒有開始做事，所以不附耗時；長作業的耗時規則見裁定 2026-10-13-17。
耗時不到 60 秒寫一位小數的秒，四捨五入是 0.0 秒時寫「耗時不到 0.1 秒」，60 秒以上寫「2 分 51 秒」，一小時以上寫「1 小時 3 分」；
產生報告或工作底稿時，忙碌遮罩上的進度每個階段一句，例如「工作底稿：正在寫入「工作表」，已完成 3 張工作表、寫入 1,500 列，經過 4.2 秒」，
經過的時間也用同一種寫法（裁定 2026-10-13-17）。

- 「輸出支援日誌」是去識別紀錄。訊息面板的按鈕在 Release 也有，匯出目前案件的紀錄；案件清單頁尾的按鈕
  只在 Debug 組建出現，不帶案件，匯出全部紀錄到 logs 資料夾，案件還沒開啟時也能用。
- Debug 的「DEV — 診斷日誌匯出」保留較完整的原始紀錄；面板版要先開啟案件，案件清單頁尾的
  「輸出診斷日誌（DEV）」則不用，並帶該次失敗的 correlation。畫面明示內容可能含案件資料。
- 支援日誌由後端寫入目前案件目錄或 logs 資料夾，診斷日誌寫入案件目錄。前端不接受任意路徑，也不自行組合或過濾 NDJSON。
- 非預期的錯誤（錯誤碼 `bridge_error`）在畫面上只顯示固定訊息「發生非預期的錯誤，此操作未完成。請再試一次。」，
  不顯示例外原文、本機路徑或例外型別；
  錯誤碼與 correlation 照舊回給畫面。後端已知的錯誤照舊顯示原本的中文訊息。

## 作業、取消與關閉

長作業一次只允許一項會改動案件資料的操作。前端顯示 busy 狀態與取消入口；`operation.cancel` 只表示
已提出取消，最終結果仍看原 request。
取消送達時若資料庫正在執行語句，三種資料庫都會中斷它，不等它跑完；原 request 以 `operation_cancelled` 結束。
檢視與預覽來源，以及各項匯入都能取消。逐檔檢視取消時停止剩下的檔案，保留已檢視的清單，不把取消當成讀檔失敗後繼續。
若串接作業的前一階段已完成，取消只停止後續步驟，畫面明說已完成的結果仍保留，不宣稱整串作業都已回滾。

案件清單保留 `project.json` 無法讀取或解析，以及本機資料庫檔不見或是 0 位元組的案件（裁定 2026-11-05-72），顯示下一步而不假裝資料庫種類為 SQLite。
使用者可以先檢查檔案是否被鎖住，或從備份復原；損壞時也可另建案件重新匯入，其他正常案件仍可使用。
開始填寫建案表單後，背景資料庫設定結果只更新 SQL Server 選項是否可用及其提示，不重建表單，不替使用者切換已選的資料庫。
未知狀態不等於未設定；確認未設定時停用選項並說明改選 SQLite 或 DuckDB，之後確認已設定時重新啟用。晚到的案件清單回應仍由離開首頁的守衛忽略。

離開案件或關閉視窗時，要先停止新 request、處理在途作業並釋放案件鎖。畫面不能因為 Bridge 尚未
回應，就自行假設鎖已經釋放。
退出不自動儲存草稿；只有第四步還有未儲存的科目分類時，才先跳出「科目分類尚未儲存」確認框。
