# JET 程式修訂紀錄

## 首次評估範圍

JET 尚未正式發布。目前的功能與修正合併視為同一個首次評估版，不把開發期間每次推送列成發布版本。

| 範圍 | 本次內容 |
|---|---|
| 案件與資料 | 使用 SQLite 建立本機案件，匯入總帳與試算表並確認欄位配對。 |
| 審計作業 | 完整性、借貸不平、空白資料及可靠性測試，並提供預篩選與條件篩選。 |
| 報告與底稿 | 產生 Excel 報告；正式底稿保留歷次匯出。 |
| 本輪修正 | 可靠性樣本預設 59 筆，可自行調整。借貸別配對標示「借貸代碼至少填一個」。 |
| 底稿文字 | 分錄編製人員說明 A4 改為「此處底稿係記錄分錄編製人員資訊」；資料預先整理之說明 A3 留白。檔案欄位資訊不再由程式寫入 V.2019。 |
| 條件篩選 | 第五步文字欄位的「開頭符合」「結尾符合」改成和「包含任一文字」一樣，一條條件可填多個值，最多 100 個。多個值可用換行、半形或全形逗號、頓號與 Tab 分隔。符合任一個就算；選排除時，每一個都不能符合。以前存下的條件只有一個值，程式照原樣讀成一個值，不拆逗號與換行，所以命中不變。 |
| 底稿欄標與說明 | 底稿 Step 2 的 L51 欄標，只在配對了傳票核准人員時改成「傳票核准人員」，L 欄寫核准者；沒有配對時保留範本原字，L 欄留空給審計員自行填寫。資料可靠性抽樣清單的 L51 照同一個條件。Step 4 A12 說明空白傳票號碼的那一句改寫進範本，主表的 A12 不再由程式另外接上；接續的工作表由程式寫出同一句。 |
| 底稿下拉選單 | 下拉選單改回範本原本的選項，不再換成「Y,N,N/A」。Step 2 的 M 到 S 欄是「相符,不符合,N/A」，B 欄測試程序的「V,NA」選單也保留。Step 4 的 P 到 R 欄是「v,no,n/a」，S 欄是「Yes,No」。樣本或傳票多於範本列數時，只把結束在範本最後一列的選單往下延伸，Step 2 B 欄的選單不變。 |
| 底稿保護與鎖定 | 工作表保護改照舊版的範圍，都不設密碼。受保護的是 Step 1、Step 1-1、Step 1-2、Step 1-3、Step 3、Step 4 與三張自動化工具表。Step 1-1 只在有借貸不平的傳票時保護，Step 1-2 只在有編製人員時保護。Step 2 與 Step 4-1 改成不保護。受保護的工作表只鎖程式寫入的資料區。資料列在鎖定欄裡沒有值的格子也一起鎖定，例如 Step 4 沒用到的條件欄，以及 Step 1-2 沒有人工或自動可寫時留白的 C 欄；其他留給審計員填寫的空白格不鎖。三張自動化工具表整張鎖定。程式不再給可以填的格子加淡黃底。 |
| 和舊版鎖定的差異 | 舊版的 Step 1-2、Step 1-3 與 Step 4 會比最後一筆資料多鎖一列空白列，JET 只鎖到最後一筆資料。資料超過一張工作表的列數上限、寫到接續的工作表時，資料區以外沒有值的格子仍照 Excel 預設鎖定。 |
| 欄位資訊頁 | 資料驗證報告的「自動化工具-檔案欄位資訊」拿掉 TB 與 GL 標題列的合併儲存格，和工作底稿的同名工作表一樣都不合併。舊版會合併標題列，這是刻意和舊版不同的地方。 |
| TB 匯入說明 | TB 和 GL 走同一條匯入程式，可以一次選多個欄位相同的檔案、工作表或資料表，合併成一份 TB，共用一份欄位配對。同一科目出現在多個檔案時每一列都保留，逐科目比對先把變動金額加總再比。TB 的畫面說明改成和 GL 相同；合併與比對的程式沒有改。 |
| 欄位不一致的訊息 | GL 與 TB 匯入時，若某個來源的欄名和其他來源不同，追加與一次匯入多個檔案都顯示同一句：「檔案「檔名」的欄位與其他來源不一致（來源多出：…；來源缺少：…）。本次未匯入，先前匯入的資料不受影響。請先在 Excel 把欄位對齊後再匯入。」追加時不再提示改用取代匯入。只改訊息文字，比對欄名的規則不變。 |
| 捲動效能 | 電腦上有讀屏軟體或其他程式透過 Windows 的 UI Automation 讀取畫面內容時，捲動 JET 的畫面會頓一下。原因是標題列的玻璃、流程軸線與目前步驟的圓環，畫在包住整個畫面或整個步驟的容器上；這類容器一改樣式，顯示畫面的 WebView2 就把容器裡全部內容的無障礙資訊重送一遍。這三樣改成獨立的小元素，外觀不變。另加一則測試，擋下大型版面容器再用這種畫法。 |
| 由底稿匯入欄位 | 第三步原本的「從報告帶入配對」改名為「由底稿匯入欄位」，按鈕與帶入結果放在配對區上方。除了有隱藏配對紀錄的新版 JET 報告，也接受舊版 IDEA JET 的工作底稿。沒有隱藏紀錄時，改讀看得到的欄位對照表；看不出來或和目前來源對不上的項目列出來請審計員補選，按「確認配對」才儲存。 |
| 借貸代碼說明 | 工作底稿及報告的欄位資訊，完整寫出已填的借方與貸方代碼；只填一側時只寫該側。從看得到的欄位對照表匯入時，也能帶回這兩側設定。舊版只寫借方代碼的檔案仍依原本內容帶入，不猜另一側。 |
| 已存內容讀取 | 上次確認的配對讀不出來時當作沒有草稿，不擋住開案。案件設定檔有讀不出來的文字時，案件清單照常列出錯誤列，仍可刪除該案件。已存的驗證與預篩選摘要不是合法 JSON、缺少必要內容、型別不對或文字讀不出來時，結果標成過期；篩選情境的文字或結構讀不出來時列為「條件內容無法讀取」，仍可移除。過深的 JSON 也依相同規則處理。資料庫版本值存成二進位時回報版本資訊無法辨識。報告清單中不能用作檔名的紀錄不列出，其他紀錄照常讀取。 |
| 結果時間與舊摘要 | 驗證或預篩選結果的產生時間損壞時，開案不帶結果並標成過期，重跑即可恢復。新結果保存成功時，只清除時間無效的舊結果列，有效歷史列保留。預篩選的舊摘要可繼續顯示當時已提供的區塊，不補造當時沒有保存的彙總；匯出資訊不足時請審計員重跑。篩選情境的日期或編號、匯入批次欄位損壞時，仍回報既有的資料庫損壞提示。 |
| 案件資料夾與完成狀態 | 案件資料夾名稱與設定檔的案件識別值不一致，或缺少有效的金額倍率時，清單列出設定檔無法讀取的案件，仍可刪除實際對應的資料夾。篩選情境已儲存或報告已產生後，附帶狀態讀回失敗時回報成功並附提醒，不再把已完成的操作報成失敗。 |
| TB 科目名稱來源 | 資料驗證報告 V_Report 5 的「會計科目名稱_TB」與工作底稿 step1 的「試算表科目名稱」，改為只取 TB 名稱。GL 有科目而 TB 沒有，或 TB 名稱為空值、空字串時，該欄留白，不以 GL 名稱補值。差異頁仍維持原本的名稱補值。金額、科目編號與差異判定不變。 |

## 如何保留修改紀錄

Git 保存已提交的程式差異，審查者可以查看修改前後的內容；本文件只說明功能範圍與重要修正，不逐行複製程式。審查意見及測試結果分別留在 Code Review.xlsx 與測試紀錄表.xlsx。

公司選定送審程式後，再填寫下表。若送審檔包含尚未提交的修改，單靠 Git 提交編號無法識別全部內容，應先整理成可追溯的送審來源。表中「條件篩選」到「TB 科目名稱來源」是 2026-11-09 與 2026-11-10 的修改，不在 2026-11-08 的提交 61d4b43「暫存目前開發進度」裡；表中其餘各列都在這個提交裡。送審內容以下表填寫的提交為準。撰寫本段時還沒有 Git 標籤，也沒有發布版本。
