## 1. 使用者體驗

JET 依審計作業分成六步：建立案件、匯入資料、欄位配對、資料驗證與測試、進階條件篩選、匯出底稿。審計員不必操作資料庫，即可完成總帳資料的篩選與整理。

畫面顯示工作進度並提供取消。可處理的錯誤說明原因與下一步。案件資料有缺失或出現風險時，由審計員判斷並在底稿說明；程式只為資料完整性保留必要檢查。

## 2. 畫面與操作

畫面以繁體中文呈現，名稱依專案名詞表。暖白底色搭配石板藍重點色，同一工作區只突顯目前的主要動作。中文使用 Noto Sans TC，英數使用 Instrument Sans，圖示與字型都隨程式提供。

明細每頁最多 200 筆。必填欄位在輸入處標示。選擇「金額與借貸別」時，借方或貸方代碼至少填一個；兩個都空白時不能確認配對。資料可靠性測試預設抽樣 59 筆，審計員可在執行前調整。

## 3. 專案與模組

JET 使用 C# 與 .NET 10。WinForms 提供視窗，WebView2 顯示本機網頁。正式版僅支援 SQLite，案件資料存放在使用者電腦。

| 模組 | 工作 |
|---|---|
| 畫面與 Bridge | 接收操作，傳遞請求並顯示結果。 |
| Application | 安排匯入、驗證、篩選及匯出的處理順序。 |
| AuditCore 與 Domain | 定義審計判斷、欄位與金額規則。 |
| Infrastructure | 執行 SQLite 查詢、讀寫檔案並產生報告。 |

審計規則由核心模組定義。畫面和報告沿用核心結果，避免各算一套。系統組成圖見 Framework.docx。

## 4. 函式與命名

名稱應表達用途，同一概念使用一致名稱。函式各自負責一項工作；共用規則集中維護。註解說明不容易從程式看出的原因與業務依據，不逐行重述程式。

畫面與 C# 經由 JetApi 傳送操作。修改操作參數時，同步核對處理程式、註冊、文件與測試。

## 5. 資料與效能

來源資料保留供追查。欄位配對後另建整理過的總帳與試算表資料。金額以整數保存到小數第四位，顯示格式不改變計算值。

大量篩選與彙總交給 SQLite，畫面只取得摘要與分頁。檔案採逐批讀寫，資料庫連線與暫存資源用完後釋放。資料變更後，相關結果需重新計算。

## 6. 錯誤與安全

非預期錯誤不把內部例外原文顯示給審計員。支援日誌保留定位問題需要的資訊，避免記錄案件內容。

查詢值以 SQL 參數傳入，欄位與排序限制在程式允許的清單。檔案先寫入暫存位置，成功後才發布。正式工作底稿每次使用新檔名，不覆寫舊檔；其餘報告可重新產生。

## 7. 開發與測試

Agent 負責維護單元測試與整合測試，檢查正常輸入、邊界值、取消及失敗情況。預期答案應獨立於被測程式，不能把程式算出的答案再當成測試標準。

人工審查集中在 AuditCore 的關鍵審計判斷。審查人員確認規則、驗算例子與預期結果；一般格式轉換、分頁、檔案與畫面處理由自動測試持續檢查。資安問題另交 ITS 與 NITSO 評估。

## 8. 公司測試與首次評估

開發測試使用合成資料。公司環境再以核准方式檢查實際操作、報告及一般使用者權限。開發電腦測試通過不能代替公司驗收。

首次送審以一份固定程式與發布檔為單位，附上測試結果、涵蓋率、人工審查及安全檢查。涵蓋率表示測試執行過多少程式，不表示審計規則一定正確。

## 9. 文件與修訂紀錄

Readme 說明操作；Code and Explanation 說明代表性程式；Code Review 保存人工意見；測試紀錄表保存自動測試及交接結果。

目前所有開發修訂都屬首次評估版。Git 保存實際程式差異，程式修訂紀錄只摘要此次範圍與修正目的，不逐次抄錄每次推送。公司選定版本後，再填上送審識別。

## 10. 部署與維護

發布內容為 Windows x64 的 JET.exe，以及畫面、範本和設定檔，整個資料夾一併交付。電腦需具備 WebView2 Runtime；匯入 Access 時另需相容的 Access Database Engine。

正式部署依公司核准程序辦理。保留核准的發布檔與文件供復原，並追蹤使用者回饋、套件漏洞及第三方授權義務。
