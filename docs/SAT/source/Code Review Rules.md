## 1. 審查分工

首次評估將審計判斷與一般程式處理分開確認。人工審查集中在 AuditCore 的關鍵業務規則；Agent 負責可自動驗證的處理邏輯、測試案例與涵蓋率紀錄。

AuditCore 資料夾也包含分頁、資料格式及報告規劃。放在這個資料夾不代表每段程式都需要審計員逐行閱讀。Code Review.xlsx 已列出需要人工確認的規則與程式位置。

| 工作 | 負責人 | 交付內容 |
|---|---|---|
| 審計規則與預期答案 | 熟悉審計作業的人員 | 規則依據、獨立驗算、意見與結論。 |
| 一般程式處理與回歸測試 | 開發人員及 Agent | 測試程式、實際結果、涵蓋率與未涵蓋部分。 |
| 安全與部署 | ITS、NITSO 及公司指定人員 | 掃描結果、風險處理與環境確認。 |

Agent 的檢視結果是準備資料，不代填人工簽核。單元測試也不能取代對規則本身的確認。

## 2. 人工要看什麼

人工表單以存入筆數與合計、總帳與試算表逐科目比對、借貸不平、納入測試範圍、可靠性抽樣及篩選規則為主。每項提供處理說明、程式位置與合成例子。

審查人員先寫出獨立預期答案，再對照程式及測試。確認例外是否合理，例如缺少試算表只會讓逐科目比對無法執行，不能被當成完整性測試通過。

Code Review.xlsx 的黃色欄位填寫規則依據、驗算結果、發現問題、結論與審查人。結論可選「待複核」「通過」「需修正」「不適用」。需修正的項目完成後，保留原意見並補上複驗結果。

## 3. Agent 要交付什麼

Agent 檢查測試是否有獨立答案，是否涵蓋正常、錯誤與邊界輸入，並實際執行。失敗要保留原始紀錄；不得放寬既有斷言來取得通過結果。

公開測試包含單元、整合及架構測試，另有前端測試。報告分別列數量，不把所有案例稱為單元測試。C# 涵蓋率另列整體與各模組的已執行行數、可執行行數及比例。未執行的程式列入後續檢查，不預設達到某個百分比就算合格。

## 4. 測試交接

1. 公司選定送審程式與發布設定。
2. 執行 tools/verify.ps1 的 Public 命令並加上 CollectCoverage。
3. 保存執行收據、TRX 測試結果與 Cobertura 涵蓋率檔。
4. 以 SAT 報告腳本更新測試紀錄表，將失敗、略過及未涵蓋範圍一併交付。
5. 複核人抽查關鍵測試的輸入與答案，完成 Code Review 的人工欄位。

開發結果與公司送審結果分欄保存。程式改動後，應重跑受影響測試；正式送審前再執行完整公開測試。原始紀錄留在公司指定位置，SAT 正文只保留摘要。

## 5. 審查完成條件

關鍵審計規則已有人工結論，測試失敗已處理，未涵蓋與安全待辦已有負責人及處理決定，才交由公司判斷是否可送審或部署。本表不代替公司核准。

審查方法參考 Google Engineering Practices 的功能、測試、可讀性與範圍檢查。這是本專案的分工安排，並非聲稱業界一律以自動測試取代人工審查。
