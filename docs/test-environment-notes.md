# 測試環境交付說明

這一版加入 KCT 條件與科目配對的調整，請在測試環境確認操作與結果。上一版的修正不再逐項列出，
尚未解決的限制保留在文末。開發與驗證紀錄見 [KCT 需求計畫](specs/2026-10-06-kct-gl-requirements-plan.md)。

## 開始前

- 請使用 SQLite 或 DuckDB；這次不驗收 SQL Server。
- 上一版建立的案件可以直接開啟，不必因為這次篩選規則更新而刪案重建。JET 會先檢查已儲存的篩選情境；
  全部仍可使用時，改用新版規則，保留名稱、動機與條件內容。舊的條件篩選報告與底稿會標為過期，
  第一次查看命中或重新匯出時才重算，所以這次可能等得比較久。
- 如果有情境不能改用新版規則，JET 會列出原因，不會只更新其中幾個。請依訊息調整情境後再試。
  之前已匯出的正式底稿不會被這次更新默默覆寫；要取得新版結果，請重新匯出。

## 本機合成資料

本輪已準備兩組由程式產生的會計資料，放在不進 Git 的 `artifacts/review/kct-filter-ops/synthetic-acceptance/`。
這些檔案只存在本機，不會隨 clone 取得。請從該目錄的 `README.md` 取得完整建案、配對與核對步驟，
每組都有 `GL.xlsx`、`TB.xlsx`、`AccountMapping.xlsx` 與 `expected.json`，可把整個資料夾帶到測試環境。

- `manual-flags`：查核期間為 2025 全年，24 筆分錄、12 張傳票。來源代碼是合成的 MNL、SYS 與空白；
  配對後應顯示人工 10 筆、自動 12 筆、空白 2 筆。空白政策選「不判定人工或自動，保留供其他測試使用」。
  用涵蓋全年日期的情境匯出，核對 Step 4-1 的全部 24 筆與預覽一致，來源代碼不變。
- `non-quarter-end`：查核期間為 2025-01-01 到 2025-11-30。58 筆分錄中，2 筆在期末之後，不進測試範圍。
  KCT A 設 5 天，應列 3/27 到 3/31、6/26 到 6/30、9/26 到 9/30、11/26 到 11/30；
  命中 8 筆收入借方、8 張傳票，包含對方科目的底稿明細共 16 筆。固定傳票清單在 `expected.json`。

GL 請用「單一帶號金額欄」，TB 請用「直接變動金額欄」。先完成科目配對，再設定篩選情境。
程式已檢查逐張借貸平衡、TB 與期內 GL 相符，並用另一個工作簿讀取器核對日期、旗標與固定命中清單。
尚未由使用者在測試環境人工驗收，也不代表私人案件的人工旗標欄已驗證。

可用同一組合成資料核對 TB 修改：先在第五步產生條件篩選報告，再匯出底稿，留下兩種舊檔供比較。
回第三步重新配對 TB，先試取消，確認情境與報告狀態都保留。接著成功重新確認 TB 配對，
確認第五步情境清空，訊息只新增一次，第四步要求重新驗證；兩種舊報告標成過期，但原檔內容保持不變。
只重新驗證仍不能沿用舊情境匯出，請重新設定情境再產生新版底稿。

## 這次請特別試的地方

### KCT 條件

- **A**：除了曆年季底前的天數，也會納入查核期末前的同樣天數。查核期末不是季底的案件，結果可能比上一版多；
  請核對畫面列出的日期區間。
- **B**：現在可以加入條件。請先在第四步新增「固定資產」與「營業費用」分類並配對科目，
  再到第五步選借方固定資產、貸方營業費用。預設包含下層分類；在建工程不要配到固定資產，也不要放在它的下層。
- **C**：卡片和條件編輯區補上現金的說明，篩選方式沒有改。現金不算一般對方科目；
  如果要排除現金銷貨，請改用預篩選條件「未預期借貸組合」。
- 新加入 **A 到 E** 時，動機會帶入 KCT 的評估說明，仍可自行修改。已儲存或手寫的動機不會被換掉。

### 人工與自動的顯示

底稿 Step 4-1 的 `人工傳票否_JE_S` 欄，原本的 1、0 改成「人工」「自動」；空白仍留白，欄名不變。
資料預覽的「納入測試的分錄」最後也多了人工或自動欄，方便在匯出前核對。來源檔的代碼沒有被改寫。
這項改動已用合成資料確認；本次私人案件沒有配對人工旗標，未驗證該欄。試用時請用有配對人工旗標的案件，
核對預覽與底稿的「人工」「自動」及空白是否正確。
如果拿舊工具的底稿對照，請先用傳票號碼與項次把兩邊的列對齊，再看這一欄，因為兩邊底稿列的順序可能不同。

### 進階篩選的名稱與儲存

- KCT 卡片的自動名稱和已儲存的情境同名時，名稱後面會加數字，例如「G 2」，可以直接儲存。
- 同一組同時有 KCT 卡片與自訂條件時，名稱寫成「G+自訂」，動機每條自訂條件多一行「自訂：」開頭的說明。
- 套用常用範例或舊表範例後，再新增或移除條件，名稱與動機會改回依目前條件自動產生；自己改過的文字不受影響。
- 名稱和其他已儲存情境相同時不能儲存，名稱欄旁會說明原因。條件相同但名稱不同的情境可以並存。

### 修改前面步驟的資料

已有篩選情境時，修改會讓篩選結果過期的前面資料，會清除全部已儲存的篩選情境，第五步回到預設狀態。
這類修改包括重新匯入或重新確認總帳與試算表配對、假日與補班日、每週非工作日、科目配對、授權名單、財報準備日與分類設定。
修改試算表比照修改總帳，資料驗證、預篩選與篩選命中一起失效，全部已存情境清除；重新驗證後仍要重新設定情境。
第二到第四步在有篩選情境時顯示一句提醒，第一步只在打開修改案件資料表單後顯示。取消或修改失敗時，情境仍在。
條件篩選報告與底稿在清單中標成過期，但已匯出的檔案不改寫；依新資料重新設定情境後再匯出。

### 幾個操作入口

- 第三步新增「傳票建立日」快捷。選好未使用的來源欄後，JET 會把它勾選為攸關資料元素欄位，名稱設為「傳票建立日」、型別設為日期。
  已有同名欄位而新來源尚未使用時，只更換來源。若所選來源已用於另一欄，JET 會先顯示目前用途，讓你決定是否改成傳票建立日。
  確認後沿用該欄，不刪掉其他欄；取消則不改任何欄位。按「確認配對」後，已儲存的篩選情境會清除，見下方「修改前面步驟的資料」。
- 第五步的值清單會顯示「已輸入 N 個值」，原有 100 個值限制的清單也會顯示上限；KCT E、F、H 沒有新增筆數限制。
  計數依實際送出的值計算，會先去掉頭尾空白及完全相同的重複值；輸入框仍保留你輸入的原文。
- 第五步指定日期的日曆可以直接選年、月，不必一直按上個月或下個月；原來的鍵盤操作仍可使用。
- 第二步的「假日與補班日」區塊新增「取得假日與補班日範本」。兩份檔案會放進案件資料夾，同名檔已存在就保留。
  範本是 **2025 年資料**，請自行更新年份與日期，再上傳；取得範本不等於已匯入假日。
  假日檔的 `Date_of_Holiday`、補班檔的 `Date_of_MakeUpday` 以 `yyyy-MM-dd` 填寫，例如 `2025-01-01`；假日檔若有 `IS_Holiday` 欄，只匯入 Y 的列。
  請保留範本第一列說明、第二列欄名的排列。JET 只略過第一列，不會因第一列空白而改略過第二列說明。

### 第四步的科目配對檔

可以沿用前一案件的配對檔。匯入後會多兩種提醒，各自可以按「列出科目」，清單較長時再按「載入更多」：

- **本案沒有的科目**：檔案有列，但本案的有效總帳與試算表沒有。JET 會保留它們，不會擋住匯入；它們不會出現在篩選結果。
- **配對檔未列的科目**：本案有，但檔案漏列。這些科目不屬於任何分類；請核對是否需要補進檔案再匯入。
  這和「檔案有列、分類留白」不同，後者仍視為 Others。

重開案件時先顯示「尚未核對」，按「列出科目」才重新查詢，不會每次開案都先掃描總帳。
匯入後若差異筆數暫時查不到，也會顯示「尚未核對」；配對仍已儲存，可按「列出科目」重試。
空白科目編號不列入待配對清單，仍由第三步的空白科目明細揭露。配對資料預覽顯示實際已儲存的內容。
多餘科目的分類仍可能讓 KCT 條件顯示可用，所以沿用前案檔案後，仍要確認本案科目確實配到所需分類。

新舊範本都可調換科目編號、名稱與分類的欄序，請保留原有欄名。舊範本的標頭在第三列也可以匯入，
第二列空白不會再漏掉第一筆資料。**Excel 的篩選和隱藏列不會限制匯入範圍，JET 仍會讀入所有資料列**；
如果某些科目不想匯入，不能只靠篩選或隱藏它們。欄名無法辨識而改依欄位順序判斷時，匯入完成後會提醒哪個來源欄被當成什麼，請核對配對預覽。

## 目前已知的限制

- 第五步自訂的條件，如果用到第三步沒有配對的欄位，結果會是 0 筆，畫面不會提醒。0 筆不代表沒有例外分錄。
  沒有匯入假日檔時，假日相關的條件也一樣。使用自訂條件前，請先確認用到的欄位都已配對。
  KCT 條件缺少需要的欄位時，畫面會寫出缺哪一欄。
- 第四步完整性測試的第一項，只確認 JET 存下的分錄和確認欄位配對時算出的數字一致，不和來源檔自己的合計比對。
  如果需要確認來源檔本身完整，請把匯入的筆數與借貸合計，和客戶系統的報表另外核對。
- 總帳入帳日在期末之後的分錄，不納入測試範圍；畫面只顯示筆數，看不到明細，也不能篩選。這已列為之後的新需求。
- SQLite 的大型案件在執行中按「取消」，要等目前那一段處理跑完才會停下，可能要等一段時間。DuckDB 沒有這個情形。這一項之後修。

## 回報問題

請寫下在哪一步、做了什麼、看到什麼訊息，並附上支援日誌。展開畫面左下角的「訊息」，按「輸出支援日誌」即可產生；
檔案會存到該案件的資料夾，日誌不含檔名與資料內容。
