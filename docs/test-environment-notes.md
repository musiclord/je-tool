# 測試環境交付說明

這份說明給在測試環境試用 JET 的同仁。這一版還不是正式版本，用來確認兩份使用者回饋的修正，以及交付前的最後修正。
開發過程與每一項的驗證紀錄在[使用者回饋與操作流程一致性修正計畫](history/specs/2026-09-17-user-feedback-and-workflow-review-plan.md)。

## 開始前

- 這一版之前建立的案件，請直接刪除，再建立新案件、重新匯入。這一版改了驗證、預篩選與篩選的規則，
  舊案件留下的結果不會沿用，舊的匯入資料也不會自動重新整理。
- 建立案件時請選 SQLite 或 DuckDB。這次不驗收 SQL Server。

## 請特別幫忙試

- 之前匯入失敗的那份總帳文字檔，請再匯入一次。
  - 成功時，請核對匯入的筆數。
  - 如果出現「欄位內含換行」的提醒，請用 Excel 打開原檔，核對提醒列出的列號。
  - 失敗時，請展開畫面左下角的「訊息」，按「輸出支援日誌」，把產生的檔案交給開發人員。支援日誌不含檔名與資料內容。

## 目前已知的限制

- 第五步自訂的條件，如果用到第三步沒有配對的欄位，結果會是 0 筆，畫面不會提醒。0 筆不代表沒有例外分錄。
  沒有匯入假日檔時，假日相關的條件也一樣。使用自訂條件前，請先確認用到的欄位都已配對。
  KCT 條件缺少需要的欄位時，畫面會寫出缺哪一欄。
- 第四步完整性測試的第一項，只確認 JET 存下的分錄和確認欄位配對時算出的數字一致，不和來源檔自己的合計比對。
  如果需要確認來源檔本身完整，請把匯入的筆數與借貸合計，和客戶系統的報表另外核對。
- 總帳入帳日在期末之後的分錄，不納入測試範圍；畫面只顯示筆數，看不到明細，也不能篩選。這已列為之後的新需求。
- SQLite 的大型案件在執行中按「取消」，要等目前那一段處理跑完才會停下，可能要等一段時間。DuckDB 沒有這個情形。這一項之後修。

## 可能會看到的新提醒

這些提醒都不會擋住操作，只是請你多核對一下。

- 匯入文字檔後：「有幾筆資料的欄位內含換行」。用引號包住的欄位可以換行，不一定是錯誤；但引號放錯位置時，
  後面幾列會被併進同一格，匯入的筆數會變少。
- 第三步選「只列人工」或「只列自動」時：確認前提醒代碼還沒和來源核對；確認後，如果清單上的代碼在來源裡一筆都沒有，
  再提醒一次，並寫出代碼與來源欄。
- 第四步「依分錄編製者彙總」超過 50 位人員時：人數寫完整的人數，表格上方說明只列出分錄筆數最多的 50 位。

## 回報問題

請寫下在哪一步、做了什麼、看到什麼訊息，並附上支援日誌。展開畫面左下角的「訊息」，按「輸出支援日誌」即可產生；
檔案會存到該案件的資料夾。
