# 測試環境交付說明

這一版調整常用篩選條件與科目配對，請在測試環境確認操作與結果。上一版的修正不再逐項列出，
尚未解決的限制保留在文末。

## 開始前

- 請使用 SQLite。DuckDB 與 SQL Server 在短期上線期間暫時移除（裁定 2026-11-06-08），以前建立的 DuckDB 案件不會出現在案件清單（裁定 2026-11-06-09）。
- 案件資料庫只接受現行版本。這一版更新了案件的版本，之前版本建立的案件都無法開啟，JET 會請你在案件清單刪除案件後重建（裁定 2026-10-30-23）。
- 已儲存情境的舊寫法不再讀回（裁定 2026-10-30-25），包括內含借貸方向的科目或傳票條件、含正負號的核心金額比較，
  以及舊式關鍵字、尾數和「同一傳票」組合。請用現行條件重建，借貸方向另用「借貸別」表示（裁定 2026-10-14-08）。
- 之前已匯出的正式底稿不會被默默覆寫；要取得新版結果，請重新匯出（裁定 2026-09-02-03）。

## 本機合成資料

本輪已準備兩組由程式產生的會計資料，放在不進 Git 的 `artifacts/review/kct-filter-ops/synthetic-acceptance/`。
這些檔案只存在本機，不會隨 clone 取得。請從該目錄的 `README.md` 取得完整建案、配對與核對步驟，
每組都有 `GL.xlsx`、`TB.xlsx`、`AccountMapping.xlsx` 與 `expected.json`，可把整個資料夾帶到測試環境。

- `manual-flags`：查核期間為 2025 全年，24 筆分錄、12 張傳票。來源代碼是合成的 MNL、SYS 與空白；
  配對後應顯示人工 10 筆、自動 12 筆、空白 2 筆。空白政策選「不判定人工或自動，保留供其他測試使用」。
  用涵蓋全年日期的情境匯出，核對 Step 4-1 的全部 24 筆與預覽一致，來源代碼不變。
- `non-quarter-end`：查核期間為 2025-01-01 到 2025-11-30。58 筆分錄中，2 筆在期末之後，不進測試範圍。
  「在該季度前 X 天借記收入的會計分錄」設 5 天，應列 3/27 到 3/31、6/26 到 6/30、9/26 到 9/30、11/26 到 11/30；
  命中 8 筆收入借方、8 張傳票，包含對方科目的底稿明細共 16 筆。固定傳票清單在 `expected.json`。

GL 請用「單一帶號金額欄」，TB 請用「設定年度變動金額」。先完成科目配對，再設定篩選情境。
程式已檢查逐張借貸平衡、TB 與期內 GL 相符，並用另一個工作簿讀取器核對日期、旗標與固定命中清單。
使用者已驗收這兩組合成資料的人工旗標、非季底期末及 TB 修改接續（裁定 2026-10-08-27）；這不代表私人案件的人工旗標欄已驗證
（私人案件的人工旗標欄見裁定 2026-10-06-03）。

可用同一組合成資料核對 TB 修改：先在第五步產生條件篩選報告，再匯出底稿，留下兩種舊檔供比較。
回第三步重新配對 TB，先試取消，確認情境與報告狀態都保留。接著成功重新確認 TB 配對，
確認第五步情境清空，訊息只新增一次，第四步要求重新驗證；兩種舊報告標成過期，但原檔內容保持不變。
只重新驗證仍不能沿用舊情境匯出，請重新設定情境再產生新版底稿。

## 這次請特別試的地方

### 驗收回饋修正

- 快速修改條件時，完整條件句只顯示一行；切換欄位配對方式時，表格上方的必填欄位那一行位置保持不變。
- 條件組合的名稱與動機一直顯示，按一次即可儲存（裁定 2026-10-14-05）。新增、修改或另存成功後清空草稿；等候儲存時再做的修改會保留。
- 日期改用原生日期框。指定日期可按「加入」或 Enter，加入後清空輸入框並保留焦點，也能貼上日期清單。
- 借貸方向、科目分類及欄位各用一條條件表達（裁定 2026-10-14-08）。子條件組與整張傳票條件可直接從組標頭加入。
- 特定人員、特定摘要、空白摘要與特定尾數四張卡共用欄位條件。每條最多 100 個值；包含清單超過時拆成多條並放進用 OR 連接的子條件組，排除清單則放進用 AND 連接的子條件組（裁定 2026-10-14-16）。
- 連續零尾數用「整數尾數符合」及「金額絕對值至少 1 元」兩條條件表達，命中結果和舊寫法相同（裁定 2026-10-14-09）。

### 日期欄裡只有數字的值

- GL 日期欄或第五步日期清單出現只有數字的值，例如 2025、2025.12 或 45292，不會被當成 Excel 日期序列值換成日期（裁定 2026-10-22-11）。
  確認配對時會寫出這些列的列號；請在 Excel 把那一欄設成日期格式後重新匯入。Excel 裡已經是日期格式的儲存格不受影響。

### 常用篩選條件

- 條件總覽的「常用篩選條件」分頁（裁定 2026-10-29-10）：上半「單項條件」是十張卡片，
  下半「情境範例」是十個範例，套用後替換整份條件。卡片只寫名稱，沒有字母（裁定 2026-10-29-11）。
  自訂分頁的另一區叫「依審計目的」。
- **在該季度前 X 天借記收入的會計分錄**：除了曆年季底前的天數，也會納入查核期末前的同樣天數（裁定 2026-10-06-02）。
  查核期末不是季底的案件，請核對畫面列出的日期區間。
- **借記固定資產(PPE，不含在建)且貸記費用之分錄**：請先在第四步新增「固定資產」與「營業費用」分類並配對科目，
  再到第五步選借方固定資產、貸方營業費用。預設包含下層分類；在建工程不要配到固定資產，也不要放在它的下層。
- **貸方為收入但借方非一般對方科目之分錄**：加入後的條件列有現金的說明。現金不算一般對方科目；
  如果要排除現金銷貨，請改用預篩選條件「未預期借貸組合」。
- 新加入前五張卡時，動機會帶入 KCT 小組的評估說明，仍可自行修改（裁定 2026-10-30-02）。已儲存或手寫的動機不會被換掉。

### 人工與自動的顯示

底稿 Step 4-1 的 `人工傳票否_JE_S` 欄寫「人工」「自動」，不寫 1、0；空白仍留白，欄名照舊版範本（裁定 2026-10-06-02 的 K5）。
資料預覽的「GL」最後也有人工或自動欄，方便在匯出前核對。來源檔的代碼不會被改寫。
這項改動已用合成資料確認；本次私人案件沒有配對人工旗標，未驗證該欄。試用時請用有配對人工旗標的案件，
核對預覽與底稿的「人工」「自動」及空白是否正確。
如果拿舊工具的底稿對照，請先用傳票號碼與項次把兩邊的列對齊，再看這一欄，因為兩邊底稿列的順序可能不同。

### 進階篩選的名稱與儲存

- 卡片的自動名稱和已儲存的情境同名時，名稱後面會加數字，例如「空白摘要 2」，可以直接儲存。
- 自動名稱列出前兩項條件，卡片帶入的條件用卡片名稱，例如「空白摘要、特定尾數(如 999999/000000 結尾)」。
  有卡片時，動機每條自訂條件多一行「自訂：」開頭的說明。
- 套用情境範例後，再新增或移除條件，名稱與動機會改回依目前條件自動產生；自己改過的文字不受影響。

### 自訂篩選條件

- 這個分頁只剩兩區。「依欄位設定」把欄位按日期、數字、文字排成三列，按欄位就加入一條條件，比較方式在右邊的條件卡片選。
- 「依審計目的」分成五類，一次只展開一類；每一項按「加入」就好，只有系統一定會擋下時才停用並寫原因。
- 範例移到「常用篩選條件」分頁下半的「情境範例」，共十個。套用後的情境名稱就是範例名稱。
- 子條件組與整張傳票條件，用每一組標頭的「子條件組」與「整張傳票」加入（裁定 2026-10-30-32）。
- 名稱和其他已儲存情境相同時不能儲存，名稱欄旁會說明原因（裁定 2026-10-07-11）。條件相同但名稱不同的情境可以並存（裁定 2026-10-07-08）。

### 修改前面步驟的資料

已有篩選情境時，修改會讓篩選結果過期的前面資料，會清除全部已儲存的篩選情境，第五步回到預設狀態。
這類修改包括重新匯入或重新確認總帳與試算表配對、國定假日與補班日、每週休息日、科目配對、授權編製人員清單、財報準備日與分類設定。
修改試算表比照修改總帳（裁定 2026-10-07-04），資料驗證、預篩選與篩選命中一起失效，全部已存情境清除；重新驗證後仍要重新設定情境。
重新匯入、附加 GL 或 TB，或重新確認這兩份資料的欄位配對，也會清除科目配對與未儲存分類，但保留分類定義（裁定 2026-10-08-12）。
請依新資料重新指定科目分類；「在 JET 配對」每頁顯示 200 筆（裁定 2026-10-16-03），不顯示先前來源留下的配對。
第二到第四步在有篩選情境時顯示一句提醒，第一步只在打開修改案件資料表單後顯示。取消或修改失敗時，情境仍在。
條件篩選報告與底稿在清單中標成過期，但已匯出的檔案不改寫；依新資料重新設定情境後再匯出。

### 幾個操作入口

- 第三步有「傳票建立日」快捷。選好未使用的來源欄後，JET 會把它勾選為攸關資料元素欄位，名稱設為「傳票建立日」、型別設為日期。
  已有同名欄位而新來源尚未使用時，只更換來源。若所選來源已用於另一欄，JET 會先顯示目前用途，讓你決定是否改成傳票建立日。
  確認後沿用該欄，不刪掉其他欄；取消則不改任何欄位。按「確認配對」後，已儲存的篩選情境會清除，見下方「修改前面步驟的資料」。
- 第五步的值清單會顯示「已輸入 N 個值」，有 100 個值上限的清單也會顯示上限。
  計數依實際送出的值計算，會先去掉頭尾空白及完全相同的重複值；輸入框仍保留你輸入的原文。
- 第五步指定日期的日曆可以直接選年、月，不必一直按上個月或下個月；原來的鍵盤操作仍可使用。
- 第二步的「國定假日與補班日」卡片沒有取得範本與開啟案件資料夾的按鈕，只有上傳國定假日清單、上傳補班日清單與每週休息日設定（裁定 2026-10-08-08）。
  兩份範本檔 `Holiday2025TW.xlsx`、`MakeUpDay2025TW.xlsx` 仍放在程式的 Templates 資料夾。
  國定假日清單的 `Date_of_Holiday`、補班日清單的 `Date_of_MakeUpday` 以 `yyyy-MM-dd` 填寫，例如 `2025-01-01`；國定假日清單若有 `IS_Holiday` 欄，只匯入 Y 的列。
  檔案的排列是第一列說明、第二列欄名，JET 只略過第一列，不會因第一列空白而改略過第二列說明。

### 第四步的科目配對範本

可以沿用前一案件的配對檔。匯入後另有兩種提醒，點整列就在原處展開科目清單，清單較長時可以分頁：

- **本案沒有的科目**：檔案有列，但本案的 GL 與 TB 都沒有。JET 會保留它們，不會擋住匯入；它們不會出現在篩選結果。
- **配對檔未列的科目**：本案有，但檔案漏列。這些科目不屬於任何分類；請核對是否需要補進檔案再匯入。
  這和「檔案有列、分類留白」不同，後者仍視為 Others。

重開案件時先顯示「尚未核對」，點開清單才重新查詢，不會每次開案都先掃描總帳。
匯入後若差異筆數暫時查不到，也會顯示「尚未核對」；配對仍已儲存，可點開清單重試。
空白科目編號不列入待配對清單，仍由第三步的空白科目明細揭露。配對資料預覽顯示實際已儲存的內容。
多餘科目的分類仍可能讓常用篩選條件的卡片顯示可用，所以沿用前案檔案後，仍要確認本案科目確實配到所需分類。

新舊範本都可調換科目編號、名稱與分類的欄序，請保留原有欄名。舊範本的標頭在第三列也可以匯入，
第二列空白不會漏掉第一筆資料。**Excel 的篩選和隱藏列不會限制匯入範圍，JET 仍會讀入所有資料列**；
如果某些科目不想匯入，不能只靠篩選或隱藏它們。欄名無法辨識而改依欄位順序判斷時，匯入完成後會提醒哪個來源欄被當成什麼，請核對配對預覽。

## 目前已知的限制

- 第五步沒有上傳國定假日清單時，「國定假日」條件與預篩選的假日條件會停用，寫出「尚未上傳國定假日清單，請先在第二步「國定假日與補班日」上傳」（裁定 2026-11-05-55）。
  「非營業日」照常可以加入，這時只看週末，補班日照樣排除，畫面不另外提醒。
  第三步沒有配對的欄位同樣不能用：用到它的欄位按鈕、「依審計目的」的條件、情境範例、常用篩選條件的卡片與預篩選規則都會停用（裁定 2026-10-22-05），
  寫出哪個欄位尚未選擇來源欄，請回第三步欄位配對補上；已存的情境用到這種欄位時，開案後列在待修正清單。
- 第四步完整性測試的第一項，只確認 JET 存下的分錄和確認欄位配對時算出的數字一致，不和來源檔自己的合計比對。
  如果需要確認來源檔本身完整，請把匯入的筆數與借貸合計，和客戶系統的報表另外核對。
- 總帳日期在期末之後的分錄，不納入測試範圍；需要期後查核時，另開一個案件，建案時把查核期間設成期後月份。
  這些分錄的明細可在資料預覽「其他資料」的「GL(未納入測試)」查看，未納入原因寫「晚於查核期間」；
  頁籤下方的「未納入原因」選這一種，就只列這些分錄。

## 回報問題

請寫下在哪一步、做了什麼、看到什麼訊息，並附上支援日誌。展開畫面左下角的「訊息」，按「輸出支援日誌」即可產生；
檔案會存到該案件的資料夾，日誌不含檔名與資料內容。
