# JET 專案背景與目前方向

更新日期：2026-08-30

這份文件回答三個問題：JET 為什麼存在、目前優先服務誰，以及正式使用環境對設計有什麼限制。精確的
欄位、篩選規則、action 與程式行為仍分別以 `docs/jet-guide.md`、相應契約、程式和測試為準。

## 從 CaseWare IDEA 到目前的 JET

JET 最早要處理的是原本在 CaseWare IDEA 中進行的傳票測試工作。IDEA 有授權成本及專有環境限制，工作
也不適合長期依賴少數熟悉 IDEA 或 SQL 的人才能完成，因此專案逐步嘗試用較容易交付與維護的方式取代。

早期曾同時評估 .NET WinForms 與 Excel VBA／Access。VBA 對當時的交付與重用較直接，但 Excel 單張工作表
約一百萬列、Access 單檔容量、巨集政策、測試與維護都會限制大型總帳。專案因此沒有把早期原型逐段延伸，
而是回到 C#、WinForms 與 WebView2，並把審計規則、應用流程、畫面和資料庫實作分開。SQLite、DuckDB 與
SQL Server 各有不同責任，但相同業務規則應得到相同答案。

使用者提供的一份早期筆記顯示，2025 年春季的台大課程合作階段曾把完整性測試、Account Mapping、簡單
條件篩選與高風險報表列為目標。這些資訊已足以說明課程合作在專案演進中的位置；目前不需要再追查正式
課程名稱、參與方式或更細的交付紀錄，也不以這些歷史細節作為產品驗收條件。筆記混有客戶作業痕跡及敏感
連線資料，因此不搬入儲存庫；可長期保留的 IDEA、VBA 與 Access 脈絡已去識別化整理在
[`../legacy/jet-legacy-notes.md`](../legacy/jet-legacy-notes.md)。

## 近期要證明的事情

目前的服務對象以 KCT 小組為主，但開發順序不是立刻擴充所有 KCT 條件。近期先讓 GA 能在本機完成原本
CaseWare IDEA 的 JET 工作，證明替代方案可行。現有 KCT 行為繼續保留；新增的 KCT 條件、分類與工作方式，
等 IDEA 替代範圍完成並驗收後再處理。

「IDEA 替代範圍完成」不能只靠一句完成宣告。現行能力、仍待確認的責任與驗收方式整理在
[`idea-replacement-scope.md`](idea-replacement-scope.md)。

## 開發電腦與正式環境不同

目前常見的開發方式，是從公司環境遠端連到個人電腦進行開發與驗證。個人電腦可以提供開發工具、SQL Server
或原生 Excel 等能力，但它不是正式部署環境，也不能拿這台電腦的權限和軟體狀態當成公司環境必然具備的條件。

正式方向必須遵守下列限制：

- 公司環境不能假設使用者有系統管理員權限。
- 公司環境無法存取 AI 相關網路服務；AI 可以協助開發，但不能成為 JET 執行期依賴。
- 本機案件處理要能在沒有企業中心服務時工作，並避免要求一般 GA 人員管理 SQL Server。
- 目前以 SQLite／DuckDB 的本機作業為優先。SQL Server 保留 provider 相容性與未來企業使用縫隙，但線上
  中心化管理要等公司帳號、網路、權限、身分與維運責任都能確認後再啟動。
- 正式環境的最低 Windows／Office 版本、允許的安裝方式及可用本機資料庫仍待使用者和公司環境確認。

## 這些背景如何影響設計

- 新功能不能因開發電腦方便，就引入需要高權限、外部 AI、常駐雲端或未核准網路連線的必要依賴。
- SQL Server、SQLite 與 DuckDB 的責任要清楚。共用業務規則不能散落在 provider、前端或單一案件特例中。
  一般候選驗證不要求 live SQL Server；需要證明 SQL Server 實跑相容性時，另行準備本機測試環境並完整
  執行 `Provider`，不能用略過或一般 `ReleaseCandidate` 冒充。
- 優先順序發生衝突時，先用 IDEA 替代範圍與目前服務順序裁定；仍有兩種答案時請使用者決定。
- 歷史文件用來解釋來歷，不能覆蓋這份現行方向或目前程式行為。

## 尚待使用者補充

- KCT 的正式全稱、方法來源及尚未提供的條件分類。
- 公司正式環境允許的 Windows、Office、安裝權限和本機資料庫條件。
- CaseWare IDEA JET 的完整責任清單；確認後要逐項納入 IDEA 替代範圍表。
