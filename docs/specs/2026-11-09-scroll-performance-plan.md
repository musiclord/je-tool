日期：2026-11-09。

狀態：待使用者驗收。標題列的玻璃、流程軸線與目前步驟的圓環改成小元素，外觀和改之前相同，捲動卡頓已量不到；測試與文件都已改完。

JET 在 WebView2 裡捲動時會頓一下。前一個 session 量到原因：電腦上有程式使用 UI Automation，WebView2 一直維護無障礙樹，
掛著 `::before` 或 `::after` 的大型容器只要樣式一改，就把整棵子樹重送一遍。這一輪把標題列的玻璃從 `.app-shell::before` 搬到

另外加了測試，擋下大型版面容器再掛虛擬元素，規則寫進前端設計規範。已改完並通過驗證，待使用者驗收。

## 查到的原因

前四點是前一個 session 的量測結論；這一輪重新量了改之前與改之後的版本，結果和這些結論一致：

- 這台電腦有程式在用 UI Automation，所以 WebView2 一直維護無障礙樹。是哪一個程式開的查不出來。
- 掛著虛擬元素的元素只要樣式一改，WebView2 就把它底下整棵子樹重送一遍。同樣的樣式改在沒有虛擬元素的元素上，不會重送。
- 捲動時實際觸發的有兩處。第一處是 `.app-shell::before` 畫的標題列玻璃：`app.js` 的 `bindChromeHeight` 在內容捲到標題列下面時
  切換 `.app-shell` 的 `data-under-chrome`，玻璃的 240 毫秒轉場開始與結束各觸發一次，而 `.app-shell` 包著整個畫面。
  第二處是目前步驟那一列的 `::before` 軸線與 `::after` 圓環，那一列包著整個工作面，滑鼠移入或樣式改變時觸發。
- 這一輪改之前在合成案件上盤點每個畫出虛擬元素的元素：子樹最大的是 `.app-shell`（5,355 個元素）與目前步驟那一列（5,111 個），
  其他都在 23 個以內，例如流程目錄的滑動選取 23 個、標題列操作組的外框 17 個。

## 目標與範圍

- 標題列玻璃改成 `index.html` 裡 `.app-shell` 的第一個子元素 `.app-shell__glass`，加 `aria-hidden`，外觀、轉場與高對比的下緣細線都不變。
  `bindChromeHeight` 照舊在 `.app-shell` 切換 `data-under-chrome`，改由 `.app-shell[data-under-chrome] > .app-shell__glass` 換外觀。
- 流程軸線改成每一列的第一個子元素 `.stepflow-item__rail`，目前步驟的圓環改成那一列最後一個子元素 `.stepflow-item__mark--current`，
  兩者都是 `aria-hidden` 的空元素，疊放順序和原本的 `::before`、`::after` 相同。
- 盤點其他大型版面容器：改完以後沒有大型版面容器掛虛擬元素。子樹 23 個以內的小元素照常使用虛擬元素。
- 加測試擋下大型版面容器再掛虛擬元素，規則寫進 `.agents/skills/jet-frontend-design/SKILL.md`，前端說明同步一句。

不做的事：

- 不關掉無障礙功能。WebView2 不吃 `--disable-renderer-accessibility`，JET 也有給讀屏軟體用的文字。
- 滑鼠移到配對表上時，滾輪改捲配對表，這是瀏覽器的正常行為，不改。
- 不追查是哪個程式開了 UI Automation。

## 改了哪些檔案

- `src/JET/JET/wwwroot/index.html`：加 `.app-shell__glass`。
- `src/JET/JET/wwwroot/css/app.css`：玻璃、軸線與圓環的樣式改掛在新元素上；玻璃用 `box-sizing: content-box`，
  因為全域的 `border-box` 不套用在虛擬元素上，高對比佈景的下緣細線才會畫在原本的位置。
- `src/JET/JET/wwwroot/js/app.js`：`stepRowHtml` 與 `doneGroupHtml` 的每一列加軸線，目前步驟加圓環。
- `src/JET/tests/JET.Tests/Architecture/DesignIntegrationFrontendTests.cs`：改三處既有斷言，新增 `Frontend_LargeLayoutContainers_CarryNoPseudoElements`。
- `tools/tests/frontend-journey-step4.test.cjs`：新增「each flow row draws its rail and the current ring as hidden empty children」。
- `.agents/skills/jet-frontend-design/SKILL.md`：加大型版面容器不掛虛擬元素的規則。
- `docs/jet-frontend-description.md`：加一句說明。檔案離 160 KiB 上限只剩幾十位元組，所以先改短和別段重複的句子：
  頂部玻璃那一段和畫面結構清單重複的兩句、主要按鈕按下時鼓起的重複說明，以及動態秒數的說明句。事實都還在文件裡。

## 改動的既有測試

`DesignIntegrationFrontendTests` 有三處斷言找 `.app-shell::before`：`Frontend_TopIsOneBandAcrossTheWindow_AboveEveryColumn` 檢查玻璃橫跨視窗與外觀，
`Frontend_GlassIsTheFunctionalLayer_AndControlsAreTactile` 檢查玻璃的 `z-index` 與高對比佈景的下緣細線。玻璃搬到新元素後改成找 `.app-shell__glass`，
斷言的外觀數值不變，另外加檢查玻璃是 `.app-shell` 的第一個子元素，而且 CSS 不再有 `.app-shell::before`。原因與第一次失敗的收據寫在測試旁的註解。

用 CDP 連上 WebView2 錄效能追蹤，以 CDP 送合成滾輪事件，不動實體滑鼠，每個捲動區的滾輪往下轉 20 下再往上轉 20 下。

## 外觀比對

在同一個 WebView2 裡用 CDP 截圖，改之前與改之後各拍 36 張，逐像素比對。情境包括案件清單、六個步驟的頂端與捲到標題列下面、
滑鼠移到目前步驟標題與其他步驟列、第四步展開「已完成的步驟」與收合目前步驟，以及第三步在視窗不在前景、關閉透明效果、
高對比佈景、減少動態與列印媒體下的樣子。截圖時固定讓頁面認為自己在前景，避免使用者切換視窗影響結果。

- 第一次比對找到一個真正的差異：高對比佈景下，標題列下緣的細線往上移了 1 像素。原因是全域的 `box-sizing: border-box` 會套用在新元素上，
  卻從來沒有套用在原本的虛擬元素上。玻璃改用 `box-sizing: content-box` 後，這兩張逐像素相同。
- 修正後 36 張裡有 25 張逐像素相同。其餘 11 張的差異只在三處：案件清單右上角 2 個像素、建立案件畫面中的一小塊，以及欄位配對表的一條橫線，
  每處的顏色差最多 10。同一份程式拍了不只一次，這三處在同一份程式的兩次拍攝之間也會不同，屬於每次執行的細微差異，和這次改動無關。
- 改之後，畫出虛擬元素的元素裡，子樹最大的是流程目錄的滑動選取，23 個元素。
