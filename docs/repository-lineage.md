## 已決定不保存來源 Git 歷史

`je-tool` 會以整理後的工作樹建立唯一的新根提交，不匯入來源專案的提交圖、tags、refs、reflogs、bundles
或其他 Git 物件，也不合併互不相關的歷史。使用者也已決定不為本次遷移保存鏡像、bundle、舊的 Git
逐行來源或逐筆提交對照；乾淨的新專案結構本身就是這次遷移的目的。

這項選擇可避免重複快照、無意義衝突，以及舊 Git 物件中的機敏或暫存資料。日常開發所需背景由現行文件、
正規化歷史副本與 `legacy/` 承接；未納入的逐位原文、舊的 Git 逐行來源與其他版本，是已明確捨棄的來源
資訊，不構成對來源專案的永久依賴。

## 新儲存庫保存的背景

- `docs/history/je-testing/`：正規化後的早期文件副本。
- `docs/history/new-je-tool/`：正規化後的近期文件副本。
- `legacy/`：IDEA、VBA、圖表與原型對照來源。
- 本檔：必要的來源提交與 tree 關係，以及已決定的新儲存庫邊界。

## 關庫裁定

- `new-je-tool/docs/design_handoff_jet_frontend/` 是臨時前端模板，已棄用且不遷移；歷史文件中對它的引用
  只說明當時發生過的設計整合，不代表檔案仍應存在。
- `je-tool/legacy/` 的正規化名稱與分立結構是使用者決定的最終保存範圍；未整理的 `JE_Tool.ism`、重複的
  VBA 匯出檔與舊路徑不再另存。
- 來源專案中被忽略的測試結果、執行產物、建置輸出、私人資料根目錄與本機案件資料不遷移。它們可以留在
  舊的本機工作目錄，但新驗證框架不得依賴或自動搜尋。
- 兩個來源專案可在 `je-tool` 完成驗證框架、正式驗證、第一次提交與推送，並從遠端讀回確認後退役；
  既有 GitHub 儲存庫設為唯讀封存即可，不另建 mirror、bundle 或歷史副本。

全新的驗證框架、正式驗證、候選工作樹、忽略規則與隱私邊界均已完成核對。第一次提交前只需維持候選清單
與實際未忽略檔案一致，並由使用者確認完整內容、`main` 與 `origin`；不得自行暫存、提交或推送。推送後要從
遠端建立全新工作目錄並重新驗證，確認可獨立重現後，才把兩個來源 GitHub 儲存庫設為封存。舊的本機工作
目錄先保留，日後若要刪除，必須另外盤點其中未追蹤或被忽略的內容並取得授權。

關庫不再包含重寫歷史、建立新舊 SHA 對照表、掃描來源 Git 物件或搬移來源產物；這些事項已完成裁定，
不是第一次提交的待辦。
