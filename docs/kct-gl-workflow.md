# KCT 小組的總帳資料整理流程

更新日期：2026-10-07

這份文件記錄 KCT 小組怎麼替查核團隊整理總帳明細與試算表，以及他們用舊版 JE tool 設定高風險條件的做法。
KCT 簡報把這項工作稱為「JE 資料整理」；JET 現在把這份資料稱為總帳明細，簡稱 GL，試算表簡稱 TB。
新版 JET 的對照、使用者裁定與實作紀錄，見現行計畫
[KCT 總帳資料整理需求與新版 JET 對照](specs/2026-10-06-kct-gl-requirements-plan.md)。

## 來源與保密範圍

來源是使用者 2026-10-06 提供的 KCT 簡報，共 50 頁。第 3 到 32 頁說明執行步驟，
第 34 到 48 頁是 KCT 期望舊版 JE tool 優化的 15 個項目。簡報用舊版 JE tool 的畫面說明，截圖裡有範例公司、單號、
人員、科目與金額。原檔只存在使用者電腦，不放進儲存庫。本文件只記錄 KCT 小組的執行步驟與期望優化的項目，當成需求看待；
不記公司名稱、客戶資料、人員、單號、檔案名稱、檔案路徑、文件所屬機構、科目代碼或金額；簡報裡的內部系統只寫用途，
例如「申請單」「派工系統」。

舊版 JE tool 是在 CaseWare IDEA 上執行的工具，視窗標題是「總帳分析自動化工具」，簡報出現 Ver.2018 與 Ver.2022
兩個版本的畫面。使用前要先把總帳與試算表匯入 IDEA。儲存庫保存的舊工具原始碼 `legacy/idea-tool.bas` 開頭標示
「分錄測試自動化工具」Ver.202607，步驟、預篩選編號與欄位名稱都和簡報相同；推論它是同一工具較新的版本，細節可能和
KCT 實際使用的版本不同。

## KCT 小組做什麼

查核團隊在簡報中稱為「申請人」。申請人用申請單提出 JE 資料整理需求，附上受查者提供的 GL 與 TB，並在申請單勾選
檔案包含的欄位；需要時也提出要設置的高風險條件。KCT 小組接單後依序完成五個階段，最後在派工系統送請申請人驗收。

| 階段 | KCT 做的事 | 使用的工具 |
|:---|:---|:---|
| 1. 確認申請人檢附的檔案 | 核對公司名稱、期間與必要欄位 | 申請單、Excel |
| 2. 整理檔案 | 把 TB 與 GL 整理成 JE tool 要求的欄位與格式 | Excel |
| 3. 匯入 IDEA | 建立 IDEA 專案、匯入、定義欄位型態、合併多個檔案、補項次 | IDEA、「新增項次」程式 |
| 4.1 確認完整性 | 用 JE tool 步驟一配對欄位，產出 Validation Report，確認完整性 | 舊版 JE tool |
| 4.2 設置高風險條件 | 寄送完整性結果給申請人，做科目配對、設定條件、產出工作底稿 | 舊版 JE tool、Excel、電子郵件 |
| 5. 交還申請人 | 交還 IDEA 專案檔，在派工系統送請驗收 | IDEA、派工系統 |

流程圖把交還分成兩條：4.1 之後接「5.1 交還申請人」，4.2 之後接「5.2 交還申請人」。簡報沒有寫明哪一種申請走哪一條。
5.1 要把專案檔整理到只剩 GL 與 TB，並「將 JE 回歸成配對前」；推測這是讓查核團隊之後自己從頭執行 JE tool，這點待確認。

## 各階段的做法

### 1. 確認申請人檢附的檔案

KCT 在申請系統核對三件事：檔案的公司名稱與申請單相同；TB 與 GL 的期間符合申請的查核期間；檔案包含申請單勾選的
必要欄位。

- TB 的必要欄位：會計科目代號、會計科目名稱、傳票金額。
- GL 的必要欄位：會計科目代號、會計科目名稱、傳票金額、傳票編號、傳票摘要、總帳日期。
- 申請單另有兩個選填欄位。傳票文件項次：客戶會計系統無法提供時，由 KCT 小組手動調整。傳票建立人員：
  客戶會計系統無法提供時，之後執行 JE tool 將無法執行相關篩選。

### 2. 整理檔案

TB 的整理：

- 移除表頭等不必要資訊。檔案內有報表期間的，留意期間是否正確。
- 整理成會計科目代號、會計科目名稱、期初金額、期末金額與本期變動數。簡報的 TB 格式要求是：科目代號為文字或數值、
  科目名稱為文字、金額為數值；金額要有年度變動金額，或期初與期末金額。
- 來源把期初、期末分成借方與貸方兩欄時，各自算成一個餘額，貸方餘額為負數。
- 期初與期末分在兩份 TB 時，以期末 TB 為主檔，用 Excel 的 VLOOKUP 把期初金額帶進來，並用「重複的值」比對兩期的
  科目代碼，確認科目完整。簡報範例中兩份 TB 的科目代碼格式不同，要先整理成一致。

GL 的整理依申請單填寫的欄位進行：

- 移除表頭等不必要資訊。
- 建立並整理會計科目名稱。
- 確保每一列都有正確的入帳日期、文件號碼等必要資訊。簡報範例的傳票日期與號碼只寫在每張傳票的第一列。
- 從借方與貸方金額欄整理出單一的傳票金額，借方為正、貸方為負。
- 整理後的必要欄位是：會計科目名稱_JE、總帳日期_JE、傳票號碼_JE、傳票文件項次_JE_S、會計科目編號_JE、傳票摘要_JE、
  傳票金額_JE。
- 非必要欄位是傳票編製人員、傳票核准人員、人工/自動分錄與傳票核准日；申請單有填寫的，務必一併整理出來。

簡報的 GL 範例有三種來源：每張傳票分成表頭列與明細列的報表、ERP 匯出的原始資料表，以及會計傳票明細表。
原始資料表的欄名是系統代碼，日期也以數字代碼存放，KCT 要先整理成 JE tool 的欄位與日期。

### 3. 匯入 IDEA

1. 建立 IDEA 專案，專案名稱依「派工單號_公司完整名稱_開始年月~結束年月」命名。
2. 用匯入助手選 Excel 檔，勾選第一列為欄名，預覽無誤後完成匯入，再核對 IDEA 的資料列數與 Excel 相同。
3. 逐欄定義資料型態，參照 TB 與 GL 必要欄位及格式要求的說明檔。
4. 需要合併多個 Excel 檔時，例如分季匯出的總帳，合併前先確認每個檔案都完整匯入，也就是核對筆數與金額加總；
   再確認每個欄位的格式定義無誤，以及有沒有項次欄。
5. 沒有項次欄時，全部合併後開啟「新增項次」程式，選傳票編號，產生項次欄。

### 4.1 用 JE tool 確認完整性

舊版 JE tool 的主畫面有五個步驟按鈕，另有「重新執行」與「離開」。KCT 在步驟一完成下列設定：

1. 輸入案件客戶名稱。
2. 財務報導期間的開始日與結束日，調整成申請單的日期；同一畫面另有「期末財務報表準備期間開始日」。
3. 產業別一律選 General Manufacturing。簡報後面幾頁的同一份清單已沒有這一項。
4. 選試算表的 IDEA 檔，配對會計科目編號、會計科目名稱與金額欄位。
5. 選傳票分錄檔的 IDEA 檔，配對必要欄位：傳票號碼、傳票文件項次、總帳日期、會計科目編號、會計科目名稱、傳票摘要
   與金額欄位。非必要欄位也要配對：傳票核准日，或勾選傳票核准日同總帳日；人工/自動分錄；分錄來源模組；傳票建立人員；
   傳票核准人員；另有四個自行定義欄位。
6. 開啟 Validation Report，確認 Validation Information 第五點為 0。第五點是完整性測試：確認試算表各科目期初與期末
   餘額的變動數，是否等於該科目在 JE 的借貸餘額；數字是兩者有差異的科目數，0 才能確認 JE 的完整性。
7. 不為 0 時，在 V_Report 5 工作表篩出 DIFF 不等於 0 的科目，分別回到整理好的試算表與傳票明細查看原因。

Validation Report 另有基本資訊與其他驗證項目。基本資訊是分錄檔名、借貸淨額（應為 0）、借方合計、貸方合計、分錄筆數、
TB 檔名與 TB 科目數。驗證項目共六項：無會計科目編號、無傳票號碼、無傳票摘要、傳票核准日不在會計期間、完整性測試、
個別傳票借貸不平。除了第五項一定產生明細表，其他項目只有發生筆數時才產生；明細超過 1 萬筆時不產生明細表。
步驟一完成後，IDEA 專案資料夾會自動產生 AccountMapping 檔。

### 4.2 完整性通過後設置高風險條件

1. 確認 4.1 的完整性結果，以電子郵件通知申請人，再確認申請人要設置的條件。
2. 科目配對：開啟自動產生的 AccountMapping 檔。在 List 工作表新增需要的分類，在 AccountMapping 工作表替 TB 科目選擇
   Standardized Account Name。List 預設 Cash、Revenue、Receipt in advance、Receivable 四類；範本說明因系統內建的邏輯，
   這四類不可更動，其他分類可自行新增，中英文不限；沒有配對的科目，系統自動設為 Others。
3. KCT 依財務報表的資產負債表與綜合損益表金額，在 TB 找出組成各報表科目的明細科目來配對。依條件可能要配對的分類有
   Revenue、Receivable（應收帳款與票據）、預收貨款與合約負債、固定資產、營業費用。
4. 步驟二上傳科目配對檔。舊工具的步驟二同時處理國定假日、週末與補班日，供非工作日切立傳票的條件使用。
5. 步驟三是標準化的預先篩選程序，內容見下方「舊版 JE tool 的五個步驟」。簡報沒有說明這一步的操作。
6. 步驟四依各條件設定進階篩選並執行，按「查看篩選結果」重新檢視申請條件與設定是否有誤，再按「匯出彙總報告」。
7. 步驟五按「產生工作底稿」，勾選要匯出的篩選條件，按各條件左方的按鈕逐一輸入評估說明，再按「匯出到工作底稿」。

### 5. 交還申請人

- 5.1：專案檔內只保留 GL 及 TB 檔，其餘檔案刪除；將 JE 回歸成配對前；將專案檔交還給申請人。
- 5.2：直接將專案檔交還給申請人。
- 送請驗收：在派工系統核對單號，點選作業已完成，附上最終的壓縮檔，填入固定的說明文字後送出；申請人未退回就自動結案。

## 舊版 JE tool 的五個步驟

| 步驟 | 畫面按鈕 | 簡報說明與畫面內容 |
|:---|:---|:---|
| 一 | 進行資料欄位的配對 | 定義試算表與傳票分錄檔的欄位，產出 Validation Report，確認完整性與可靠性。 |
| 二 | 上傳特定科目配對的檔案 | 科目配對供特定借貸組合使用；國定假日、週末與補班日供非工作日切立傳票使用。 |
| 三 | 預先篩選程序 | 執行六項標準化預先篩選：#1 於期末財務報表準備期間核准之分錄、#2 分錄摘要出現特定描述、#3 未預期出現之特定借貸組合、#4 分錄金額中有連續 0 的尾數、#5 依分錄編製者彙總分錄、#6 較少使用之科目。查核團隊可自訂摘要特定描述、借貸組合與特定尾數。產生 Pre-screening Report，並放入 Validation Report 已產生的空白摘要結果。 |
| 四 | 設定進階篩選條件 | 針對步驟三的結果設定條件，最多保存十組。可選預先篩選的結果；預設參數有總帳日期或核准日期在週末、在國定假日、排除補班日，僅考量借方或貸方傳票，以及篩選人工編制傳票；另有兩組文字欄位篩選、兩組日期區間、一組數字區間與一組科目類別配對。科目類別配對有 Dr A, Cr B、Dr A, Cr not B、Dr not A, Cr B 三種。 |
| 五 | 產生工作底稿 | 勾選要匯出的篩選條件，並為每個條件輸入考量說明；符合條件的完整分錄彙總到工作底稿。 |

簡報第 41 頁指出，舊工具每執行完一個步驟，都會因為產生新的 Excel 檔而開啟新的檔案總管視窗。

## KCT 的高風險條件 A 到 E

下表依簡報第 22 頁「確認申請人需設置之條件」整理。條件名稱與評估說明逐字照抄，連原文的錯字也保留；
其他欄把原文的箭號改寫成文字。

| 項次 | 高風險分錄篩選條件 | 評估說明 | GL 需額外整理 | 需配對科目 | 進階篩選 |
|:---|:---|:---|:---|:---|:---|
| A | 在該季度前X天借記收入的會計分錄 | 期末前 X天內收入科目有迴轉分錄，表示收入認列過程中可能存在不適當的調整或更正(案件團隊須提供天數) | 無 | Revenue | 設定日期；特定文字，輸入所有收入的科目代碼；僅考量借方傳票 |
| B | 借記固定資產(PPE，不含在建資產)且貸記費用之分錄 | 借記固定資產科目(如不動產、廠房和設備(PPE))但貸記營業費用或維修費用等費用科目之分錄組合不符合公司營業流程的瞭解，因此屬於為非預期的過帳，可能為舞弊類型分錄及其他調整的特質。 | 無 | 固定資產；營業費用 | 借方：PPE；貸方：營業費用；Dr A, Cr B |
| C | 特定科目組合(貸方為收入，但借方科目非為應收票據/帳款、預收貨款/合約負債) | 查核團隊已發現與收入科目相關的未預期或不尋常過帳(貸方為收入，但借方科目非為應收票據/帳款、預收貨款/合約負債) | 無 | Revenue；Receivables(含應收票據&應收帳款)；Receipt in advance(預收貨款&合約負債) | 直接匯出 |
| D | 收入的人工分錄 | 根據查核核團隊的瞭解，收入科目的過帳一般是自動產生，如為人工分錄非屬正常營業流程的會計分錄 | 做出欄位：人工/自動；人工：1，自動：0 | 收入 | 文字篩選 1：會計科目編號，輸入所有收入科目代碼；「勾選:」後面原文空白 |
| E | 傳票編製人員為會計經理 | 執行長、財務長及高階主管通常不預期會經手會計分錄編製或過帳。且因高階主管所處的位置常有能力能直接或間接操縱會計記錄來進行財務報表舞弊。誘因或壓力愈大，則愈有可能合理化其舞弊行為。 | 做出欄位：高階主管；高階主管：Y，非高階主管：N | 不需進行配對 | 文字篩選：傳票編制人員，輸入高階主管們 |

D 的「進階篩選」在第 22 頁只寫到「勾選:」，依第 28 頁的操作，勾選的是「篩選人工編制傳票」。各條件的操作頁補充如下：

- A：在步驟四勾選「僅考量借方傳票」，在「會計科目編號_JE」的特定文字篩選輸入所有收入科目代碼，以逗號分隔，再設定
  日期區間，區間內的日期都包含在內。簡報的例子是找期末前 5 天，日期區間就填期末前第 4 天到期末當天，只示範期末這一段。
- B：在 AccountMapping 新增固定資產與營業費用兩類，步驟四的科目類別配對選借方 PPE、貸方營業費用與 Dr A, Cr B。
- C：科目配對 Revenue、Receivables 與預收貨款及合約負債，步驟四勾選預先篩選結果「#3 未預期出現之特定借貸組合」。
  第 27 頁的條件表把評估說明寫成「例如，借記存貨，貸記收入」。科目配對沒有列 Cash，但 List 預設的四類包含 Cash。
- D：整理 GL 時建立「人工/自動」欄，格式為數值；匯入 IDEA 時也要設置這一欄。步驟四勾選「篩選人工編制傳票」，並在
  「會計科目編號_JE」輸入所有收入科目代碼。
- E：匯入 IDEA 時要有傳票建立人員欄位。步驟四在「傳票建立人員_JE」輸入要篩選的人名，以逗號分隔，名稱之間不能有空格。
  注意事項：要留意重複名稱，以及同一個人有兩個編號；例如 A001 與 A00 兩個編號，篩選 A00 時 A001 也會被篩到；
  不同編號在人員名單上是同一個名字時也要留意。

簡報在第 30 頁寫「以下依序是項次一到項次五的篩選範例供參考」，所以 A 到 E 是範例，不一定是 KCT 的完整條件清單。
條件本身也有幾處需要確認的地方：A 的條件名稱寫「該季度前」，評估說明與操作只寫期末；C 的科目配對沒有列 Cash；
E 的條件名稱寫「會計經理」，評估說明與操作寫的是執行長、財務長及高階主管，表格寫另建 Y/N 欄，操作頁則直接以人名篩選。
這些落差、新版 JET 的對應與後續裁定，記在上述 KCT 計畫；現行操作見 `jet-guide.md` 第 6 節。
